POST /api/v1/chat/messages → { reply }；GET /api/v1/chat/replies/:id。
此前后端零实现，AI 页只能走 mock（台账 §7.1）。

本批实现（新增 3 端点 + 1 表 + 2 模块）：
  · app/api/chat.py：POST /messages · GET /replies/{id} · GET /conversations/{id}/messages
  · app/services/external/agent.py：调 Agent 服务的**唯一出口**
  · app/db/models/chat.py + 迁移 b5c6d7e8f9a0：chat_messages 表
    （契约要求 GET /replies/:id ⇒ 回复必须可持久化，否则该端点只能 404 或伪造）
  · app/core/errors.py：CHAT_001/002/003 先入登记表再引用（本仓铁律）
  · app/core/config.py：agent_service_base_url / token / timeout_s

三条不可退让的断言（均有专门用例）：
  1. user_id 必须来自 JWT —— agent 服务自身不鉴权用户身份（agent/UPSTREAM.md 五-1），
     故它不得暴露公网，本后端是唯一可信注入点；
  2. **失败不伪造回复** —— agent 不可用 → 502/504，只留用户消息（"问了但没答上"可复盘），
     绝不本地生成"看似 AI 的回答"；
  3. **会话隔离** —— 他人/不存在的 conversation_id → 404，且**不得触发 agent 调用**。

刻意不套 with_retry（写进 agent.py 文件头，改动前先读）：该装饰器对 5xx/超时重试，
而对话调用**非幂等**——agent 经 save_memory 等工具写库，超时重试会**重复落库**。
故单次尝试 + 明确失败，宁可报错让人重问，也不产生脏数据。
