# G 批护栏评测

从仓库根目录运行。输入为步骤 4 导出的 G13 JSON。项目原文和逐条报告保存在 Git 忽略的真值目录或 `.cowork-temp`。

```powershell
python -m research.guard_benchmark.run_eval `
  --input research/truth-data/g/g13_project_80_20261125.json `
  --limit 20 --output .cowork-temp/g13-pilot.json
```

默认 `--mode mock` 运行后端实际规则与 mock 兜底。去掉 `--limit` 即遍历整个输入。限量试跑按场景轮流挑选已有评测入口或观测的案例，再选择其余案例。同一输入、选项和后端配置复用同一批案例。

| 场景 | 使用的证据 |
|---|---|
| 私人保存 | `moderate` 和 `verdict_action` 的放行、打码或拒绝，映射到保存入口的处置 |
| 对话回复候选 | `screen_generated(deep=True)` 是否拦住原文。后端在拦截时返回错误，因此这一链路只对比原文是否被拦截 |
| 对话请求、主动回响、对外发送 | 通过 `--observations` 导入对应入口的实测处置。缺观测时，报告该场景为未覆盖 |

观测文件是 JSON 数组。每项使用同一份 G13 输入中的案例编号和该场景的实际处置。错误或超时可用 `status` 记录。例如，下面的编号需要换成对应场景的实际案例：

```json
[
  {"guardrail_id": "g-0001", "action": "先澄清"},
  {"guardrail_id": "g-0002", "status": "timeout"}
]
```

报告包含数据和代码文件指纹、运行模式、各场景样本量、成功／未覆盖／失败／超时、实际动作、动作混淆矩阵，以及可对齐原文拦截语义的二分类指标。回复筛查只验证拦截时，完整处置记为未计分。分母为零时输出 JSON `null`。源表的标注状态按原值记录。输出只含案例编号、行号和评测字段。

`--mode live` 使用当前配置的百炼托管护栏和现有兜底，向现有检测服务提交被评文本。测试使用有权外发的素材和项目既有的 Infisical 配置。被后端兜底合并为「服务不可用」的异常统一报告为失败，可识别的超时独立统计。正式质量结论需要审定标签和对应业务入口的实测结果。
