## 边界

- `git push` 按决策台账 2.22「push 归用户」纪律不执行，最后提示用户自行推送。
- 全量门禁的 pytest 超时与 api_smoke（需 Docker）为已基线对照证明的环境性阻断，不算回归。

## 技术方案

### 既有栈（不引入新技术）

- 仓库：Python 3.12 agent（uv）+ Python 3.11 backend（FastAPI + SQLAlchemy + Alembic）+ uni-app x 客户端；git 单仓多目录。
- W6 迁移：backend/migrations/versions/ 新增 revision（先查 head 接对 down_revision），`DROP TABLE IF EXISTS` 幂等写法；schema.sql 与迁移链保持一致（它是 weekly 漂移巡检的比对源）。
- W3 契约扩展：`backend/app/schemas/content.py` 的 ContentCreate 加 `tags: Optional[list[str]]`（≤10 条、单条 ≤32 字符），`backend/app/api/contents/agent.py` 创建时写入 tags_json；`backend/app/services/pipeline/pipeline_tagging.py:45` 的覆写改为**合并语义**（保留已有标签、LLM 新标签去重并入），防止镜像行被 worker 处理时冲掉预置 topics。
- agent 侧：`agent/src/tools/memory_tools.py` 镜像调用时把 L3 topics 传为 tags（mood/category/people 仍留 extra）。
- 依赖删除用 `uv lock` 同步 uv.lock。

### 执行顺序与提交切分

每步独立 commit（中文消息）：A 出包批 → B merge → C W5 删链 → D W6 迁移 → E W3 映射 → F 台账/progress 收尾。每个代码 commit 前跑对应测试；最后跑快速+全量门禁。

### 验证口径（交接文档既定）

- `agent`: `python -m pytest tests -q`（基线 140 passed）；`backend`: test_schema_drift_guard + wechat 4 个测试文件。
- 门禁：`python scripts/review_agent.py` / `--full`；失败用例读 `.cowork-temp/test-report.json` 的 `failed_tests` 机读键。
- 安全阀：W6 任何一张 legacy 表有数据 ⇒ 暂停整个 DROP 步骤并报告，不擅自清理数据。

### 风险控制

- merge 冲突可能性低（远程零触碰 agent/）；合并后核对 deploy/Dockerfile.agent 假设（本地已删 18 个依赖反而使其可构建）。
- W5 删除前确认 `WECHAT_CORP_SECRET` 仅从 agent 侧引用移除，deploy/.env.production.template 不动（backend 在用）。
- 多行 python -c 一律落临时文件执行、用后即删（PowerShell 引号坑）。
