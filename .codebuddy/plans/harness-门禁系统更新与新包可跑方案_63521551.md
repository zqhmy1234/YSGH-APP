## 产品概述

两件合一的长周期工程，目标是让"重构后的新包"真正可跑，并把长期失修的 harness 与门禁系统性补齐：

1. 用**固定公网地址（ngrok 免费静态域名）**把本机当后端载体，手机无需数据线即可装 APK 测试；把目前 11 步全手工的出包链脚本化。
2. **系统性更新 harness 文档与工程（state 全面改造）与门禁**（这是最久未维护、也最重要的部分）。

## 核心功能

- 固定地址层：ngrok 静态域名 + 一键回写客户端环境三件套；隧道方案可切换（ngrok/cloudflared）
- 解阻塞：撤销上一轮引入的「隧道地址禁止出包」误判，让既定出包方案能过前置门
- 服务栈一键化：Docker 依赖 + backend(8010) + RQ worker + agent(8300) 一条命令起；端口口径统一
- 客户端编译门自动化：纳入全量门禁与出包前置门（不进每次提交）
- 门禁缺口修补：client 参与密钥扫描、端口一致性校验、孤儿脚本接入、harness 治理自检
- state 全面改造：唯一"当前状态"文件 + 唯一数字口径 + 漂移软告警，新会话不再被 43 天前的旧口径误导
- 出包链一键化：前置门 → 云打包 → 四项尸检 → 投放下载页
- 文档与 skill 体系更新：过时口径批量修正、新增门禁维护与流式对接 skill

## 视觉/交互效果

无 UI 变更；交付物为脚本、门禁、文档与 state 文件，用户侧效果是"装 APK 直连即可用"与"新会话不再读错状态"。

## 技术栈

- 脚本层：PowerShell 5.1+（Windows 主开发机）、Python 3（门禁与静态检查，复用既有 `scripts/gate_*` 基础设施）
- 客户端：uni-app x（UTS/uvue），HBuilderX CLI（编译门与云打包）
- 隧道：ngrok CLI（免费静态域名，地址永久固定）；保留 cloudflared 作为可切换提供方
- 底座服务：Docker（yishu-redis/yishu-qdrant）+ 本机原生 PostgreSQL 17.10 + FastAPI backend(8010) + RQ worker + agent(8300)

## 实现方案

### 总策略

三根支柱解耦推进，用一个"隧道提供方可切换"的抽象避免将来换方案时改动扩散：

1. **地址固定**：`ngrok http 8010 --url=<静态域名>` 得到永久固定地址；`write_base_url.ps1` 一键把 `ENV`/`REAL_DEVICE_HOST`/`PROD_BASE_URL` 回写进 `client/utils/config.uts`（**无 BOM**，因该文件被 PowerShell 读取判定），并打印"本包依赖外部隧道 + 必须常驻的服务清单"。
2. **解阻塞（本方案最关键的一点）**：上一轮由本 Agent 引入的两处判定把既定出包方案卡死，必须同时修正——

- `deploy/scripts/preflight_pack.ps1:97-107` 的隧道域名循环由 `Fail` 降为 `Warn`，并加 `-AllowTunnel` 显式开关（默认仍拦防误用；显式传入即放行并打印交付提醒）。
- `client/utils/config.uts:53-57` 的 `PLACEHOLDER_MARKERS`：**移除 `ngrok-free.app`/`ngrok.io`**（它们是既定方案，必须视为合法），保留 `trycloudflare.com`/`loca.lt`/`localtunnel.me`/`serveo.net`（不在方案内，仍提示）。
- 保留上一轮的 `isDevCarrier()`：它让"打包产物强制走 `PROD_BASE_URL`"，与"打包产物走隧道地址"方向一致，是防 `ENV` 漂移的安全网，**不动**。

3. **门禁自动化分层**：客户端编译门只在 `review_agent.py --full` 与出包前置门跑（每次提交多 45s+ 不可接受，且依赖 HBuilderX 常开）。

### 关键技术决策与权衡

- **隧道判定由"硬拦"改"显式开关 + 提醒"**：硬拦已被证明会误杀既定方案；纯放行又丢失"临时地址会失效"的警示价值。开关法兼顾两者，且把决定权交给出包人。
- **`<image :src>` 无法加自定义头**：ngrok 免费版的浏览器拦截页（interstitial）可能让媒体图全裂，且图片请求不能带 `ngrok-skip-browser-warning` 头。故方案要求：API 请求统一加该头作为防御，同时把"真机图片可达性"列为出包验收硬项。
- **编译门不进 pre-commit**：依赖 HBuilderX 单实例（`cli pack` 与其它窗口并发会互杀），且耗时 20~45s；放进 `--full` 与出包门即可覆盖高风险节点。
- **state 收敛为单点**：现规则"五处数字同步"已被证明不可执行（两处根本没有该数字位）。改为"全局数字只写 `STATE.md` 一处，其余只引用"，并加日期漂移软告警（不阻断）。
- **`feature_list.json` 重构而非删除**：它承载 MVP 用户故事能力清单，仍有价值；问题在于 11 条并行 `in-progress` 使"一次只做一个特性"无法验证，故收敛为只允许 1 条 `in-progress` 并新增 `blocked`/`deprecated`。
- **端口口径统一**：backend `8010`、agent `8300`（规范值，`agent/.env.example:100`/`agent/src/main.py:616`/`backend/app/core/config.py:64`）；旧的 `8000`（`scripts/e2e_agent_chat.ps1:58`、`scripts/realdevice/r2_4b_verify.ps1:58`）与一次性覆盖值 `8399`（`docs/交接_流式输出与对话UI_20261009.md:53-54`）修正/标注为历史。

### 性能与可靠性

- 门禁新增项全部为"读文本 + 子进程调用"，`client_compile_gate.py` 需设超时（建议 180s）与"缺 HBuilderX 则降级 WARN"，避免在无环境机器上把门禁变成死锁。
- `start_all.ps1` 需幂等：进程已在跑则跳过，附带健康探针（backend `/healthz`、agent `/health`、redis ping），失败即明确报错而非静默。
- 隧道重启不再导致旧包失效（地址固定后），但"本机栈必须常开"这一点必须写进交付说明，否则仍表现为"全空不报错"。

### 安全与纪律

- 密钥纪律不变：`agent/.env` 与 `ngrok authtoken` 均**不入库**（`.env` 从 `.env.example` 复制后手工填；authtoken 存 ngrok 自身配置目录）；签名口令仍走仓库外 `~/.yishu-signing/`，用完即删。
- `write_base_url.ps1` 写入 `config.uts` 时必须保持无 BOM 与原有编码，避免 preflight 的文本判定失配。

## 关键接口定义

隧道提供方抽象（供 `start_tunnel.ps1` / `write_base_url.ps1` / `pack.ps1` 三处复用，避免换方案时改动扩散）：

```
# scripts/dev/tunnel.ps1 —— 隧道抽象层（点源复用）
# 参数：-Provider <ngrok|cloudflared>  -UpstreamPort <int>  -StaticDomain <string>
# 返回：[pscustomobject]@{ PublicUrl; Provider; StartedAt; Pid }
# 约定：PublicUrl 必须为 https 且可被外部访问；失败时抛出可读错误（不静默）
function Start-YishuTunnel { param([string]$Provider='ngrok',[int]$UpstreamPort=8010,[string]$StaticDomain) }
```

`write_base_url.ps1` 的写入契约（三个常量行唯一定位，且必须无 BOM）：

```
# 匹配：export const ENV: string = '<dev|prod>'
#       export const REAL_DEVICE_HOST: string = '<...>'
#       const PROD_BASE_URL: string = '<https url>'
# -Prod : ENV='prod'、REAL_DEVICE_HOST=''、PROD_BASE_URL=<隧道 https 地址>
# -Restore : ENV='dev'、REAL_DEVICE_HOST='localhost'、PROD_BASE_URL 保持原值
```
