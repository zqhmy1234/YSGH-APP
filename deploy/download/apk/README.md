# APK 投放目录（卡 E1 → 卡 C3 交接点）

把云打包产出的 APK 放进本目录，**文件名固定为**：

```
deploy/download/apk/yishu-beta-latest.apk
```

`index.html` 的主按钮指向的就是这个相对路径 —— 只要文件名一致，**页面无需任何改动**。
（若出包文件名带版本号，请复制/重命名一份为该固定名；保留带版本号的原件便于追溯。）

## 为什么固定文件名而不是写死版本路径

内测期会多次出包。固定名 + 覆盖 = 页面的下载链接永久有效，避免"每出一版改一次 HTML、
改漏一处就 404"。版本信息由页面上的「内测版 vX.Y.Z / 更新于」文案承担。

## 放进来之后必须做两件事

1. **校验完整性**（不是"传上去就算"）：
   ```bash
   ls -l yishu-beta-latest.apk
   sha256sum yishu-beta-latest.apk   # 记录到内测群公告，便于用户核对
   ```
2. **回填页面上的 3 个占位**（见 `deploy/download/README.md` 的「[替换点]」清单）：
   文件大小、更新日期、以及两份二维码图片。

## 注意

- 本目录下的 `*.apk` **不入库**（根 `.gitignore` 已忽略 `*.apk`，见「Gradle / Android 构建」段）；
  页面文件本身照常入库。
- 内测期下载链接**不要公开传播**：本页已设 `<meta name="robots" content="noindex, nofollow">`，
  但真正可控的是"只把地址发在反馈群内"。
