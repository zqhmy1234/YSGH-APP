## 1. 目的

补齐"首批事件 30s 门禁"的**大批量真机计时**：**≥50 张**照片从「授权完成/导入开始」到「首批日卡片渲染出现」**≤30s**，并记录分段耗时定位瓶颈（上传 / 管线 / 渲染）。

## 2. 前置条件

- P1 本地后端在线（mock 档即可）；P3 nova 11 已装最新包 + USB 授权；P5 相册 ≥50 张（**建议 60 张留余量**）含 EXIF；P6 测试账号数据隔离；建议 **WiFi** 环境（蜂窝会暂缓原图，非本清单目的）。

### 2.1 前置就绪自查（不满足则本清单标"待补"，勿硬跑）

- □ 后端在线：`curl http://127.0.0.1:8000/healthz` → `{"status":"ok"}`
- □ 设备在线：`Get-Device`；`KeepAwake`
- □ 相册数据：≥50 张（60 更佳）含 EXIF（用 `scripts/generate_test_photos.py` 生成 + scan_file 注入新目录，见 skills/android-media-e2e）
- □ 测试账号隔离：清空该账号旧 contents/events 或新建测试账号（避免旧数据干扰计时与渲染判定）
- □ **设备系统时间已校准**（与真实时间一致——08-24 曾出现设备时钟错位，计时无效即重测）

## 3. 执行步骤

> 开始前 `Clear-Logcat`。计时以**系统时间**为准（截图含状态栏时间），logcat 时间戳辅助对齐。

**Step 1 · 数据隔离 + 基准**
- 记录测试账号标识；清空该账号后端旧数据（psql 删 contents/events，或换新测试账号）。
- 采证：记录清理前后 counts（可选）。

**Step 2 · 授权完成 = T0**
- 打开 App 首页 → 触发相册授权（首次授权 / 重新授权）。
- **授权完成时刻记为 T0**（截图含系统时间）。
- 采证：`Shot 03 1a`（T0 授权完成，含状态栏时间）。

**Step 3 · 批量导入 ≥50 张**
- 系统相册全选 ≥50 张，或 scan_file 注入到**全新目录**（`/sdcard/Pictures/yishu_test30`，逐文件注入）。
- 从 T0 开始观察，不要额外操作。
- 采证：`GrabLog 03 found`（`found` / `batch` 观察者触发日志）。

**Step 4 · 记录首批日卡片渲染时刻 = T1**
- 观察 logcat 时间线：`emitIncremental found N` → `batch received: N` → 上传 → 聚合 → 事件上云 `accepted=` → 时间轴刷新。
- **首批日卡片渲染出现时刻记为 T1**（截图含系统时间，确认卡片已渲染）。
- 采证：`Shot 03 2a`（T1 首批日卡片，含状态栏时间）；`GrabLog 03 timeline`（`upload`/`pipeline`/`timeline`/`accepted`）。

**Step 5 · 记录与计算**
- 记录：总张数 __；上传完成时刻 __；渲染完成时刻（T1）__；**耗时 = T1 − T0** = __s。
- 若耗时 >30s：按 upload→pipeline→渲染分段计时（logcat 各段时间戳），定位瓶颈环节。
- 采证：`Shot 03 3a`（完整时间轴，日卡片分组内容）。

## 4. 预期（可判定口径）

| 项 | 预期 | 判定口径 |
|---|---|---|
| 计时 | **T1 − T0 ≤ 30s**（≥50 张，授权完成 → 首批日卡片渲染） | 时间差 ≤30000ms |
| 渲染内容 | 首批日卡片分组正确（日期/张数与真值一致；L1 日卡片「YYYY-MM-DD · N条 / M张」） | 截图可见日卡片、张数对得上 |
| 分段 | 服务端基线参照：上传 4.2s + 管线 5.6s（单进程）；设备侧受 WiFi/扫描节奏影响，观察者 4s 静默窗口分批 | 分段计时用于瓶颈定位，非门禁项 |

## 6. 判定标准

- **✅ 通过**：T1 − T0 ≤ **30s**（门禁 🟡→✅ 转绿）+ 渲染内容正确（日卡片分组与张数对）。
- **❌ 失败**：>30s —— 记录瓶颈环节（上传/管线/渲染分段计时）与差多少，作为性能优化输入；门禁维持 🟡。
- **🟡 部分**：设备时间未校准 / 相册不足 50 张 / 蜂窝网络拖慢 —— 标"待补"，注明未达标原因，不虚构计时。
