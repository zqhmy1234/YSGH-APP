## 二、部署到服务器/新机器

1. 把模型目录复制到 `<服务器>/opt/yishu/backend/models/`：
   - `setfit-classifier/`（必须含 `labels.json`、`config.json`、权重文件）
   - `bge-m3/`（或确保 HF 缓存随镜像/挂载可用）
   - `SenseVoiceSmall-onnx/`
2. 设置 `EMBED_DEVICE=cpu`（生产容器默认无 GPU；本机评测可 `cuda`）。
3. 若启用 bge 粗排：把 `bge-reranker-v2-m3/` 放到同目录，`RERANKER_MODEL` 指向它。
4. 重启 `yishu-api` / `yishu-worker` / `yishu-agent`，跑：
   - `curl /healthz` 200；
   - `python -m pytest backend/tests/test_setfit.py -q`（需在镜像内/有依赖）；
   - 分类一条 `question`/`fact` 文本，确认输出 7 类而非 5 类。

## 三、bge-reranker 下载（缺口）

`deploy/scripts/pull_models.sh` 当前**刻意不下载** 3.2G 的 reranker（CPU 单对 ~850ms 超 P95）。
需要 R-6/E6 时，二选一：

```bash
# A. 从已有机器拷贝（推荐，避免网络）
scp -r <源机器>/backend/models/bge-reranker-v2-m3 <目标>/backend/models/

# B. 从 HuggingFace 镜像下载（网络可达时）
export HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download BAAI/bge-reranker-v2-m3 \
  --local-dir backend/models/bge-reranker-v2-m3
```

下载后校验 `config.json` 存在、目录约 3.2G；`RERANK_AUTO_ENABLE=true` 且 GPU 可用时才会自动启用。
**没有该模型时，R-6 的 `device=` 代码只能通过单测验证，不能做延迟/收益实测。**

## 四、SetFit 资产的关键口径

- `labels.json` 必须含 7 类：`emotion/fact/idea/mixed/question/quote/todo`；
- 模型是 BGE-M3 底座 + SetFit head，约 2.2G；只拷 head 不够；
- 训练脚本：`backend/scripts/train_setfit.py`；种子：`backend/data/setfit_seed.json`；
- 训练环境需 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`（否则会尝试访问 huggingface.co 的 adapter_config）。
