## 1. 网络类（6 项）

上轮教训：模拟器飞行模式**穿透 adb reverse 隧道**（虚拟网络直通），断了个寂寞。
组合三层手段：

```powershell
# 层1：App 可见网络状态翻转（触发 App 内「待WiFi/失败」分支）
adb shell svc wifi disable
adb shell svc data disable
# 层2：飞行模式（API 35 实测可用）
adb shell cmd connectivity airplane-mode enable
# 层3：真掐断 —— 停后端进程（上轮 4.2/5.3/5.4 已验证）
# 层4（恢复）：
adb shell svc wifi enable; adb shell svc data enable
adb shell cmd connectivity airplane-mode disable
```

**10.5 弱网限速**：`adb emu network speed gprs`、`adb emu network delay umts` 只对虚拟网卡生效，
对 adb reverse 隧道**不生效**。解法：测试期间把客户端后端地址从 `127.0.0.1:8010` 切到
`192.168.31.165:8010`（走虚拟网卡），限速即生效；**测完必须切回**（出包红线见 handoff §2.5）。
备选：宿主机 `clumsy` 对 8010 端口加延迟/丢包。

来源：[auto-mobile network-state 设计文档](https://github.com/kaeawc/auto-mobile/blob/main/docs/design-docs/plat/android/network-state.md)（API 35 实测记录）。

## 2. 中文输入（4 项）

ADBKeyBoard：https://github.com/senzhk/adbkeyboard/releases （v2.4-dev 稳定 / v2.5-dev 含 A16 修复）

```powershell
adb install keyboardservice-debug.apk
adb shell ime enable com.android.adbkeyboard/.AdbIME
adb shell ime set com.android.adbkeyboard/.AdbIME
# Windows 下必须走 base64 通道（adb text 不传 UTF-8）：
$b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("自定义分类名"))
adb shell am broadcast -a ADB_INPUT_B64 --es msg $b64
adb shell ime reset   # 测完恢复原输入法
```

注意：uni-app x 输入框需先 tap 获得焦点再广播；软键盘视图不弹出不影响注入（IME 广播直达焦点框）。

## 3. 麦克风（2 项）

`pcm_readi failed` 根因＝模拟器无音频输入源。三档：

- **Plan A**：AVD `hw.audioInput=yes` + 启动参数 `-allow-host-audio`（emulator 30+）→ 宿主机默认录音设备进模拟器麦克风。
- **Plan A+（推荐）**：装 VB-CABLE 虚拟声卡 → 设为宿主默认录音设备 → 播放器/ffplay 循环播放测试语音 WAV → App 录到真语音，FunASR 端到端可验（1.2 语音链、2.6 遮罩关录音、2.7 4 分 40 秒长录音全解锁）。
- **Plan B**：模拟器 gRPC `injectAudio`（emulator_controller.proto，31+）；[auto-mobile #13628](https://github.com/kaeawc/auto-mobile/issues/13628) 印证了 host-audio 与 gRPC 两条路，但其工具未发布，不必等。
