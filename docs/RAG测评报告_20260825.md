# RAG 检索测评报告（2026-08-25）

> 范围：文字 RAG 全链路检索层（BGE-M3 编码 → Qdrant RRF 混合检索 → 类目路由 → 命中提升 → 溯源）
> 依据：`research/rag_benchmark/run_eval.py --external` 多轮实测 + 逐查询探针 + `evaluation_report.json`
> 结论先行：**门禁全 PASS**；产品口径（显式相关）recall@3=0.92（合成集）/ 0.89（真实分布外部集）；LLM 改写经调研改为"有门控 + 双路加性"方案后与规则基线持平且保留纠错/扩写能力。

---

## 一、本次测评的 RAG 流程

```
用户查询 q
  │
  ▼
① Query 改写（_rewrite_query）
  ├─ 规则层：句首时间词 → 时间范围过滤（"去年去的地方"→ 去年 1.1-12.31）+ 删词
  ├─ NER：地点/人物 → place/tags 过滤（显式参数优先，可回退）
  └─ LLM 层（llm_rewrite_enabled=true 时）：有门控改写——短关键词原样返回，
     仅改错别字/口语/描述性查询（prompt v2，2026-08-25 调研后重写）
  │
  ▼
② 路由（规则词表，确定性）：图片意图关键词 → image（只搜 caption）；否则 text
  │
  ▼
③ 类目路由（P1-A，规则词表跑【原始查询】）：emotion/idea/quote/todo 主导类别
  → content_class 过滤（生产 payload 字段；空结果自动回退全量，防过过滤）
  │
  ▼
④ 编码 + 双路召回（BGE-M3：dense + sparse）
  ├─ 主路：改写后查询 → Qdrant dense(0.7)+sparse(0.3) RRF 融合（k=60, Top-50）
  ├─ 回退：NER/类目过滤致空 → 去掉对应过滤重试
  └─ 双路（LLM 开启且改写变化时）：原查询用【生效过滤器】再检索 → 按 content_id 取高分合并
      —— 改写路只增不减，原路永远兜底（2026-08-25 调研后修复 eff_filters 接线）
  │
  ▼
⑤ 精确命中提升（_boost_exact_matches）：词元全命中 ×1.8 / ≥50% 命中 ×1.3
  │
  ▼
⑥ 溯源组装（RET-016）：回填真实内容 + dense/sparse 命中解释；双层 rerank 默认关
（CPU 上 bge-reranker 单对 ~850ms 超 P95<3s 门禁；GPU 部署后开）
```

**查询集**（queries_text.json，15 条）：
- 检索聚合层 11 条：descriptive 4（"关于做产品的想法"类释义查询）/ keyword 3（买牛奶/马拉松/收房租）/ typo 2（买牛乃/松鼠桂鱼）/ length 2（购物/长句）
- 行为层 4 条：temporal 2 + route 2（行为判定，不进 recall 聚合）
- **显式相关标注**（P0-B 新增）：6 条具体查询补 expected id（如 买牛奶→b-todo-04），用于显式口径 recall 诊断

### 2.2 外部集（T2Ranking dev 抽取，70 条查询 / 88 段语料）
- 来源：THUIR/T2Ranking（中文段落排序基准）dev 集，经 C-MTEB/T2Retrieval 本地缓存语料对齐 qrels（118,932/118,933 段命中，免下载 3.66GB collection）
- 抽取口径（build_external_corpus.py，对齐本 APP"个人记忆碎片"输入分布）：
  - 查询 4~20 字符（短口语查询，如"蜂巢取快递验证码摁错怎么办"）
  - 相关段落去 HTML 标签后 8~120 字符（碎片级）
  - qrels rel≥2 优先；seed=42 确定性抽样；段落全局去重
- 产出：corpus_ext_t2r.json（88 段，id `ext-t2r-*`）+ queries_ext.json（70 查询，全显式相关）
- 定位：**补充基线 + 回归哨兵**，独立 collection `yishu_benchmark_ext`，不进 M1 门禁

## 三、指标定义与门禁

| 指标 | 定义 | 口径 |
|---|---|---|
| hit_rate@k | Top-k 是否至少命中 1 条相关（二元） | 门禁口径（label 级相关集） |
| mrr | 首个相关结果的倒数排名 | 门禁参考 |
| precision@k | Top-k 中相关占比 | 门禁参考 |
| recall@k | 相关∩Top-k / 相关总数 | **双口径**：label 全集（诊断，理论上限 3/15~3/20≈0.2）+ 显式 id（产品口径） |
| ndcg@k | DCG/IDCG | 排序质量 |

**M1 门禁**：hit_rate@3 ≥ 0.70 ｜ route_acc ≥ 0.90 ｜ temporal_acc ≥ 0.90 ｜ P95 < 3s（本轮未重测延迟，见局限）

## 五、关键发现（本轮测评挖出的坑）

1. **recall@3=0.0626 是口径失真**：label 全集分母使 Top-3 理论上限仅 ~0.2；显式口径（产品语义"找一条记录"）recall@3=0.9167/0.8857。
2. **LLM 改写"替换式"伤害（EXT recall 0.886→0.75）**：探针实锤 9/10 短关键词被无谓改写（"过年要给父母红包吗"→"过年是否要给父母红包"），embedding 偏移。**调研结论**：改写应是有门控 + 加性（原查询路兜底），不是替代。
3. **双路召回首个实现有接线 bug**：原查询路复用了回退前 filters（含改写文本派生的 content_class）→ 外部语料无该字段 → 原路恒空 → 双路名存实亡。修复：跟踪 eff_filters（最后一次成功搜索的过滤器）。
4. **LLM 路由误判**："货车保险杠前面加装的灯叫什么"被判 image → 过滤全部 text → 空结果。路由保持规则词表（route_acc=1.0）。
5. **dashscope 403 静默降级**：机器 User 环境变量残留旧 key（sk-4980）覆盖 .env 新 key，且 SDK 不读项目 settings——LLM 链路从未真正生效过（eval 成绩曾误归因）。修复：删残留变量 + `_ensure_api_key()`。

## 六、结论

1. **门禁达标**：hit_rate@3 0.7273→0.9091，route/temporal acc 1.0，P95 未重测（单查询探针 ~2s，含 LLM 改写 0.3~0.8s，预算内）。
2. **产品口径召回达标**：显式 recall@3 = 0.92（合成）/ 0.89（真实分布外部集），mrr ≥ 0.85。
3. **LLM 改写保留并修复**：门控 prompt + 双路加性 + 路由规则化后，探针验证与规则基线持平，同时具备错字纠正（买牛乃→买牛奶）与描述性扩写能力；真实数据（口语/长查询占比高）到位后预期正收益。
4. **遗留**：①temporal 层测试是"空结果即正确"占位（benchmark payload 无 taken_at）——真实数据必须带时间字段；②外部集段落偏长（≤120 字 vs 碎片 1~2 句），指标看相对增益；③rerank/更大候选集待 GPU；④C-MTEB 编码器基线待跑。
