> 配套设计：`docs/设计_B5记忆域_B7有人味域_深度设计_20261123.md`
> 配套总计划：`docs/架构重构总计划_v3_20261123.md`（若仓库内未同步，使用会话计划文件 §16）
> 规则：**任务卡没有 `background.docs` 或章节不存在 → 审判直接 `FAIL: missing_background`，不进入代码审查。**

---

## 0. 通用约定

### 0.1 角色

| 角色 | 职责 | 禁止 |
|---|---|---|
| `architect` | 写 ADR / 任务卡 / 契约；裁决接口 | 不写业务代码 |
| `implementer-B5` / `implementer-B7` | 按 `allowed_paths` 实现一个切片 | 不改契约、不改测试变绿 |
| `judge` | 独立读 diff；跑变异/负向/契约/端到端 | 不改生产代码 |
| `integrator` | 合并、全量回归、staging smoke | 不跳审判 |

### 0.2 每个任务的完成定义

- 代码实现目标行为；
- `pytest` 真实跑过（不是“应该能过”）；
- 至少 1 个负向探针 + 1 个变异体；
- `judge-report.json` 有 PASS/FAIL、覆盖矩阵、未覆盖风险；
- 任务卡背景章节存在且与 diff 对应；
- 不新增第二真源、不让 Agent 直连业务表。

### 0.3 审判输出格式

```json
{
  "task_id": "B5-01",
  "verdict": "PASS|FAIL",
  "issue_code": "missing_background|contract_mismatch|negative_probe_missing|mutation_survived|e2e_failed",
  "evidence": {"pytest": "...", "mutation": "...", "probes": ["..."]},
  "uncovered_risks": ["..."]
}
```
