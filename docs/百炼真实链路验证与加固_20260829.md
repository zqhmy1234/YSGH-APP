## 2. 两处后端加固（本次开发）

### 2.1 LLM 精排解析三级兜底（`backend/app/services/llm_ops/rerank.py`）

**动因**：`docs/搜索真实数据评测_20260828.md` §四 实测「llm_rerank 逐查询调用 dashscope 且输出
解析失败回退原序」——解析失败 = 第二层精排整体静默空转（多花一次 qwen-flash 往返，排序零收益）。

**加固**（降级契约不变：任何失败仍原序返回，但「形态失败」不再拖「内容成功」下水）：

1. **标准路径**：整数组解析（`parsing.extract_json_array` 围栏剥离/数组切片）；
2. **打捞路径**：整数组失败（max_tokens 截断 / 全角标点混入 / 散文包裹）→ 逐 `{...}` 块
   json 重试 + 正则打捞 `i/ans/reason`；截断尾块（无闭合 `}`）仅补收 i+可识别 ans，
   **未知前缀（如 `tru`）宁可不判**，绝不用 bool() 冒换序风险；
3. **字段归一**：`i` 接受字符串数字；`ans` 走 `_norm_ans` 中英文布尔同义集合
   （修复 `bool("false")==True` 恒真误判——原实现会把 LLM 判「不能回答」的候选顶到前排，
   属静默错误排序，比回退原序更糟）。

**回归用例**（`backend/tests/test_rag.py` 新增 4 项）：ans 字符串化 / 截断数组打捞 /
全角标点打捞 / 单对象输出+字符串 i。

### 2.2 以图搜图 VL 失败过期缓存兜底（`backend/app/services/rag/image.py`）

**动因**：`docs/搜索真实数据评测_20260828.md` §3.3——COCO 真实评测 2/10 miss 系
qwen3-vl-plus 连接重置（内部 3 次退避重试耗尽）→ 直接降级空结果；§六.3 登记「失败重试需加强」。

**加固**：重试耗尽后若存在**过期缓存（>24h TTL 旧记录）→ 降级返回旧 caption**（网络抖动期
检索可用性优先）；VL 成功但空描述同样落旧缓存；空 caption 不再覆写缓存位。
无任何缓存时维持原契约（上抛 → search degraded）。

**回归用例**（`backend/tests/test_image_search.py` 新增 3 项）：失败→过期兜底 /
空描述→过期兜底且不覆写 / 无缓存→仍上抛。
