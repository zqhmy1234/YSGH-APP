## 2. O-2：真机纠错——点任意分类标签后裁决恒输出「混合」

### 2.1 根因（分层：主因代码可证 + 首触发源二选一未定）

**RC1 主因（决定性，客户端流程缺陷）**：`client/pages/record/record.uvue:207-241` `onTagTap` 成功路径把**服务端裁决回声当成用户意图**——先 `submitArbitrate(text)`（请求里**根本没有用户刚点的标签**，契约见 `backend/app/schemas/correction.py:22-27` 仅 text/content_type），轮询得 `finalLabel` 后 ①用它**覆盖**用户乐观更新（:221-222）②`submitCorrection(..., finalLabel, ...)`（:223）把裁决结果本身写回纠错记录。于是：第 ① 层个人规则永远学不到用户的选择；而一旦层②对某文本首次输出 mixed，mixed 被写回 correction_log → **同文本再点任何标签，层①按相似度 1.0（文本相同）命中旧 mixed → 恒 mixed，且 Qdrant 同点覆盖"最后一次为准"使锁死自我强化**。这精确解释"不管点什么标签，纠错后一律变成混合"（lessons 08-28 23:19 现象），且与 D-16 同族——**把"没测到/测坏了"伪装成合法类目**。违反基线约束"用户操作优先，自动算法永不覆盖"（AGENTS 关键约束）与 B5-c 设计"主动纠错立即生效"（交付文档 05c §2/§3）。
- 置信度：**高（≈95%）**：代码路径 + 逻辑复现双证。

**RC2 首触发源（mixed 从哪来，两候选现场不可分）**：
- **(a) SetFit 静默降级**：`backend/app/services/classifier.py:44-51` 模型加载失败 → `_load` 返回 None → `:62-69 _fallback_result` **恒 label=mixed/conf=0.0**，仅一条 warning。该降级为 CI 引入（commit ee5e3ca "SetFit 模型缺失优雅降级"），生产语义下把"模型不可用"洗成"混合"分类。当晚 worker/uvicorn 与全局 3.13 同源，**setfit 1.1.3 import 链/签名兼容实测无恙**（`.cowork-temp/o2_setfit_probe.py`+out），但权重级加载（2.2GB fp16）因内存窗未测 → (a) 不可排除；且 15:40-16:05 刚发生过全局 python 依赖半残事故，重启后 worker 若在半残态拉起 SetFit，降级 mixed 完全成立。
- **(b) SetFit 真预测**：50 条种子样本的 5 类模型对真机短句泛化差，mixed 为 attractor（与 S2 校准同族）。
- 置信度：中（≈55% 倾向 (a)；定界方法见 §2.3-验证单，成本一次 curl）。

**RC3 配套一致性缺口（同链发现）**：`POST /corrections`（`backend/app/api/corrections.py:30-63`）只写 correction_log/Qdrant，**不回写 `contents.content_class`**（全库唯一写点 `backend/app/services/pipeline.py:100`）→ 即使端侧修好，时间轴展示/类目路由（config `class_routing_enabled`）/PG 兜底过滤仍用 SetFit 原始值，"纠错生效"在检索与画像侧不可见。
- 置信度：高（代码可证）。

**测试盲区（为何没被拦住）**：`backend/tests/test_correction.py:28` mock 向量恒 `[0.1]*1024`（任意文本余弦=1.0），层①命中语义在测试里退化——既测不出真实相似度分布下的"误命中"，也**没有一条覆盖"用户标签必须成为 new_label"的端侧链路契约**；另 0.8 阈值对 BGE-M3 短文本是否过松（跨内容污染风险）无标定。
- 置信度：高（读测试代码即证）。
