## 二、键名与路径基准的取证过程（为什么不是"照第一份文档抄"）

图标/启动图的 JSON 写法**两份官方文档都没给**（`manifest.html` 与 `manifest-android.html` 均明文写「建议在 HBuilderX 可视化界面操作，不推荐手动改源码视图」）。按项目铁律**不许猜**，故从两个内部权威源取证：

1. **HBuilderX 官方 manifest Schema**（决定性）：
   `D:\HBuilderX\plugins\hbuilderx-language-services\jsservice\src\schemas\manifestUniAppx.json`
   解析结果（`app-android.distribute`）：

   | 节点 | 直接子键 |
   |---|---|
   | `icons` | `hdpi` / `xhdpi` / `xxhdpi` / `xxxhdpi`（72/96/144/192）——**密度键是直接子键，没有 `android` 包装层** |
   | `splashScreens` | `default` / `background` / `icon` / `brand` |
   | `splashScreens.default` | `ldpi` / `mdpi` / `hdpi` / `xhdpi` / `xxhdpi` / `xxxhdpi` |
   | `splashScreens.icon` | `xhdpi` / `xxhdpi` / `xxxhdpi`（480/720/960） |
   | `splashScreens.background` | `string`（Android 12+ 生效，默认白） |

   **推翻了一处文档误读**：`manifest.html` 把层级写成 `splashScreens.android.default`，而 schema 与仓库现存 `splashScreens: {default: {}}` 都表明**没有 `android` 层**。（`hookManifestJson` 里的 `icons.android` 属于**旧 `app` 节点**的迁移源，与 `app-android` 节点无关——两者不矛盾。）

2. **HBuilderX 中文语言包**：`"tooltip.iconSavePath.desc": "图标保存路径：unpackage/res/icons"` —— 这是**「自动生成图标」功能**的落点提示，同时语言包里存在 `"不替换手动设置的图标"`，说明**手动指定项目内路径是被支持的正常用法**。

**路径基准的最终选择与残余风险**：官方未规定基准目录，故采用**项目根相对路径**（HBuilderX 工程根 = `client/`，由 `cli project open --path D:\GuangH-App\client` 确定）：

```
static/app-icon/icon-72.png
```

- **不用 `unpackage/res/icons/`** 的理由：`unpackage/` 是**构建产物目录**（本仓 `.gitignore` 已忽略），把资源真源放进去会重演本项目已栽三单的「文件写了、git 里却不存在」= diff 审查永久盲区。放进 `static/` 才能受版本控制。
- **残余风险（明确登记）**：若云打包实际按其它基准解析，现象是**图标仍为默认图标**（不会报错）。届时修法是 **4+6 行字符串改写 + 重新打包**，成本很低。**出包后必须用 aapt 核对**（见 §五），这是该风险唯一的验收手段。

### 9.5 风险：知情接受（更正此前一处错误表述）

**更正**：口头说过"泄露后别人能签新版本顶掉正规包"——**这是错的**。Android 强制同签名才能覆盖升级，别人的包**装不上**已装的 App（报"与已安装版本签名不一致"）。

真实风险只有四条：

| # | 风险 | 后果 |
|---|---|---|
| 1 | **不可逆** | 证书发出去收不回来。想收回只能改包名重签 → 所有测试机**卸载重装**，端侧 SQLite 数据全丢（本 App 数据在手机本地，**无云端兜底**） |
| 2 | **丢失即永久损失** | 对方丢失/被清 ⇒ 永远无法给已装用户发更新，同样只能卸载重装 |
| 3 | 误签包无法辨真伪 | 他签出的包与你签的无法区分 |
| 4 | **上架后锁死** | 一旦上应用商店，签名与 listing 绑定，**永久不能换** |

峰宝判断"后期换掉就行"**在当前阶段成立**：未上架、测试人数小群几个、换签名代价是卸载重装而非业务事故。

### 10.3 CLI `--config` 的正确格式（踩坑记录，官方文档站是 JS 渲染抓不到）

`cli pack --config <file>` 的 JSON **必须是「嵌套 + 原生类型」**。首次用**扁平键名 + 字符串值**（`"iscustom": "false"`）会在"正在提交到云端"后报 **`打包参数无法解析，请关闭电脑上安装的加密软件、杀毒软件等软件后`** —— 该文案是 DCloud 的通用误导文案，**与杀毒软件无关**，真实原因是参数结构错。

正确形态：

```json
{
  "project": "D:\\GuangH-App\\client",
  "platform": "android",
  "iscustom": false,
  "safemode": true,
  "android": {
    "packagename": "com.yishu.guanghua",
    "androidpacktype": 0,
    "certalias": "yishu",
    "certfile": "C:\\Users\\ghf\\.yishu-signing\\yishu-guanghua-beta.jks",
    "storepassword": "***",
    "certpassword": "***"
  },
  "ignoreWarnings": true,
  "async": true,
  "json": true
}
```

要点：
- `android.*` 是**真嵌套对象**，不是带点的扁平键；
- 布尔必须给**原生 `true`/`false`**，给字符串 `"true"` 会被拒（同一原因，`pack status --json` 也因此报 `参数 json 类型为boolean 值必须为true或false` —— 但**命令行直接传 `--json true` 字符串是好的**，只有配置文件里必须用原生类型）；
- `androidpacktype: 0` = 使用自有证书。

**为什么必须用 `--config` 而不是命令行参数**：口令出现在命令行会进进程列表（`tasklist`/`wmic` 可见）并落入 CI 日志。配置文件放**仓库外**（本次 `%USERPROFILE%\.yishu-signing\pack-config.json`），**用完即删**（已删）。仓库 `.gitignore` 覆盖不到该路径，靠"放仓库外"保证不误提交。

### 10.5 ⚠️ 本包用的是**临时公网地址**（重要，会失效）

`client/utils/config.uts` 的 `PROD_BASE_URL` = `https://metadata-bacon-most-represent.trycloudflare.com`（cloudflared quick tunnel）：

| 特性 | 后果 |
|---|---|
| 临时地址 | **cloudflared 一重启，地址就变** → 已分发的 APK **立刻连不上后端**（表现为"所有页面全空且不报错"，本项目最贵失败形态） |
| 依赖本机 | 开发机**关机 / 休眠 / 断网 / 重启**，隧道即失效 |
| 无 HTTPS 自有证书 | 用的是 trycloudflare 的临时证书（信任链由 Cloudflare 提供，客户端不校验） |
| 上游依赖 | 本机需常驻：Docker Desktop（native PG 已常驻）＋ `yishu-redis` 容器 ＋ uvicorn 8010 ＋ cloudflared |

**服务器到货后必须重出包**：按 `deploy/ONE_SWAP.md` 换 `PROD_BASE_URL` 为真实公网地址（或 HTTPS 域名）→ 重跑前置门 → 重新云打包。**旧包不会自动恢复**。
