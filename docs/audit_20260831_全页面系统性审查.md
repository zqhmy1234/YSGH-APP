## 〇、一页结论

1. **两极分化**：用 ardot 画布 JSON 直转的 7 个 n*_ 页（search/messages/profile/settings/detail/interview/ai）字号/字重/颜色/阴影/圆角命中率高（多数页 100%），唯二例外 index/record 是**未吃画布数据的旧手写页**，全维度偏差——这不是玄学，是数据链路问题。
2. **最重全局缺陷 = `gap`**：33 处 CSS `gap`（ai 8 / detail 9 / search 6 / messages 4 / settings 4 / interview 2），uvue App 端引擎**静默丢弃**（官方样式清单无此属性；r11 编译日志 34 条 WARNING 实锤），所有受累容器间距塌为 0。
3. **最重单页缺陷 = record 渐变**：`to right` + 百分比停靠双违规——方向比画布错 90°（画布真值 to bottom，纵向），% 停靠是 App 端非法语法（官方仅 3 参数格式），整条渐变在真机不可用。
4. 像素级还原做不到的**根本原因**分三层：① uvue ucss 平台硬限制（不可逾越，只能有据降级）；② 三代提取管线的演化遗留污染（v1 全崩→v2 渐变方向误判→v3 画布直转才精确）；③ 转换器丢语义 + 验证体系只验结构不验视觉。

## 一、根本原因分析（先读这个）

### 第 1 层：平台硬限制（uni-app x App 端 ucss 子集，官方文档实证）

| # | 硬限制 | 官方依据 | 对还原的影响 |
|---|---|---|---|
| R1 | **样式不继承** | 《uvue css使用》：「样式不继承，即父元素样式不影响子元素」；文本必须写 text 组件上 | 每个 text 类必须独立声明 font-family/size/weight，漏一处即回退系统默认黑体黑色 16px。当前仅 4 处缺口（§四），但这是历史上「文字全不对」的机制根源 |
| R2 | **background-image 仅支持 linear-gradient 且仅 3 参数** | 《background-image》App 平台节：「仅支持linear-gradient……仅支持三个参数，格式 linear-gradient(direction, color-start, color-stop)」 | 画布 3~4 停靠渐变（index hero 顶部暗化 0.5/0.28@50%/0、底部溶解 4 停靠）**物理上无法精确表达**，只能双停靠近似；**百分比停靠语法不被支持**→record 两条渐变整条不可用；radial-gradient 无此属性→径向光斑/同心光晕永远无法 CSS 直写 |
| R3 | **gap / row-gap / column-gap 不存在** | 官方样式清单 flex 属性族无 gap；编译器报 `gap is not a standard property name`（WARNING 非保守提示） | 引擎静默丢弃、不报错。33 处容器间距全部塌缩。**这是当前与设计稿偏差的最大单一来源** |
| R4 | box-sizing 默认 border-box；flex-direction 默认 column | 官方 css reset 清单 | border 内缩挤压内容（TabBar 已按「双轴居中才安全」判据规避）；横向布局漏写 row 即竖排 |
| R5 | backdrop-filter 在支持清单，但 App 平台「拍平（flatten）兼容性」表 Android(Vapor) 标 x | 样式清单含 backdrop-filter；background-image 页拍平表 | TabBar/搜索胶囊/问题卡/操作条/输入条 5 处玻璃的 blur 真机效果仍未实证（台账 T3 留观），fill α0.55/0.32 部分已正确落地 |
| R6 | class 选择器仅限 A-Za-z0-9_-，单 class 按 class 属性书写顺序定优先级（非定义顺序） | 《uvue css使用》 | 复合选择器（`.menu-icon.amber`）与多类叠加的行为与 web 有差异，易产生「写了不生效」 |

### 第 2 层：数据链路——三代管线，两代带毒

| 代 | 数据源 | 缺陷 | 遗留污染 |
|---|---|---|---|
| v1 | `design_data_for_agents/*/design_data.json`（svgelements 解析） | 8 份**全部解析崩溃**（`'Circle' object has no attribute 'r'`），几何/文字提取量=0 | 08-30 前的全部还原是**无数据截图目测**——index/record 两页旧样式体系（20/22/24/26/28 整数 rpx 字号、16rpx 阴影、手写 px 圆角）的直接来源 |
| v2 | `design_data_v4/*.json`（SVG 直解析） | ① 文字已转曲，字号=轮廓包围盒中位高，系统性偏差；② **渐变方向未求逆**（gradientTransform 是对象空间→渐变空间映射，直读 x1/x2 得到「横向」假象，官方语义与画布求逆均证伪） | 「设计稿是横向渐变」的错误结论 → record hero 遮罩被改成 `to right` + stops 值也按误判重写（0.38/0.12 vs 画布 0.5/0.28）——**方向错误 + 非法语法双重缺陷**；index 的 hero 注释写「垂直暗化」是对的，两页互相矛盾即是证据 |
| v3 | `uvue_gen/*_canvas.json`（ardot MCP 节点级导出） | 转换器把画布 gap 平译成 CSS gap（R3）；@tap/v-if/v-for 交互全丢（已手工接回，本轮对拍 6 文件交互数全部 ≥HEAD，无丢失） | 本轮对拍证明 v3 数据驱动的 7 个 n*_ 页文本/阴影/圆角几乎逐项命中——**数据源质量决定还原质量** |

### 第 3 层：转换器与流程

- **转换器丢语义**：画布节点级 `gap`/`itemSpacing` 没有被翻译成「非首子元素 margin」方案，而是直译成目标平台不支持的 CSS 属性（转换成功≠渲染生效）。
- **验证体系盲区**：grep 对拍（@tap/孤儿/CSS 合法性）只能证明结构没丢，证明不了视觉一致；阴影漏层、blur 减半、渐变方向这类损伤 grep 全盲。
- **日志漏读**：r11 部署日志 35 条 WARNING（gap 34 + backdrop-filter 1）未读 → 「部署成功」假象。
- **设备口径（G7 扩展）**：设备逻辑宽 361px ≠ 画布 390px。rpx 体系页面整体等比缩 7.4%（构图保持、绝对尺寸缩水）；TabBar 组件用 **px** 直写不缩 → 组件相对页面内容偏大 7.4%。rpx 与 px 双口径并存使「全页等比」假设被局部破坏，这是任何单页修值都治不好的系统性失配。
