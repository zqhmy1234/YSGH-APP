# 集成规则与冲突回退（docs/parallel-dev/13）

> 执行人：集成 Agent（主窗口）｜所有波次 Agent 必须遵守，否则按"静默完成"处理

## 1. 每波末集成流程（顺序执行）

1. **收齐**：等待本波次全部 Agent 的完成消息（含文件清单 + 测试结果 + 表需求 + 待 key 项）。
2. **逐个合并**（按"独立服务 → 钩子触点 → 共享 UI"顺序）：
   - `cd D:\GuangH-App && git checkout develop && git pull origin develop`
   - 对每个分支：`git merge --no-ff waveN-agentX -m "merge: waveN-agentX <域>（<日期>）"`
   - 冲突时按第 2 节回退规则处理。
3. **全量验证**：`cd backend && python -m pytest tests -q`（默认套件基线 ~247 + PR#1 新增；`-m rag` 14 项需 Qdrant，环境缺失标 CI 验证）。
4. **契约**：涉及 API 的波次重导出 OpenAPI（`docs/openapi.json` + `docs/OpenAPI契约.md`）。
5. **登记**：更新 `feature_list.json`（对应 feature 的 status/evidence）、`progress.md`、`session-handoff.md`。
6. **通知下一波**：把 merge 后 commit 号 + 环境变化写进完成消息，供下一波 Agent 拉取。

## 2. 冲突回退规则

1. **同波次文件域重叠**（Agent 违反 Scope）→ 后到者重做：保留先 merge 分支，后 merge 分支手动挑拣非重叠 commit（`git cherry-pick` 逐个），重叠部分由集成 Agent 合并两版逻辑。
2. **pipeline.py / dashscope.py / models.py / migrations 冲突** → 冻结文件以"集成 Agent 版本"为准：任何 Agent 的改动先回退，需求以任务卡备注形式由集成 Agent 在 merge 后统一实现（或转交对应钩子文件）。
3. **feature_list.json / progress.md 冲突** → 以集成 Agent 版本为准，Agent 侧改动丢弃（Agent 不写这些文件）。
4. **跨波次共享文件**（如 rag.py）→ 后波次 Agent 在 merge 后的 develop 上重做，不 cherry-pick 旧分支。

## 3. 集成 Agent 专属文件（Agent 一律只读）

- `AGENTS.md`、`feature_list.json`、`progress.md`、`session-handoff.md`
- `backend/app/db/models.py`、`backend/migrations/`
- `backend/app/services/pipeline.py`、`backend/app/services/external/dashscope.py`
- `docs/parallel-dev/`（Agent 只读；自己的完成记录写 .cowork-temp/audit_*.md）
- `docs/OpenAPI契约.md`、`docs/openapi.json`

## 4. 新表/新列需求通道

Agent 需要新表/新列 → 不许动 models/迁移；在完成消息"表需求"段写明：表名/列、用途、关联任务卡编号。集成 Agent 在下一波开始前统一评估（优先复用 Wave 0 已建表：profile_sensitive / sensitive_words / profile_annotation_pool / upload_tasks / upload_chunks）。

## 5. 高风险项清单（merge 时重点检查）

1. `pipeline.py` 钩子调用点（Wave 0 已埋 4 处，Agent 只实现 pipeline_ext 内函数，merge 后跑 test_pipeline 确认调用链）
2. `rag.py`（Wave 1 A 改 + Wave 2 F 可能加精排接线——跨波次，后到者基于最新 develop）
3. `client/pages/index/index.uvue`（Wave 2 E 独占；Wave 3 H 的同步状态 UI 通过新建组件 + 集成 Agent 接线一行，H 不得直接改 index.uvue）
4. `backend/app/api/events.py`（Wave 2 D 独占；E 的反向入口用新文件 `backend/app/api/event_items.py`）
5. `notify.py`（Wave 4 J 独占；此前零调用方，改动安全）
