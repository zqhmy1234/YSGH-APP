- 手动 merge/split/confirm UI → 后续波次

## 四、技术要点

### 后端新增（1 接口 + 1 存储接线，不改架构）
```
POST /api/v1/contents/upload
  multipart: file(照片) + meta(JSON: taken_at/gps/perceptual_hash/source/extra)
  → storage 后端存 COS（dev 走 minio/fake）→ contents 建记录(cos_key) → enqueue_high(process_content)
```
- 与现有 `POST /api/v1/contents`（JSON 元数据）共存；去重复用 perceptual_hash 409 逻辑；护栏复用 moderate。

### 客户端骨架（D:\GuangH-App\client\）
```
client/
├── manifest.json / pages.json          # HBuilderX uni-app x 工程
├── pages/index/index.uvue              # F8 时间轴（L1 卡片 + L2 分组）
├── uni_modules/yishu-photo-watch/      # UTS 插件（系统能力层）
│   └── utssdk/
│       ├── interface.uts               # 相册监听/读取接口
│       └── app-android/
│           ├── index.uts               # UTS→Kotlin 桥接导出
│           ├── PhotoObserver.kt        # 从 research/poc/android 平移（Hybrid Mode）
│           └── AndroidManifest.xml     # 权限（READ_MEDIA_IMAGES 等）
└── utils/api.ts                        # 中转上传 + timeline 拉取
```
- 游标去重：SharedPreferences 存 last_seen（照片 id/time），不引 SQLite。
- 攒批：ContentObserver 回调 → 3-5s 静默窗口 → 批量上传（并发 ≤3）→ 全部完成触发 timeline 刷新。

### harness 集成
- `review_agent.py` / `ruff.toml` 排除 `client/`（Python 工具链不扫 Kotlin/UTS）
- feature_list F1/F8 状态与 DoD 随波次更新
