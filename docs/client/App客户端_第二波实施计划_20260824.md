## 四、技术要点

### 端侧 ST-DBSCAN（UTS 算法层）
- 从 backend/app/services/event_aggregation/ 移植：pipeline（预处理）+ st_dbscan（L0）+ 日聚合（L1）
- 参数与后端一致：L0 级联 ST-DBSCAN（60min 默认/30min 保守开关、500m、min_pts 3）；L1 自然日（深夜归前一天）
- AGG-016：同一组用例 Python 与 UTS 输出对比（簇成员/日卡片一致）
- Kotlin 桥接：相册读取（复用第一波 PhotoObserver）+ EXIF/定位元数据

### 事件上传与云侧改造
- `POST /api/v1/events/sync`：批量提交端侧 L1 事件（client_event_id/成员照片引用/时间窗/模板标题），幂等
- `aggregate_user`：不再聚 L0/L1，改"收端侧事件 → 关联照片 → 跑 L2/L3 候选"；`_process_photo`（caption+CI 打标）保留
- 第一波数据迁移：端侧初始化拉云侧 events（含 level=1）为基线落本地，此后增量以端侧为准

### XView（SQLCipher）
- 5 表：events（client_event_id 唯一）/ photo_event / op_log（op_id 唯一，B4-3 规格）/ sync_cursor / photo_index
- schema_version 迁移 + 轻量自研 DAO；WorkManager 持久化经 UTS 插件 Kotlin 桥接

### 同步协议（按 B4 定稿）
- 冲突：字段级 LWW + 同时间云端胜 + 提示（不弹窗）
- 队列：op_id 幂等 + 指数退避（2s/4s/8s/上限 5 次）+ 4xx 停该条 + 批量 10+ 暂停 + 横幅"继续上传"
- 触发：前台/相册监听/2h 定时三路 + 游标去重
- 删除：软删除 30 天
