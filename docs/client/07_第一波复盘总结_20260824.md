### 2. UTS 语言 / 编译器（高频，务必先读 skill: hbuilderx-uniappx-runloop）

| # | 坑 | 根因/修复 |
|---|---|---|
| 6 | `display:block` 不支持 / `page` 选择器不支持 | uvue 仅支持 class 选择器 + display: flex/none；全局底色走 pages.json + 根 .page 类 |
| 7 | 对象字面量不能赋给 interface | UTS 字面量仅支持 class（构造类型）→ 所有 DTO 用 class + 构造函数 |
| 8 | UTSJSON / UTSAndroid import 失败 | 内置全局对象不可 import；全局类型名是 `UTSJSONObject`（不是 UTSJSON） |
| 9 | Promise.catch/onRejected 不接受带类型闭包 | 重载只认 `(Any?) -> R` → 全改 resolve-only（失败 resolve(null)+toast），onRejected 参数留空 |
| 10 | const 箭头函数不可自引用（找不到名称） | 先定义后使用 → 模块级 function 声明 / class 方法（UploadPool 模式） |
| 11 | interface.uts 多函数声明 + 平台实现 → 编译器 overload panic | 不用 `export * from interface.uts`；类型具名再导出（error3）；函数声明保持最少 |
| 12 | `getUniActivity()` 才是 Activity 获取 API（getCurrentActivity 不存在） | UTSAndroid 静态方法列表以文档为准 |
| 13 | 原生 interop 类型：Long vs Number / UTSArray vs Java Array | 显式 Long；MediaStore query 传 null projection/selectionArgs 绕开数组互转 |
| 14 | catch 参数类型是 UTSError | `catch (e: Error)` 可编译 |

## 二、经验与方法论（第一波沉淀）

1. **真机实测 >> 单测推演**：17 号并发竞态、15 号隐私事故、16 号 EXIF 污染——都是单测覆盖不到、真机一跑就现形的。客户端联调必须早接真机，别等代码"写完"。
2. **数据源可信度分级**：相机拍摄时间以服务端 EXIF 为准；客户端/系统提供的时间（DATE_TAKEN/DATE_ADDED）只做兜底。同类原则：任何"用户可控/系统可污染"的字段，服务端都要有权威源。
3. **游标/去重类逻辑的默认安全**：监听类功能默认"不导入存量、只收增量"；宁可漏收不可误全量（隐私红线）。上限防护（fake 512MB）证明有价值——防护不是为了测试，是为了兜底真实事故。
4. **编译循环是主战场**：uni-app x 客户端 90% 的"开发时间"在 编译→修错→再编译（每轮 ~30s）。把编译错误清单沉淀成 skill，第二次起每类错误 1 分钟内修复。
5. **门禁纪律价值**：review_agent 全绿才提交；lessons 强制登记让每次踩坑都变成资产。本波 7 条新教训全部来自真实失败。
6. **决策裁剪要留痕**：插件 Hybrid→纯 UTS（标准基座可跑）是本次最重要的架构调整，理由（自定义基座需云打包/三方依赖链路复杂）与代价（SecurePrefs 推迟）都记录在 progress.md，峰宝知悉。
