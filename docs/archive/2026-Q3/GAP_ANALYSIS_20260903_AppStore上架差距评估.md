# 忆述光华 · App Store 上架差距评估报告

> 生成：2026-09-03 ｜ 依据：三路代码/文档/跨端侦察（48 路由后端实测 + 12 页客户端接线核验 + 交付文档九份回源）
> 问题：当前开发情况离「能完整上架 Apple App Store 的 MVP」还有多大差距？

---

## 0. 总判断

| 维度 | 结论 |
|---|---|
| **Android 内测可达度** | 代码侧 ~90%，但**内测可达度仅 60–70%**（评估文档 08 自认口径）——缺口不在代码，在三座大山：外部凭证 / 七批真值数据 / 合规三申请 |
| **iOS App Store 就绪度** | **约 10%。manifest 的 app-ios 节点是空壳，4 个自研 UTS 插件 3 个 Android-only，全项目 0 处 iOS 条件编译，构建链路（证书/图标/权限文案）从零开始** |
| **一句话** | 当前 APP 是「Android 主端的开发中产品」：功能骨架 90% 已立，但要走完"Android 内测"还差合规三申请 + 真值验收 + 缺陷复验；要"iOS 上架"则是**一整条未开工的工程线 + 一整套未启动的合规流程** |

## 1. 已实现且接线的部分（不用再做的）

### 后端（48 路由，60 个测试文件）
- AI 全家桶真实接入：BGE-M3（dense+sparse，`services/embedding.py:27`）、SetFit 分类（降级规则兜底）、百炼 qwen-flash/qwen3-VL（改写/路由/护栏三用）、FunASR Flash + SenseVoice 双通道 ASR、Qdrant 向量库

### 客户端（12 页全部存在，10/12 接真后端）
- 时间轴 ✅（`USE_MOCK_TIMELINE=false`）、搜索 ✅（`USE_MOCK_DATA=false`）、详情/消息/访谈/安全页均真后端

- 离线队列 + 断网恢复补跑已实现

## 2. 差距全景：六个层面

### 层面一：功能未打通（客户端↔后端断点）

| 断点 | 现状 | 影响 |
|---|---|---|
| **AI 对话页整体 mock** | ai.uvue 零网络 import，本地语料轮换；B2 对话域后端不存在 | 核心卖点功能对用户不可用 |
| **微信登录是 mock** | auth.uts:75 硬编码 `code:'dev-client'`，未集成微信 SDK，两端都没接 | F6/US-31/32/33 三条用户故事卡企微凭证 |
| **短信登录 501** | providers.py:73 TODO T1 | 无微信时的兜底登录缺失 |
| **推送无真实通道** | notify.py mock 占位；厂商通道（小米/华为/OPPO）审核 3-7 天未申请 | 回响/关怀触达不可用 |
| **STS 直传凭证** | storage.py:76 NotImplementedError | COS 上传走的是哪条路需复核 |
| **后端契约缺口 11 项** | 收藏/删除/胶囊/导出/动态打标/评论/消息跳转等零端点（远期待办总账 A1-A11） | 收尾波次补的页面有按钮无后端 |
| **未接线函数** | markAllRead（无"全部已读"按钮）、reconcileNow 无触发点；6 处 mock 开关（B8 铁律要求提审前全部=false，当前 ai/trash 等仍在册） | 提审硬门槛 |

### 层面四：iOS 上架——工程侧（差距最大的一块）

**结论：iOS 适配工作量为 0，而非"已适配待验证"。**

| 项 | 状态 | 证据 |
|---|---|---|
| manifest app-ios 节点 | ❌ 空壳：无 bundleId、图标、启动图、权限文案 | manifest.json:53-59 |
| iOS 权限声明 | ❌ 零条——相机/相册/麦克风/定位全是核心功能依赖，缺即闪退+提审必拒 | 全文件搜不到 NS*UsageDescription |
| yishu-recorder（录音） | ❌ 仅 app-android | 需 AVAudioRecorder 对齐 wav 16kHz 契约 |
| yishu-photo-watch（相册监听） | ❌ 仅 app-android，且 **iOS 无 ContentObserver 等价物**——产品逻辑级缺口，最坏降级为前台手动扫描 | F1 核心链路重设计 |
| yishu-background-tasks | ❌ WorkManager 是 Android 专属，需 BGTaskScheduler 重写，iOS 后台预算严苛 | 后台同步/转写重排 |
| hens-svg | 🟡 有 app-ios 目录但 index.uts 是加密产物，需云打包实测 | 所有 SVG 图标依赖 |
| 条件编译 | ❌ 全项目 0 处 `#ifdef APP-IOS` | 平台分支为零 |

| 微信 iOS 接入 | ❌ 需 openSDK + Universal Links，与 Android wxapi 机制完全不同 | 两端都未开始 |
| 构建链路 | ❌ 无 Apple 开发者账号/证书/provisioning 记录；versionCode 100/0.1.0 | 从零走 HBuilderX iOS 云打包 |

## 3. 差距分层结论

```
能 Android 内测（20 人大致可跑）   ████████░░  80%  ← 差：凭证实网接入 + 11 单复验 + D-06
能 100 用户公网内测（原 MVP 目标） ██████░░░░  60%  ← 再差：合规三申请 + 公网 HTTPS + 真值 5 项验收
能 Android 商店上架                ███░░░░░░░  ~35%  ← 再差：内容安全 + mock 清零 + 商店资质软著
能 iOS App Store 上架             █░░░░░░░░░  ~10%  ← 再差：整条 iOS 工程线 + Apple 账号/隐私标签 + 相册监听机制级重设计
```

## 4. 建议的关键路径（按依赖顺序）

1. **立刻启动合规三申请**（ICP/软著/企微认证）——5-6 周串行是最长纯等待项，并行跑
2. **凭证实网接入**：企微三件套→微信收/找验收；阿里云短信；内容安全（US-44/C3）
3. **R2 复验波**：11 单已修缺陷关单 + D-06 机型适配方案
4. **真值验收**：向产品部催 A/C/D 批，把 6 项未达标门禁清掉
5. **iOS 技术验证先行**（最高不确定性）：先做 photo-watch 在 iOS 的替代机制验证（PHPhotoLibrary 限制下自动感知是否可行），再决定 F1 链路在 iOS 的产品形态；随后 recorder/background-tasks iOS 端、manifest 补全、云打包首跑
6. **提审检查清单**：B8 铁律（grep USE_MOCK 全 false）+ 账号注销端点 + Apple 隐私标签 + ATS 域名替换
