# 小鲸无忧 × 忆述光华 合作分析报告

> 日期：2026-09-12 ｜ 分析人：北嘎霖 ｜ 依据：小鲸无忧平台介绍V1.2.pptx（28 页全文提取）+ 忆述光华代码库盘点（2026-09-12）

---

## 0. 结论先行

**值得谈，但以「渠道合作」入场，不以「产品相似」为合作叙事。**
两家的相似是**表面相似**（同为银发/家庭场景的移动互联网平台），本质是**互补而非同类**：小鲸无忧是 O2O 服务调度 SaaS（人海服务），忆述光华是 AI 多模态记忆产品（内容技术）。真正的合作逻辑是——**他们有渠道和政企资源但没有 AI，我们有 AI 和产品力但没有渠道**。

⚠️ 两个前提性事实问题（签约前必须核清）：
1. **对方不是复星，是复医（复旦系）**——上海复医致享科技发展有限公司 = 复医天健全资子公司 = 上海复旦医疗产业创业投资有限公司成员企业。若对接方真说是"复星"，要么对接人自己搞错了，要么有包装成分，本身就是第一个尽调信号。
2. **"烂尾"需定性**：PPT V1.2 里业务案例是活的（静安区芷江西路街道阳光陪诊站落成、上海市残疾人福利基金会战略签约、聋人协会锦旗），母公司口径年服务 300 万住院病患。"烂尾"更可能是**平台技术团队收缩/自研系统停滞**，而不是业务死掉。烂在哪一层决定了合作的切入方式和谈判筹码。

## 1. 对方产品定性（小鲸无忧）

| 维度 | 内容 |
|---|---|
| 公司 | 上海复医致享（复医天健全资子公司，2003 年母公司成立，国企/复旦背景） |
| 产品 | 助医陪诊一站式服务平台：陪诊、代问诊、代配药、出入院协助、院内护理/点餐 |
| 架构 | SaaS；小程序 / APP / 预约一体机 / 电话 → 系统自动调度陪诊师 → 陪诊师手持 PDA 服务 → 全程可追溯、平台可监管 |
| 技术 | 移动互联网 + "人工智能、物联网"字眼（PPT 层面仅调度、双录签到、可视化轨迹，无内容 AI） |
| 资源 | 10 省市 300+ 公立医院（中山/华山/仁济/瑞金等）、社群健康助理员持证 335 人、上海市首批职业技能等级认定试点 |
| 客群 | 独自就医老人、异地就医患者、孕妈、行动不便者、上班族等 8 类 |
| 政策东风 | 2024-12 国务院养老服务改革意见 + 2025-01 上海助医陪诊试点方案（先发政策卡位） |
| 案例 | 助残陪诊签约、街道陪诊站、医院服务日——B2G/B2B2C 模式 |

**一句话定性：渠道型 + 政企关系型 + 人海服务型公司，技术是自研 CRUD 级监管平台，不是 AI 公司。**

## 2. 相似度判定：和忆述光华像在哪、不像在哪

| 维度 | 小鲸无忧 | 忆述光华 | 判定 |
|---|---|---|---|
| 目标人群 | 老人/患者/家属（服务场景） | 20-60 岁全龄（记忆场景，含长者签约院） | ✅ 相似（银发家庭流量） |
| 产品本质 | O2O 服务调度平台（撮合陪诊师） | AI 记忆收纳（多模态收录→聚合→检索→回响） | ❌ 不同物种 |
| 技术壁垒 | 调度系统、PDA、服务 SOP、持证人力 | ST-DBSCAN 四层事件聚合（端云双份）、BGE-M3+Qwen3-VL 双塔检索（hit@3=90.91%）、语音双通道、LWW 同步 | ❌ 几乎零重叠 |
| 收入模式 | 服务费（陪诊/护理/点餐订单） | 内测期，远期订阅/家庭共享/机构授权 | 部分互补 |
| 短板 | 无内容 AI、无 C 端留存产品力 | 无渠道、无政企资质、无线下、缺凭证通道 | ✅ 互补 |

**判定：低度重叠、中度互补。**"产品和对方相似"这个说法技术站不住——合作叙事如果建立在"我们像"上面，谈判时会被对方定位成同质竞争者，反而不利。正确叙事是**"我们把你的服务变成记忆，你把你的渠道变成我们的获客面"**。

## 3. 技术对拍：双方各自手里有什么牌

### 他们有的（我们缺的）
1. **线下渠道网络**：300+ 医院实时入口，陪诊师是与老人/家属面对面的信任触点。
2. **政企与合规资产**：残联/街道/协会合作记录、职业技能认定资质、国企信用背书。
3. **高频线下场景**：就医是长者最高频、情感浓度最高的时刻之一——天然的记忆采集场景。

### 我们有的（他们缺的）
1. **多模态记忆管线**（真实可用，832 项测试背书）：语音转写+情绪标注、图片理解、AI 分类/画像。
2. **四层事件聚合 + 描述性搜索溯源**：说一段模糊描述就能找到记忆，这是"记忆产品"区别于"相册"的核心体验。
3. **家庭共享空间方向**：子女异地查看父母记忆——正好接住"异地就医患者家属"的焦虑场景。
4. **我们的短板（对方视角）**：AI 对话域还是 mock、iOS 未开工、企微/短信/推送凭证未通——**谈判时如实披露，别许诺做不到的排期**。

## 4. 商业合作模式（按投入由轻到重分级）

### 方案 A：渠道互推（轻，0-3 个月，先做这个）
- 他们的陪诊服务结束后，向客户赠送/推荐"本次就医记忆档案"（我们产品的轻量入口）；我们的家庭共享页给陪诊服务一个自然推荐位。
- 成本最低，验证渠道转化率。试点选 1 家医院或 1 个街道陪诊站。

### 方案 B：场景产品共建——「陪诊记忆卡」（中，3-6 个月，主推方向）
每次陪诊结束，陪诊师端一键生成结构化「就诊记忆」：诊中录音/照片/医嘱要点 → 经我们的语音转写+事件聚合+AI 整理 → 自动沉淀进家庭记忆空间，子女远程可见。
- **对他们的价值**：服务从"完成订单"升级为"留下情感资产"，差异化卖点（竞对陪诊做不到）+ 服务可追溯的温感版本。
- **对我们的价值**：预装了真实、高情感浓度的数据场景与付费方（子女为服务+记忆付双份钱）。
- 技术上只用到我们已跑通的能力（上传→转写→聚合→分享），无需先补 AI 对话域。

### 方案 C：技术白牌输出（重，6 个月+，谨慎）
把我们的转写/聚合/检索引擎以 SDK/私有化形式输出进他们的 SaaS。
- 风险：核心壁垒让渡、消耗我方工程资源、对方若"烂尾"在技术团队，接不住交付。
- 只有在 A/B 跑通、对方明确有付费预算时才谈。

### 方案 D：资本/合资层面（现阶段不谈）
对方是国企体系子公司，任何股权动作都涉及国资流程，周期不可控，与 MVP 内测节奏冲突。

## 5. 风险清单与尽调要点

| # | 风险 | 尽调动作 |
|---|---|---|
| 1 | "复星"口径错误或刻意包装 | 确认对接人身份、对方真实的决策层级（复医致享→复医天健→复旦医疗产业投资） |
| 2 | "烂尾"真实含义 | 问清：平台技术团队还在吗？自研系统谁维护？有无欠款/人员流失 |
| 3 | 对方想要什么 | 警惕三种可能：找外包干活 / 想低价拿技术 / 纯粹业务员刷业绩。若对方开口就"你们帮我们开发"，直接降级 |
| 4 | 数据与合规 | 医疗场景记忆涉及健康信息，家庭共享必须过《个保法》敏感信息关；对方医院渠道有HIPAA式院内管理规定 |
| 5 | 我方产能 | 我们是学生团队+AI Agent 并行多项目，只能承诺方案 A 级别的工作量，B 方案需拆分最小闭环 |

## 6. 我的判断

1. **合作值得谈，但叙事必须换**：不谈"相似"，谈"互补"。对方的说服话术如果停留在"我们像"，说明对方没想清楚要我们什么——这本身是个负面信号，谈之前先把"他们图什么"问清楚。
2. **最佳切入点是方案 B（陪诊记忆卡）**：场景契合度极高（就医=高情感浓度记忆时刻），只依赖我们已跑通的技术，且给对方差异化竞争力，是"我有你缺 × 你有我缺"的正交集。
3. **复旦系身份是隐性加成**：你复旦软工在读 + 对方复旦医疗产业体系，信任建立成本天然低，可以善用但不必刻意经营。
4. **第一步动作**：约对方要三样东西——①平台当前真实运营数据（月订单量/活跃陪诊师数）②技术团队现状 ③他们对合作的预期投入。拿到这三样，谈判筹码才算落地。
