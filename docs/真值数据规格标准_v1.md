# 真值数据采集标准 v1（忆述光华 · 产品部人工采集手册）

> 状态：**已拍板**（2026-08-25，峰宝 grill-me 定稿）
> 定位：**给产品部的人工采集手册**——产品部是收集者，按本手册收数据、整理成 JSON。不是给系统用的自动管道规格。
> 决策：①数据来源=**真实用户**（beta 期 W18 起采集）②搜索期望结果=**expected_ids（精确到条）+ expected_label（类别级）双轨** ③隐私=**人脸打码 + 录音只收自述片段** ④交付形式=**JSON 文件**
> 存放：`research/truth-data/{a,b,c,d,e}/`（每批一个子目录 + manifest.json）
> 用途：RAG 上线评测集 / SetFit 校准 / ASR WER 校准 / 事件聚合验收 / 三层裁决效果门禁
> 工具：校验器 `python scripts/validate_truth_data.py`（产品部交付前自检，全绿才入 manifest）

---

## 〇、总则（所有批次通用）

| 项 | 规定 |
|---|---|
| 谁收集 | **产品部（人工）**——招募/访谈 beta 用户、收集授权数据、AI 辅助整理成 JSON、人工最终确认 |
| 数据来源 | 真实用户（beta 期）：访谈提问、用户授权导出、用户日常使用样本；**不团队自造** |
| 文件格式 | UTF-8 JSON，每批一个 `.json` 数组文件 + 音频单独存 `audio/` 子目录 |
| 命名规范 | 记录 id：`{批次}-{4位序号}`（如 `q-0001`）；文件：`{批次}_v{n}.json`（n=版本号，追加不改历史） |
| 必填完整率 | 每条记录必填字段 100%，缺字段 = 该条作废不计入评测 |
| 用户标识 | 一律 `user_id_hashed`（sha256 脱敏），禁止明文手机号/微信 id |
| 时间格式 | ISO8601 带时区（`2026-09-01T10:00:00+08:00`） |
| 隐私铁律 | 照片导出前人脸打码（腾讯 CI 检测 + 高斯模糊）；录音只收自述片段；涉第三方信息置空 |
| 一致性 | D 批多人标注 ≥2/3 一致才入真值；C 批 transcript 必须人工校对后才算真值 |
| 整理方式 | 产品部用 AI 辅助生成初稿 → **人工逐条确认** → 按模板落 JSON |

### 人工采集操作流程（产品部，每周五交付）

1. **招募/授权**：向 beta 用户说明用途并取得口头/书面授权（数据用于改进功能，脱敏后使用）
2. **收集**：按各批指引采集（见下）；工具随意——微信问卷/访谈录音/用户手机导出/产品部记录，**不限形式**
3. **整理**：AI 辅助把收集结果整理成模板 JSON（模板见 `research/truth-data/templates/`）→ 人工逐条核对
4. **脱敏**：照片打码、录音筛自述片段、user_id 哈希化（技术侧可提供打码脚本，非必需）
5. **自检**：`python scripts/validate_truth_data.py` 全绿
6. **交付**：放入 `research/truth-data/{a,b,c,d,e}/`，命名 `{批次}_v{n}.json`，通知技术侧更新 manifest

## A 批：搜索查询评测集（目标 50 条 · RAG 上线评测集，M1 门禁硬依赖）

**产品部怎么收（人工）**：
1. 访谈 beta 用户："平时你会怎么搜自己的记忆？原话说出来"——记下原话（**不改写**）
2. 或收集用户真实使用中的搜索词（询问/截屏/日志转述）
3. 期望结果：问用户"你希望搜到什么？"——能指出具体某条记忆就填 expected_ids；只能描述类别就填 expected_label
4. 分层：产品部判断查询属于哪层（描述性/关键词/错别字/时间表达/图片意图/混合）

**一条记录**：
```json
{
  "query_id": "q-0001",
  "query": "去年生日那天的照片",
  "layer": "temporal",
  "expected_ids": ["a1b2c3d4-...-uuid"],
  "expected_label": null,
  "user_id_hashed": "sha256:...",
  "source": "beta-user",
  "collected_at": "2026-09-01T10:00:00+08:00",
  "note": "用户原话，含口语和时间表达"
}
```

| 字段 | 类型 | 必填 | 枚举/说明 |
|---|---|---|---|
| query_id | string | ✅ | `q-` 前缀唯一 |
| query | string | ✅ | 用户原话，**不改写** |
| layer | string | ✅ | `descriptive`（描述性）`keyword`（关键词）`typo`（错别字/口语）`temporal`（时间表达）`route`（图片意图）`mixed` |
| expected_ids | array<string> | 二选一 | 精确到条：beta 用户点开的真实记忆 content_id（**不能是空数组**） |
| expected_label | string | 二选一 | 类别级：`__none__`（期望无结果）或语义类别描述 |
| user_id_hashed | string | ✅ | 脱敏用户标识 |
| source | string | ✅ | `beta-user`（用户真实搜索）`annotation`（产品部补标） |
| collected_at | string | ✅ | ISO8601 |
| note | string | 否 | 补充上下文（口语背景、搜索意图） |

**分层分布目标**：descriptive ≥20 / keyword ≥10 / typo ≥5 / temporal ≥5 / route ≥5 / mixed ≥5（共 ≥50）。

## B 批：文字碎片（目标 100-200 条 · SetFit 5 类校准，M1/M2 门禁）

**产品部怎么收（人工）**：
1. 访谈/问卷：让 beta 用户口述或写下"随手记的碎片"（待办/灵感/情绪/引用/混搭都行）
2. 或用户授权导出其 App 内文字记录（技术侧可导出原始数据，产品部脱敏后整理）
3. 分类：用户自己说它属于哪类优先；说不清的产品部定，争议样本标 `disputed`（不计入校准）

**一条记录**：
```json
{
  "fragment_id": "f-0001",
  "text": "明天记得带身份证去体检",
  "label": "待办",
  "label_confidence": "confirmed",
  "source": "beta-user",
  "user_id_hashed": "sha256:...",
  "collected_at": "2026-09-01T10:00:00+08:00",
  "note": ""
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| fragment_id | string | ✅ | `f-` 前缀 |
| text | string | ✅ | 原样文本（长度 2-500 字） |
| label | string | ✅ | `待办` `灵感` `情绪` `引用` `混合`（唯一枚举，不可自定义） |
| label_confidence | string | ✅ | `confirmed`（用户/人工确认）`ai-assisted`（AI 初判+人工过目）`disputed`（争议待定——**disputed 不入校准集**） |
| source | string | ✅ | `beta-user` `annotation` |
| user_id_hashed | string | ✅ | 脱敏 |
| collected_at | string | ✅ | ISO8601 |

**分布目标**：每类 ≥20 条；长度覆盖 5-200 字；含口语/网络语/错别字样本（typo 类）。

## C 批：语音片段（目标 20-50 段 · ASR WER 校准）

**产品部怎么收（人工）**：
1. 征得用户同意后，请用户**自己一个人**录一段"今天想说的"（1-3 分钟，手机录音即可）
2. 或用户授权导出其 App 内语音记录——但只保留**自述片段**（无他人可识别语音）
3. 产品部抽听，人工校对转写（transcript_source=human）——机器转写不算真值

**一条记录**：
```json
{
  "clip_id": "v-0001",
  "audio_ref": "research/truth-data/c/audio/v-0001.wav",
  "duration_s": 23.5,
  "transcript": "今天项目上线了，累但是开心",
  "transcript_source": "human",
  "emotion": "happy",
  "noise_level": "clean",
  "self_talk_only": true,
  "user_id_hashed": "sha256:...",
  "collected_at": "2026-09-01T10:00:00+08:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| clip_id | string | ✅ | `v-` 前缀 |
| audio_ref | string | ✅ | 相对路径；wav/m4a，≤3.5min（对齐客户端录音上限） |
| duration_s | number | ✅ | 秒，1 位小数 |
| transcript | string | ✅ | **人工校对后**的转写（真值口径） |
| transcript_source | string | ✅ | `human`（人工）`asr`（机器初判，仅参考不计真值） |
| emotion | string | 否 | `happy` `sad` `angry` `neutral` 等（可空） |
| noise_level | string | ✅ | `clean` `noisy` `bgm` |
| self_talk_only | boolean | ✅ | **必须 true**（隐私铁律，false 该条作废） |
| user_id_hashed | string | ✅ | 脱敏 |

**验收**：WER 评测只统计 `transcript_source=human` 的条目；每条需产品部 1 人校对 + 1 人抽检。

## D 批：照片事件真值（目标 50-100 张 / 覆盖 3-5 天 · 事件聚合 L1/L2 验收）

**产品部怎么收（人工）**：
1. 找 2-3 位志愿者，授权导出其**连续 3-5 天**的手机照片（如某次旅行/周末+工作日）
2. 导出后**人脸打码**（技术侧提供打码脚本，腾讯 CI 检测+模糊；产品部确认无清晰人脸）
3. 产品部 2-3 人**独立**把照片按天分组（L1）+ 按主题归并（L2），然后对照——≥2/3 一致才入真值

**一条记录（一套 = 一个用户一个时间窗）**：
```json
{
  "set_id": "p-0001",
  "user_id_hashed": "sha256:...",
  "time_span": { "from": "2026-08-22T00:00:00+08:00", "to": "2026-08-25T23:59:59+08:00" },
  "photo_refs": ["research/truth-data/d/photos/p-0001/001.jpg"],
  "expected_l1": [
    { "date": "2026-08-22", "photo_ids": ["001.jpg", "002.jpg"], "title": "周末出游" }
  ],
  "expected_l2": [
    { "theme": "西湖一日游", "l1_dates": ["2026-08-22"], "photo_ids": ["001.jpg"] }
  ],
  "annotator_count": 3,
  "consensus": "3/3",
  "collected_at": "2026-09-05T10:00:00+08:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| set_id | string | ✅ | `p-` 前缀 |
| user_id_hashed | string | ✅ | 脱敏 |
| time_span | object | ✅ | 连续时间窗（3-5 天） |
| photo_refs | array<string> | ✅ | **打码后**照片副本路径 |
| expected_l1 | array | ✅ | 期望日卡片：date（`YYYY-MM-DD`）+ photo_ids + title（可空） |
| expected_l2 | array | 否 | 期望主题归并：theme + 覆盖的 l1 日期 + photo_ids（**跨天归并是 L2 关键验收点**） |
| annotator_count | number | ✅ | 标注人数 |
| consensus | string | ✅ | `n/m`（≥2/3 才入真值） |
| collected_at | string | ✅ | ISO8601 |

**验收口径**：系统 L1 与 expected_l1 对比（日卡片成员一致性）；L2 主题归并与 expected_l2 对比（跨天归并正确率）。

## E 批：纠错样本（目标 10-20 条 · 三层裁决效果门禁）

**产品部怎么收（人工）**：
1. 访谈/使用观察：记录"用户本来想说/记成什么，后来改成什么"的真实案例
2. 或用户授权导出 App 内改分类记录（技术侧可导出 correction_log 原始数据，产品部整理）

**一条记录**：
```json
{
  "correction_id": "c-0001",
  "text": "周末想去看展",
  "predicted": "灵感",
  "corrected": "待办",
  "context": "user-manual",
  "user_id_hashed": "sha256:...",
  "collected_at": "2026-09-01T10:00:00+08:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| correction_id | string | ✅ | `c-` 前缀 |
| text | string | ✅ | 原文 |
| predicted | string | ✅ | 系统初判（5 类枚举） |
| corrected | string | ✅ | 用户/裁决后类别（5 类枚举，≠predicted） |
| context | string | ✅ | `user-manual`（用户手动改）`arbitration`（三层裁决） |
| user_id_hashed | string | ✅ | 脱敏 |
| collected_at | string | ✅ | ISO8601 |

**验收口径**：纠错后 7 天同类准确率提升 ≥10%（对 B 批同分布样本重测）。

## 交付流程（产品部 → 技术）

1. 产品部按上文指引人工收集 → AI 辅助整理成 JSON（模板见 `templates/`，可要求技术侧提供批量导出初稿，**人工确认后才算交付**）
2. 放到 `research/truth-data/{a,b,c,d,e}/`，命名 `{批次}_v{n}.json`
3. 产品部自检：`python scripts/validate_truth_data.py`（校验必填/枚举/一致性/隐私标记）→ 全绿
4. 技术侧登记 manifest + 评测 harness 消费（RAG run_eval --real / SetFit 校准 / run_wer_bench --truth / 事件聚合 run_validation --truth）

## 技术侧支持项（辅助产品部，非自动管道）

1. `scripts/export_truth_data.py`（可选）：从 contents/correction_log 导出 B/E 批**初稿**（产品部人工确认后入真值）
2. `scripts/mask_faces.py`（可选）：照片人脸打码（腾讯 CI 检测 + 高斯模糊）
3. 评测 harness `--real` 模式：消费真值目录跑评测
4. 明确**不做**：搜索自动埋点日志、系统级自动采集——采集由产品部人工完成
