# P0-3 从已有记忆重建画像修复记录

- 执行时间：2026-10-28
- 账号：当前真机账号
- 环境：API `0.0.0.0:8010` + RQ worker

## 一、问题

修复前画像管理页：

- “刷新画像”只重新调用 `GET /interview/profile`，没有重算；
- 画像标签把内部维度 key（如 `relation_role`）当标签显示；
- 没有从用户已有内容重建画像的任务入口；
- 页面没有明确的无画像空态。

## 二、实现

### 2.1 后端异步任务

新增：

```text
POST /api/v1/profile/rebuild
GET  /api/v1/profile/rebuild/jobs/{job_id}
```

任务放入 low 队列：

- 扫描本人 `status=done` 且有文本的内容；
- 复用现有 `profile_annotator.annotate_content`；
- 单条失败隔离，不中断整批；
- `Content.extra.profile_rebuilt_at` 作为幂等标记；
- 清除画像时同时移除该标记，允许下一次真正重建；
- RQ meta 返回 total/processed/applied/pooled/failed/skipped/degraded；
- 任务查询校验本人归属，不存在与越权统一返回 404 `PROFILE_001`。

### 2.2 前端

画像管理页：

- “刷新画像”创建真实后端任务并轮询；
- 显示“正在整理 N/M 条记忆”等进度；
- 完成后重新拉画像和统计；
- 无真实 LLM 时显示“已完成（本地规则模式）”；
- 标签显示实际画像值，不再显示内部 dim id；
- 接口暂无置信度时不再伪造百分比；
- 增加“暂无可展示画像”的诚实空态。
