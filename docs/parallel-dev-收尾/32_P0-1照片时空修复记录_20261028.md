## 一、已完成

### 1. 后端 EXIF 时间兼容

`backend/app/services/photo_exif.py`：

- 拍摄时间读取顺序改为 `DateTimeOriginal → DateTime`。
- 真实相机只写 tag 306 `DateTime` 时也能得到拍摄时间。
- 不读取文件系统 mtime，避免复制/同步时间冒充拍摄时间。

### 2. 两条照片上传链路统一解析

- multipart 与分片 complete 均以照片 EXIF 时间为最终权威值。
- 照片 EXIF GPS 优先于客户端“打开面板时”的位置。
- 分片 complete 缺少 bytes 入参时，注册层从存储原件补解析 EXIF。

### 3. 上传响应回填最终事实

`UploadCompleteOut` 新增：

- `taken_at`
- `gps_lat`
- `gps_lng`

客户端 `UploadOutcome` 读取这些字段并原地更新 `PhotoItem`。随后端侧 L1
聚合使用的是后端最终确认的拍摄时间和 GPS，不再继续使用保存时刻。

### 4. 客户端照片来源区分

`RecordSheet.uvue`：

- 相册旧图不再默认使用当前位置。
- 相机新拍仍允许在相机入口刷新当前位置作为 EXIF 缺失兜底。
- 相册选择显式请求 `sizeType=['original']`。
- 相册临时图优先根据文件名+大小回查 MediaStore 原始媒体 EXIF。
- 没有权威拍摄时间时，不生成 1970 或保存时间事件。

### 5. 原生照片插件 v1.1.0

`yishu-photo-watch` 新增实例方法：

```text
lookupPickedPhotoMetadata(displayName, size)
```

回查顺序：

1. MediaStore `_display_name + _size` 定位原媒体；
2. 原始媒体 URI 输入流 + ExifInterface；
3. 原始 `DATA` 路径 + ExifInterface；
4. MediaStore `DATE_TAKEN/DATE_ADDED` 时间兜底；
5. GPS 均不可得时保持 null，不用当前位置冒充。

插件版本已升至 `1.1.0`。

### 3.2 真机相册上传

强制选择 `yishu_p0b` / `yishu_p0c` 的 3 张原图后：

- 三张照片 `taken_at` 全部正确；
- 9 月照片无 GPS，保持空；
- 另两张 GPS 仍为空。

进一步检查确认：

- `/sdcard/Pictures` 原文件本身仍含 GPS；
- 系统选择器生成的同尺寸 temp 文件清除了 GPS；
- MediaStore 的 `LATITUDE/LONGITUDE` 列在 OPPO 上被雾化为 NULL；
- scoped storage 下旧自定义基座中的插件无法读取原始 GPS。

因此时间链路已真机通过；历史相册 GPS 恢复代码已编译，但必须进入新的
自定义基座或正式 APK 后才能做最终真机确认。

### 3.3 2026-10-29 ADB 回归补充

ADB 标准基座复测发现一张历史照片被写成 `(0,0)` 并生成错误地点。已补四层防护：

- 后端 EXIF：全零坐标返回 `None`；
- 后端上传 meta：全零或单边坐标归空；
- 客户端选图回填：拒绝 `(0,0)`；
- 客户端上传与照片监听插件：不发送 `(0,0)`。

相关专项测试 `65 passed`。修复后同一历史照片写入 `gps=None, place=None`，不再生成
错误地点；标准基座仍取不到原始 GPS，最终正确定位仍需 104/新自定义基座复验。
完整过程见 `37_ADB通道真机测试记录_20261029.md`。
