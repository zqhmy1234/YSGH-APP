## 一、问题复现

当前账号明确存在：

- 文字内容：`你好`；
- 语音转写：`这是一段本地模拟转写文本。`。

修复前：

| 查询 | 结果 |
|---|---:|
| 你好 | 0 |
| 本地模拟 | 0 |
| 不存在的唯一词XYZ987 | 0 |

根因：Qdrant 只要返回任意语义候选，就不会触发 PG 关键词兜底。因此明确存在的
字面关键词没有独立召回通道，完全依赖 Qdrant 是否恰好把它召回。

## 二、实现

### 2.1 独立精确召回

新增 `_pg_exact_search`：

- 内容原文；
- 标签 `tags_json` / `extra.ci_tags`；
- 事件标题；
- 用户隔离、软删除、`status=done`；
- 显式类型/时间/地点/标签过滤。

精确通道不套用 LLM/NER/分类器推断的类别过滤，防止正确关键词被模型推断条件挡住。

### 2.2 与语义召回合并

搜索顺序：

```text
Qdrant dense+sparse 语义召回
  + PG 原文/标签/事件标题精确召回
  → content_id 去重
  → 精确命中提权
  → 事件归属与溯源
```

精确召回不再只在 `raw_hits=[]` 时执行。

### 2.3 可解释结果

`trace` 新增：

- `exact_score`
- `matched_fields`

可能取值：

- `text_phrase`
- `text`
- `tag`
- `event_title`

客户端显示为用户语言：

- 精确
- 原文
- 标签
- 卡片标题

### 2.4 结构治理

新增 `services/query_helpers.alive_clause(model)`，收敛软删除查询条件，并按结构
棘轮要求同步 per-file 基线。

## 五、当前边界

1. 关键词明确存在于内容/标签/事件标题时，已能稳定进入结果。
2. 语义近邻仍会保留在精确结果之后，用于支持同义表达和描述式搜索。
3. 纯语义、无关键词的结果仍可能返回最近邻；严格“无关词必须 0 条”需要下一轮
   真实负样本标定 dense/answerability 阈值，不在本次关键词通道修复中擅自调整。
4. 搜索结果目前仍按语音卡、文字/照片卡分区展示；后端排序已保证精确命中优先，
   跨类型统一排序可作为下一项 UX 优化。
