# 101 与 102 APK 差异审计

> 日期：2026-10-23
> 对象：`__UNI__2650A2A_1014141701.apk` 与 `__UNI__2650A2A_1023011434.apk`
> 目的：确认 102 是否只是 101 加新增功能，并定位输入框白字回归

## 1. 结论

1. 两个 APK 都包含 1338 个文件，其中 1330 个文件逐字节相同。
2. 只有 8 个文件不同：版本清单、签名文件、`app-service.js`、`classes2.dex` 和 `baseline.prof`。
3. `app-service.js` 只差 8 行，其中 6 行是三个输入框的颜色样式，2 行是编译器自动生成的组件 ID。
4. `classes2.dex` 长度完全相同，只有 25 个字节不同：24 字节是 dex 的签名/校验头，另 1 字节为 `0x65` 到 `0x66`，对应版本 101 到 102。没有新增业务方法或类。
5. 因此 102 在功能代码上并不是“101 + 后续新功能”，实际更接近“101 + 版本号变化 + 三个输入框样式回归”。
6. 当前 102 中没有发现 `SearchHitOps`、`ChatAttachment`、`include_profile`、搜索历史等后续源码功能标记。若这些功能应在 102 中，则 102 是错误或过期的构建产物。

## 2. 输入框差异

| 位置 | 101 APK | 102 APK |
|---|---|---|
| 主搜索框字色 | `color:#3A2E25` | `color:var(--c-ink-900, #3A2E25)` |
| 主搜索框占位色 | `color:#B3A696` | `color:var(--c-ink-300, #B3A696)` |
| 收藏页搜索框字色 | `color:#3A2E25` | `color:var(--c-ink-900, #3A2E25)` |

Android 原生输入控件可以正常解析字面十六进制颜色，但没有正确解析这里的 CSS 变量及 fallback。输入值和搜索逻辑均存在，实际文字却被绘制成白色。
