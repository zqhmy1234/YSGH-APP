## 3. 7 清单执行流程

### 3.1 顺序建议（高频项先行，失败项不阻塞后续）
`01 蜂窝+横幅 → 02 录音中断 → 03 30s 计时 → 04 L2/L3 归并 → 05 转写/情绪 → 06 HBuilderX 冒烟 → 07 自定义基座`

### 3.2 每份清单执行五步（用户照做）
1. 读清单「目的/前置」→ 勾 §2 前置。
2. 按「步骤」逐步执行（编号可照做；adb 辅助用 `scripts/realdevice/adb_helpers.ps1`：Shot/GrabLog/Record）。
3. 对照「预期」判定：通过 / 失败 / 降级（填原因）。
4. 采集证据：截图/日志按 `evidence/ck<编号>_<步骤>_<YYYYMMDD_HHMMSS>.png` 命名存 `scripts/realdevice/evidence/`。
5. 填「记录表」（§5 模板）→ 通知协调者。

### 3.3 判定口径（引用 D1 清单，各清单核心标准）
| 清单 | 核心判定 |
|---|---|
| 01 | 蜂窝体积明显小于 WiFi（缩略图+元数据）；暂停/恢复横幅；断网重试不丢 |
| 02 | 来电打断恢复续录不丢段；30min 自动结束（可标注调试参数缩短验证）；FGS 通知常驻 |
| 03 | 授权完成 → 首批日卡片渲染 ≤30s（≥50 张）；起止时刻截图 + 分段计时 |
| 04 | L2 主题事件正确归并（标题/封面/成员数），后端日志显示真实 qwen（非 mock） |
| 05 | 转写文本可读 + 情绪标签与录音一致；日志显示 FunASR/SenseVoice 真实调用 |
| 06 | HBuilderX CLI 编译无错 + 六页可达 + 关键链路可用 + logcat 无 FATAL |
| 07 | SQLCipher XView 加载无错；FGS/WorkManager 真实执行；attribution 面板可见 |

## 4. 协调者职责（主窗口，实时跟进）

1. **结果接收**：每份清单完成即收（用户在会话里回报 or 证据目录落盘）。
2. **环境 vs 代码区分**（失败时第一问）：网络/后端在线/key/蜂窝？先按 §2 前置排查；确认代码缺陷才开缺陷单。
3. **缺陷流转**：缺陷单模板——
   ```markdown
   ## 缺陷单 D-<序号>（<日期>）
   - 清单：<ck编号>｜用户故事/门禁：<US-xx / §7.1 项>
   - 现象：____ 期望：____ 实际：____
   - 证据：<路径> 后端日志关键行：____
   - 归属：环境 / 客户端 / 后端 / 数据
   - 处置：登记远期待办 or 开小补丁分支（走 INT merge）or 降级标注
   ```
4. **证据升级登记**：每通过一项 → 更新 `progress.md`（真机记录格式沿用既有）+ `feature_list.json`（对应 feature 的 evidence 追加 `真机 A 级：<日期> <清单> <结论>`）。
5. **30s 计时门禁**：清单 3 达标 → §7.1 该项从 🟡 转 ✅（在 progress 注明）。

## 6. 证据标准（全部清单统一）

1. 三要素：真机型号（nova 11）+ 日期时间；截图/日志文件路径；判定（通过/失败/降级原因）。
2. 命名：`evidence/ck<编号>_<步骤>_<YYYYMMDD_HHMMSS>.png`（adb_helpers 自动命名）。
3. 日志：`adb logcat -d -T <时间戳> | Select-String <关键词> > evidence/ck<编号>_<关键词>.log`；关键清单（04/05）需后端日志（真实 qwen/FunASR/SenseVoice 调用记录）作非 mock 证据。
4. 降级规则：设备不在场/网络不可用 → 标"待补"，不得虚构 A 级（07 报告证据纪律）。
5. 截图黑屏排查：`adb shell svc power stayon usb` 屏幕常亮；`dumpsys window | grep mCurrentFocus` 确认 App 在前台。
