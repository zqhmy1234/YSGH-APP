# P0-4 语音转写修复记录

日期：2026-10-28
角色：开发 C
范围：客户语音转写降级、失败重试、后端 ASR 配置与验收口径

## 1. 本轮目标

解决记录页语音输入无法稳定转成文字的问题，并明确区分以下三种状态：

1. 本地/远端 ASR 已真实识别；
2. 当前环境被 mock 配置接管；
3. ASR 确实失败，但录音与用户输入不能因此丢失。

目标是先把可内测的降级链路做通，再切换真实模型完成最终验收。

## 2. 根因

### 2.1 后端缺少本地 ASR 路径

原转写实现主要依赖百炼远端服务。没有配置远端 Key 时，语音链路只能失败或落入模拟数据，缺少可独立运行的本地 SenseVoice 兜底。

### 2.2 后台二次增强失败会拖垮已成功的前端转写

客户端已经取得有效转写文本后，后台仍会执行二次 ASR 增强。原逻辑中，只要增强阶段报错，整条内容就可能被标记为 `failed`，用户已看到并已提交的文字反而丢失。

### 2.3 客户端转写失败后缺少恢复入口

失败后虽然会提示错误，但录音与重试操作没有形成闭环，用户只能重新录制。

## 3. 已完成的修复

### 3.1 本地 SenseVoice 兜底

- 新增 `SENSEVOICE_MODEL_DIR` 配置。
- 配置本地模型目录后，即使没有百炼 Key，也可走本地 SenseVoice 转写。
- 远端能力与本地能力按配置顺序选择，不再把“无远端 Key”直接等同于“语音不可用”。

### 3.2 后台增强失败不覆盖已有结果

- 后台 ASR 二次增强失败时，只要客户端已经提供有效转写，内容继续保持 `done`。
- 失败信息保留在流水线元数据中，供排查使用，但不回滚用户已经得到的文字。

### 3.3 客户端保留录音并支持重新转写

- 转写失败时保留本次录音。
- 增加“重新转写”入口。
- 用户可以原地重试，不需要重新录制。

### 3.4 客户端 ASR 上传超时放宽

- ASR 直传原来固定超时 30 秒，但该链路允许接近 4 分钟的 WAV；云端稍慢时客户端会先判失败，即使后端随后返回 200。
- ASR 上传单独放宽到 90 秒；其他普通请求超时保持不变。

### 3.5 内容审核异常不再变成 API 500

- 当审核凭据缺失或误填为非 ASCII 占位文字时，`httpx` 会抛 `UnicodeEncodeError`。
- 原实现只捕获网络异常，导致 ASR 路由返回 500。
- 现在非 ASCII 请求头按“托管审核不可用”降级，由既有 fail-safe/兜底策略处理。
- 新增回归测试，防止无效凭据再次把整条 ASR 路由打成 500。

### 3.6 首次录音权限等待放宽

- ADB 真机首次授权麦克风时，系统权限弹窗可能超过 15 秒；旧看门狗会先判失败，
  用户随后授权仍会看到一次“录音失败”。
- 权限看门狗由 15 秒放宽到 60 秒，仍保留回调丢失兜底。

### 3.7 相关专项测试

- 语音、内容安全、fail-safe 三组专项测试：`74 passed`。
- 复核 ASR 与 guard_managed：`58 passed`。
- 客户端编译门：通过（26.7 秒）。

## 4. 当前验证结果与边界

初始本地环境配置为：

```text
app_env=development
mock_external_ai=True
dashscope_configured=True
sensevoice_model_dir=''
```

当时接口返回仍为：

```text
这是一段本地模拟转写文本。
audio_processing.mock=True
```

该状态下的结论：

- 当前文本来自 mock，不是 SenseVoice 或百炼的真实识别结果。
- 当前已有百炼 Key，但 `MOCK_EXTERNAL_AI=true` 会强制跳过真实外部 AI。
- 因此本轮可以确认“降级、保留录音、重试 UI、后台失败不回滚”已打通，但不能把 mock 文本当作最终语音识别验收。

后续核对发现，`backend/.env` 中 `DASHSCOPE_API_KEY` 实际是说明文字，真正 Key 位于仓库外
`D:\projects\photo_pipeline\_local_keys.env`。已用最小 `qwen-flash` ping 验证该 Key 可调用，
测试期间只在服务进程环境中注入，未把 Key 写入仓库。

## 5. 真实模型验证结果

### 5.1 百炼 Fun-ASR

使用真值数据 `a001.mp3` 截取 12 秒语音，经正式接口
`POST /api/v1/asr/transcribe?preferred=funasr` 返回：

```text
outcome=succeeded
channel=funasr
mock=false
model=fun-asr-flash-2026-06-15
duration_ms=12000
guardrail_passed=true
provider_request_id=5d7c4251-5a2a-9968-8c02-dccc04d0f9fb
text=刚刚做完了工作，然后想着休闲一下。嗯，但是我发现现在手机上很少有真正可以属于自己的地方，就是。
```

另用一条 3 秒历史录音验证云端“无词”边界：

```text
code=HTTP_400
message=ASR_RESPONSE_HAVE_NO_WORDS
```

该结果不是鉴权或网络故障，系统随后正确降级到本地 SenseVoice，并返回真实本地转写。

### 5.2 PKX110 真机

使用 HBuilderX 自定义基座清理缓存重新运行最新 `client` 后：

1. 手机录制 11 秒；
2. 请求到达 API，后端返回 200；
3. 页面从录制态进入“补充信息”；
4. 客户端显示 `funasr` 通道、情绪“平静”；
5. 原生输入框实际文本为“以及晚上7点以后嘛。”，不是 mock 占位文本；
6. 后端继续发起 `/api/v1/classify` 并成功返回任务状态。

至此，真实录音、上传、Fun-ASR 转写、安全审核、客户端展示、AI 分类主链已连通。

### 5.3 联调环境注意事项

- 最新客户端 `ENV='prod'`，联调地址为 `http://192.168.31.143:8010`。
- API 必须监听 `0.0.0.0:8010`；若只监听 `127.0.0.1:8010`，真机会一直显示“正在转写”并最终失败。
- HBuilderX 重新运行自定义基座后可能清空 `adb reverse`；使用局域网地址时不需要 reverse，使用 `localhost` 模式时必须重新执行 `adb reverse tcp:8010 tcp:8010`。
- `scripts/dev/start_all.ps1` 已改为自动选择 `ysgh_venv`、从仓库外 `_local_keys.env` 注入密钥，并支持 `-SkipAgent`：

```powershell
pwsh -NoProfile -File scripts\dev\start_all.ps1 -SkipDocker -SkipAgent
```

该命令已在临时端口验证可以启动 API 并返回 `healthz=200`。
