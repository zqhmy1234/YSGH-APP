## 0. 先纠正我自己上一版的两个错误

**错误一：把许可当成技术结论。**
上版写"只借设计不复制代码"，主要理由是"Linger Open Source License 有附加条款"。查了 LICENSE 原文后，这个理由站不住：

- 基础是 Apache 2.0；条款 1 明确"**may be used commercially, including by a company for its own work and as a backend for its own applications**"。
- 唯一需要书面确认的是 1.a：不得"把 Linger 源码作为 hosted/managed service 提供给组织外的人"（定义含"每个用户各自一套部署"也算）。我们的 App 确实是面向第三方用户的托管服务，所以**若整包 vendor 成后端**要与 SIMPLEX AI 谈授权。
- 1.b 只限制 `apps/web/` 前端去掉 LOGO——我们不用它的前端，不受影响。

结论：**代码内嵌/改造复用属于 Apache 2.0 基础允许范围，登记 + NOTICE + 文件头标注即可**；只有"把 Linger 当服务转售"才需要谈。这不是技术阻碍，按你说的"遵循就好"。

**错误二：没区分"Linger 的 Agent"到底是什么。**
`docs/local-inference.md` 白纸黑字：Runtime = **Claude Code / Codex / Pi**（"Claude Code, Codex and Pi run as they always do"）。所以：

- Linger **没有自研 Agent 框架**可搬。它的 agent 是"外部 runtime + 一层 MCP 工具面 + `team.md` 规则 + 审批/调度"。
- 它真正自研、且值得搬的是 **记忆写入器（memory/llm-wiki）、记忆维护循环（memory-agent）、检索协议**。
- 我们要搬的对象因此是**"记忆与校验的算法"**，不是"agent loop"。我们的 LangGraph 才是自有 runtime，这块搬不动也不需要搬。

## 1. 复用分级矩阵

| 级 | 定义 | 对象 | 结论 |
|---|---|---|---|
| **L0** | 业务本体，搬来即错配 | `apps/teamhub`（Go：Rooms/Documents/Profile/River 调度）、`memory_source` 视图、OpenWiki 图、`apps/web` 前端、PolyStrata/Strata、Codex/Claude/Pi runtime | ⛔ 不搬，只读它们的**约束来源** |
| **L1** | 可 1:1 vendor（打包原样进仓库，只做接线） | ① `prompts/memory-agent/principles.md`、`prompts/llm-wiki/personal/*.md`（提示词资产）② `memory/apply.ts` 的事务外壳（若走 Node sidecar 方案） | ✅ 搬 |
| **L2** | 逻辑等价移植（改造后直接用，保真到规则名/顺序） | `memory-agent.ts` 循环 → Sculptor harness；`wiki-candidate-validation.ts` 规则表 → Provenance/Sculptor 校验；`chunks.ts` 切块 → Librarian 分块；`memory/README.md` 查询协议 → SearchQuery/SearchResult 契约 | ✅ 搬，逐条对照 |
| **L3** | 只搬常量与公式 | 输出预算分级（20k 字符闸、5 items/3 summaries、600 字底线）、近因公式 `1+0.2*(recency-0.5)` 与 60 天衰减、19 个 issue code、拒答口径 | ✅ 搬 |
| **L4** | 明确不搬 | PG FTS + CJK bigram + BM25F 检索内核（我们是 BGE-M3 dense+sparse + Qdrant + rerank，搬它=自废一半能力）；TeamHub 的 River/审批/推送；本地模型栈；OpenWiki 原生图 | ⛔ 不搬 |

**一句话**：**写入侧（Sculptor / Provenance / 记忆台账）它以 Markdown 为权威、我们以 PG 为权威，但"提案→校验→应用"这套算法与规则表可以 90% 保真移植；检索侧它的设计前提（无向量）与我们的架构相反，只能借协议不能借内核。**

## 2. 为什么不 1:1 整套搬（六条，带证据）

1. **没有可搬的 Agent 本体**。它的 agent runtime 是外部三件套（Claude Code/Codex/Pi）。搬它等于把产品改成"每台电脑装 Codex"——与云侧 FastAPI 8300 + qwen-flash + uni-app 多租户冲突。
2. **数据本体不同**。它的对象是 `client/contact/project/topic/session` 五类 wiki 页 + Room；我们是 `contents / events(L0-L4) / echo_history / profile / person`。validation 里的"必需 H2 段顺序""同一实体不得两个页""别名合并"全部绑死在它的 ontology 上。直接跑 = "能跑，但校验的不是我们的东西"。
3. **检索栈方向相反**。`memory/README.md`：*"keyword search only… no vector or rerank model is called and there is no vector column"*。我们已定 BGE-M3 双塔 + 双层 rerank + Qdrant named vectors；整包搬会主动砍掉 45 万行后端里最贵的那部分能力。
4. **运行时栈**。`apps/node-services/package.json`：`node >=26.5.0 <27`、pnpm workspace、`@linger/*` 私有包（未上 npm）、`openwiki`/`hocuspocus`/`yjs`/`pdfjs-dist` 等 20+ 依赖。加一个 Node 常驻服务 = 多一条供应链 + CI 腿 + 一个容器；而把 apply/validation 移植成 Python 约 1200 行。
5. **数据面要靠假视图接**。它读 TeamHub 的 `memory_source` 只读视图、写 `memory_index`。我们的 32 表在 FastAPI 侧，要让它跑必须先造一层"TeamHub 形状"的视图——这是最贵的一种适配：把别人的领域模型翻译成我们的，翻译层本身就是全部风险所在。
6. **许可（已改判）**：见 §0，只影响"整包做托管服务"，不影响内嵌复用。

## 7. 模块实施方案

> 输入/输出分布为**设计预算**（容量与门禁阈值），P6 由回放集校准，不作结论引用。

### 7.1 Orchestrator（`harness/orchestrator.py` + `plan.py`）
- 职责：九步（准入→护栏→意图→取料→装配→调度→校验回路→落库回执→收尾观测）。
- 模式：Pipeline + Strategy；`plan()` **纯函数**（TurnContext→TurnPlan），可 100% 单测。
- 输入分布：闲聊 40-45%｜回忆检索 28-32%｜记录/纠正 12-15%｜情绪 6-9%｜设置 2-4%｜越界 2-3%。
- 输出分布：Agent 调用 1-3；LLM 调用 1（常态）/2（触发校验）；预算拒绝 <1%。
- 契约：`GuardPort/LLMPort/TracePort` + Agent 的 `run(plan)->output`；零 adapter 依赖。
- 测试：决策表 60 例（降级/超时/危机三分支）；预算溢出必须回 `degraded`。

### 7.2 Frame（`harness/frame.py`）
- 九段：人设→关系→雷区→修正→digest→叙事摘要→证据→任务约束→危机口径。
- 模式：Builder + 分层缓存（稳定段按 persona 版本键；易变段每轮重建——对应 Linger "summary 不进 system prompt，避免 prompt cache 失效"）。
- 输入分布：稳定段命中 ≥95%；digest 三态 ok 70% / insufficient 20% / unavailable 10%。
- 输出分布：≤4200 字；证据段 ≤1200 字/≤8 条；裁剪顺序固定（低分证据→叙事摘要；**永不删雷区与修正**）。
- 测试：裁剪顺序快照；"雷区被裁"必红。

### 7.3 Muse（`agents/muse/`）
- 唯一出话、唯一无写权。模式：Inner-loop（`create_agent`）+ Gate Chain（validator→provenance 钩子→输出契约）。
- 输入分布：100% 触发；只读工具 0-3 次/轮。
- 输出分布：120-380 字；引用 0-3；拒答 1-3%；P50 1.6s / P95 4.2s。
- 测试：越界负向 12 例；工具预算超限降级；`heal_dangling_tool_calls` 回归。

### 7.4 Librarian（`agents/librarian/`）
- 只给证据不给结论；双列表（摘要/原文）。模式：Ports&Adapters + 多通道 RRF + 双列分离。
- 输入分布：触发 30-40%；`alternates` 均 2.1；mode evidence 65/overview 20/person 10/time 5。
- 输出分布：hits 3-8；empty 4-8%；relaxed 12-18%；clarify 5-9%；P50 180ms / P95 420ms。
- 保真要求：`empty` 之前必须打过 originals（Linger 规则："must search the originals before it says something was never recorded"）。
- 测试：`resolve_query` 三通道 filter 同源；"问 3 月答案在 1 月"仍召回（时间只加权）。

### 7.5 Provenance（`agents/provenance/`）
- 只判不写；私料无证据 fail-closed。模式：Specification/Rule-engine + 责任链（P1-P5 短路）。
- 输入分布：触发式 15-25%（含私料/数字/日期/人名或回忆检索意图）。
- 输出分布：pass 78-85%｜needs_evidence 8-12%｜mask 4-7%｜reject 1-3%｜handoff <0.5%；P50 45ms，LLM 触发 ≤800ms。
- 保真要求：issue code 与判定顺序对齐 §3。
- 测试：8 条负向探针（§9）。

### 7.6 Sculptor（`agents/sculptor/`）
- 离线加层，只加不改原文，幂等可回滚。模式：PVA + 批量幂等 + 快照回滚 + 限步债务循环。
- 输入分布：夜间 1 批/人/日 + 增量触发 ≤6 次/日；批内 200-800 条。
- 输出分布：提案 6-25（add 60/update 30/retract 8/came_from 2）；整批接受 70-85%；拒绝码 missing_evidence 45/scope_violation 20/duplicate 15/dropped_source 10/其它 10。
- 测试：双跑 hash 一致；apply 异常回滚；"AI 覆盖用户修正"必红。

### 7.7 Serendipity / 7.8 Memory / 7.9 Policy / 7.10 API
沿用 V1 方案，不变。要点：Serendipity 零写；Memory 双时序 + 三态（confirmed 55-65/draft 30-40/rejected 3-8）；Policy 四落点（修正优先/雷区/禁语/危机）；API 4 端点 + `/v1/chat` 兼容。

## 8. 抽象契约（不变，摘核心）

```python
class SearchPort(Protocol):
    async def retrieve(self, q: SearchQuery) -> SearchResult: ...

class SearchQuery(BaseModel):
    query: str; person_id: str
    mode: Literal["evidence","overview","person","time"] = "evidence"
    alternates: list[str] = []                       # ≤6，各 ≤200 字
    date_from: date | None; date_to: date | None
    event_from: date | None; event_to: date | None
    as_of: date | None
    limit: int = 20

class SearchResult(BaseModel):
    hits: list[Hit]; summaries: list[Hit]
    reason: str | None; relaxed: bool; clarify: str | None
    event_hit_count: int; trace: list[TraceItem]
    degraded: bool; gaps: list[str]
    status: Literal["grounded","partial","empty"]

class ProvenancePort(Protocol):
    async def judge(self, c: ClaimBundle) -> Verdict: ...   # pass|needs_evidence|mask|reject|handoff

class MemoryWritePort(Protocol):
    async def propose(self, p: MemoryProposal) -> WriteReceipt: ...
    async def commit(self, b: ProposalBatch) -> CommitReceipt: ...   # 仅 Sculptor
    async def purge(self, s: PurgeScope) -> PurgeReceipt: ...

class GuardPort(Protocol):
    async def screen(self, r: GuardRequest) -> GuardVerdict: ...
```

依赖矩阵同 V1：`●` 必需 `○` 可选，越界 import 由 `test_import_boundary.py` 断言。
