## 三、两处方案级建议（不改你们的结论，只补漏）

### B-3 敏感字段加密：还缺三件实现级细节

1. **密钥版本**：密文要带 key version（或 key_id + 保留历史密钥），否则换一次 `PROFILE_FIELD_ENCRYPTION_KEY` 全库旧数据不可解。
2. **nonce 存储格式**：AES-GCM 的 nonce 必须与密文一起存（建议 `v1:base64(nonce||ct||tag)`）——手册只说"加 `topic_enc TEXT`"，不规定格式，实现的人会各自发明。
3. **密钥来源**：手册让写 `backend/.env`，但 `AGENTS.md` 要求密钥只经 Infisical（手册自己也写了 `.infisical.json` 不存在）。这条要先拍板，不能留给接手人现场决定。
   另：`echo.py` 有 `topic in text` 的用法（走解密后的明文）——回填顺序建议明确为「双写 → 回填 → 切读 → 删列」，并提醒别把明文打进日志。

### B-4 / B-5：G 批基准与护栏评测器是同一交付的两半

B-4 要"60–100 条真值 + 漏杀/误杀报告"，B-5 要"护栏评测器"。建议合成一个交付物：**评测器 + 20 条起步样本 + 报告**，
一个人做、一次验收；否则要么两个人各做一半，要么同一个人做两遍。
