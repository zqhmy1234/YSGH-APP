# RAG 评测体系与门禁标准（忆述光华）

> **本文件定义 A 批搜索查询真值"如何有效驱动 M1 门禁"**：真实输入分布、模态与跨模态、检索/过滤路径、分层门禁矩阵、负样本与隐私红线、待技术侧落地、benchmark corpus 来源。
> **与《真值数据规格标准_v1.md》的关系**：真值规格只定义"收什么 / 怎么收 / 为什么收"；本文件定义"收来的数据怎么评、门禁多少算过"。两者配套使用。
> **形成方式**：峰宝与北嘎霖按设计方法论铁律（先定真实输入分布，再定评测覆盖与门禁）逐层 grill-me 收敛（分支①–⑤，2026-08-25）。

---

## 0. 为什么需要独立评测体系（现状问题）

- 现有 `run_eval.py` 全跑合成 `queries_text.json`（与 `build_corpora.py` 同源 `_TEXT_SEED`）→ query 与 corpus 同源，模型在自己造的小世界里找自己造的东西，分数虚高且不可外推。
- `test_rag.py` 仅 5 条硬编码文案；`image_search_report.json` 15 条图文（旁支，image_vec 就绪后才接）。
- A/C/D 三批人类真值**均未被任何 harness 加载**（仅校验器引用）→ 真实数据零接入，评测跑在一片假数据上。
- 指标口径失真：recall 用类目全集做分母（3/20）无显式 id 则废；precision **没有检索层真负样本**→ 误召回测不出；`hit_rate@3≥70%` 这门槛是拍在合成集上的，真实集上到不到、该不该是 70% 无人知道。

**结论**：当前评测对真实输入/输出零代表性，必须按本文件重建。门禁阈值须基于真实集校准，不能拍在合成集上。corpus 来源已定（§7）：采集的 B/C/D 批即 corpus，无需生产导出。

## 1. 真实输入分布（7 层 + 占比）

| layer | 路径 | 占比 | 含义 / 说明 |
|---|---|---|---|
| descriptive | 向量（BGE-M3） | 20% | 模糊描述 / 情绪化 / 模糊指代（难例归此层难度轴，非独立层） |
| keyword | 向量 | 10% | 明确关键词（"松鼠桂鱼""复旦"） |
| typo | 向量 | 5% | 错别字 / 口语 / ASR 转写错（语音路径权重更高） |
| person | filter（NER tag） | 10% | "和妈妈有关的"（峰宝定，从 5% 升） |
| place | filter | 10% | "在复旦拍的" |
| time | filter | 10% | 时间表达（从 15% 降；相对时间占大头） |
| route | 跨模态（文→文+图+语音） | 35%（峰宝定） | 跨模态返回；image_vec 在数据采集完成前就绪，M1 即按全跨模态真值评测（不降级） |

- 语义路（向量）整体 35%、filter 路（payload）整体 30%、route 跨模态 35%（image_vec 在采集完成前就绪，M1 即全测）。合计 100%。
- `length` 层**已删除**：真实用户不按长度搜。
- 难度轴（叠加于 layer，非独立层）：`descriptive` 内难例（模糊指代+情绪化）占 30-40%（6-8 条）。

> 数据印证（调研）：Flickr 4M 个人媒体搜索日志——个人搜索 85.3% 是精确查询（人/地/物/时），印证"精确偏多、语义偏少但必不可少"。

## 2. 模态与跨模态返回

- 记忆模态占比 **文:图:语音 = 4:4:2**（团队预期）。
- 交互模型：**用户用文字搜 → 期望结果里文字+照片+语音一起出（跨模态返回）**。
- 当前 `run_eval.py` 把文/图/语音拆成独立 collection 隔离索引、只查文，**未测跨模态返回**——结构性缺口，须补。
- route 层每条查询的 `expected` 须**同时含 text_id + image_id + voice_id**（三模态关联真值）。
- image_vec 在数据采集完成前开发就绪（峰宝定 2026-08-25），故 route 层 M1 即全测三模态返回，无临时降级。

## 3. 检索 vs 过滤路径（代码 + 交付文档双重核查）

| 维度 | 路径 | 依据 |
|---|---|---|
| 时间 / 地点 / 人物 | payload **filter**（非召回路） | B2-2；`schemas/search.py` `time_from`；`vector_store.py` filter 含 place/entity |
| 模糊描述 / 情绪化 | 向量**语义检索** | 无结构化 tag，靠 BGE-M3 |
| Query 改写层 | 把自然语言解析成 filter 条件（"去年夏天"→`time_from/time_to`） | B2 架构 MVP 必做 |

→ 当前 `queries_text.json` 只有语义层、无 filter 层查询；filter 路（占 30%）未测，且须单独测"Query 改写正确率"（相对时间→filter 条件，易错点）。

## 4. 分层独立门禁矩阵（M1 当期，k=3）

| 层 | 路径 | recall@3 | precision@3 | hit_rate@3 |
|---|---|---|---|---|
| descriptive | 向量 | ≥65% | ≥60% | ≥70% |
| keyword | 向量 | ≥80% | ≥70% | ≥85% |
| typo | 向量 | ≥70% | ≥65% | ≥80% |
| person | filter | ≥90% | ≥95% | ≥95% |
| place | filter | ≥85% | ≥90% | ≥90% |
| time | filter | ≥90% | ≥95% | ≥95% |
| route（文→文+图+语音） | 跨模态 | ≥65% | ≥70% | ≥75% |

- **依据**：通用 RAG 研究（Domo recall>80%/prec>60%；Stackpractices prec>0.75/recall>0.80；skill.re prec>70%/recall>60%）。filter 层是精确匹配，命中/不命中都该很准→门槛最高；descriptive 模糊语义本就难→门槛最低。
- **远期提升**：上述门槛整体随时间提升（真实集校准后收紧；峰宝要求）。
- route 按全跨模态真值评测（image_vec 就绪前置，M1 不降级），门槛同上；后续随真实集校准收紧（远期提升，峰宝要求）。

---

## 5. 负样本与隐私红线

- **每层都要有负样本**（含 filter 层 person/place/time）——防未来结构化语义小漏洞（峰宝定）。
- 一般负样本（语义/结构本不该命中）：**误召回率 ≤ 5%**（target ≤3%）。
- 隐私排除负样本（self_talk / private，靠 `self_talk_only` 铁律）：**0% 硬红线，任一条泄漏 = 门禁阻断**。
  - 依据：`fail closed` 原则（Facebook Search 设计约束 / GDPR Art.25 / CWE-200）；私密内容出现在搜索结果即数据泄露。
- 门禁总条件：7 层 hit_rate@3 全达标 + 一般负样本误召回 ≤ 阈值 + 隐私 0。

## 7. benchmark corpus 来源（峰宝定：来自采集数据，非生产导出）

### 7.1 核心结论
**corpus（被搜记忆库）= 产品部采集的 B/C/D 批真实记忆条目**，不是另从生产库导出。
- **A 批** = 评测查询（query + `expected` 指向 content_id）
- **B 批（文字碎片）/ C 批（语音片段）/ D 批（照片事件）** = corpus 的记忆条目（text / voice / image 三模态）
- **E 批** = 纠错真值（独立用途）
→ 采集数据本身就是评测语料，A 批 `expected` 引用 B/C/D 条目的 id 即可，id 天然同空间，不必做"生产导出 ↔ 查询"的对齐。

### 7.2 采集数据如何成为 corpus（ingestion，非导出）
产品部采集的 B/C/D 条目经一步 ingestion 脚本（`scripts/build_truth_corpus.py`，待技术侧写）转成评测 corpus：
- 每条采集条目分配**稳定 content_id**（uuid）；A 批 `expected` 填的就是这个 id。
- 模态对齐：B→text 条目、C→voice 条目、D→image 条目；route 层一条查询的 `expected` 同时含三类 id（同一事件的三模态关联，由 D 批照片事件聚合串联）。
  - 模态占比须逼近 4:4:2（文:图:语音）（§2）；采集时须保证三模态条目数量都足够（检索才有意义，**每模态 ≥60 条起**，作为评测 corpus 最低规模目标）。
  - PII 处理策略见 §7.4（corpus 存独立私有 git 仓库，保留全保真字段，不再强脱敏）。

### 7.3 已拍板设计项（2026-08-25）
- **id 对齐方式（峰宝认可方案 b）**：B/C/D 模板现有 `fragment_id`/`clip_id`/`set_id`，ingestion 时**统一重映射为 uuid**（与系统 `content_id` 格式一致），并出 `corpus_manifest.json`（采集 id ↔ uuid 映射 + 模态 + 关联事件）。A 批 `expected` 引用重映射后的 uuid。
- **corpus 规模**：**每模态 ≥60 条起**（text / image / voice 各 ≥60），作为评测 corpus 最低规模目标；route 层（35%）需三模态关联真值，故 D 批照片事件须能串联同事件文/图/语音。
- **CI 取得 corpus 机制（峰宝定：独立私有 git 仓库）**：corpus 存**独立私有 git 仓库**（受限访问，非公共代码仓库），CI 经仓库访问凭证拉取后就地评测（AtD 思路，不在 CI 内嵌真实数据）。候选② 选定；① 私有 COS 桶 / ③ 本地受控卷 为备选。

### 7.4 PII 与合规（峰宝定，2026-08-25 修正）
- **保留全保真字段**（不再强脱敏）：因 corpus 存**独立私有 git 仓库**（§7.3，受限访问、非公共代码仓库），风险边界从"公开暴露"转为"受控访问"——故 **数据所有者的精确位置 / 聊天内容 / self_talk 私密语音 / geohash 均保留，不替换、不降精度**。
  - **第三方 PII 例外（峰宝定 2026-08-25）**：聊天 / 文字碎片中若提及**其他人的**姓名 / 电话 / 地址——**若能锁定到具体现实个人，必须脱敏**；**若不能锁定（泛指 / 无法对应特定人），可漏过不处理**，以保数据语义质量（过度脱敏会挖空检索相关性）。此例外仅适用于内容中提及的第三方，不适用于数据所有者本人。
  - 此条**取代**此前"PII 一律替换、脱敏到无法锁定具体个人"的强脱敏版本；取代前提 = **corpus 永不出私有仓库边界**。
  - **红线约束**：若 corpus 任何子集需离开私有仓库（对外共享 / 进公共 CI 缓存 / 第三方评测），必须重新走强脱敏（一致哈希 `user_id_hashed` + 替换数据所有者及可锁定第三方的姓名/电话/聊天原文 + geohash 降精度 + self_talk 排除）后再出。
- **仍须做的身份隔离**：`user_id` 用一致哈希（sha256 + salt）保留跨表引用完整性（对应 `user_id_hashed`），不导出明文 user id。
- 保留全保真不影响评测有效性：检索测相关性 / 模态结构，身份字段不进入向量；隐私排除负样本（self_talk 在搜索结果里"不该返回"）靠 §5 铁律在 harness 层验证，而非靠脱敏。

## 8. 调研依据（benchmark corpus 来源，2026-08-25）

- **生产日志是评测集金标准**（mljourney / unrag / gigagpu 一致）：真实用户 query 比手写 / 合成更脏、更覆盖长尾；"500 条精心抽样 + 标注的生产样例 > 5000 条雷同手写"。
- **分层抽样而非随机**：用句向量聚类，大簇按比例、小簇（长尾 / 难例）过采样（mljourney）。
- **PII 去标识**：一致哈希（sha256 + salt）保留跨表引用完整性（securetoolsguide）——对应我们 `user_id_hashed` 做法；伪匿名在 GDPR 下仍属个人数据，需访问控制。
- **个人记忆基准（ATM-Bench / "According to Me", 2026）**：真实个人记忆数据需明示同意 + PII 替换 + 大量人工审计；**关键警示——LLM agent 自动标注生成的 query 偏"分析性"而非"人类回忆性"，不反映真实回忆行为** → 印证我们"人工采集 A 批"路线正确，不能靠 LLM 自动造 query。
- **个人数据评测范式（Hopfgartner 等）**：个人数据不宜以 DtA（数据下发）测试集发布（隐私 / 治理），宜用 AtD（算法到数据）——评测就地跑在用户脱敏数据上。
- 本项目结论：corpus 由采集的 B/C/D 批构成（AtD 思路），A 批 query 与 corpus 同源于采集动作，id 天然对齐。
