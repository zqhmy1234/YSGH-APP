### 1.2 关键缺口（按用户痛点排序）

1. **process_content AI 管线未实现**（worker.py 占位）：照片/语音/文字入库后 status 永远 processing，
   转写、分类、图片 caption、事件聚合全部未接线。这是"图片塔上传失败"的直接上下文——
   不是失败后没兜底，是整条 AI 管线还没做。
2. **外部 API 调用无统一重试**（AGENTS.md 已记录教训）：批量 caption 121 张 ConnectionError（10053）。
   现状 dashscope.py 各函数直接调用，单点失败即降级/失败。需要统一：指数退避重试（3 次）+ 超时控制 + 熔断。
3. **队列任务无重试策略**：worker retry_job 存在但 process_content 未用它；RQ 任务失败无 dead-letter 观察。
4. **前端降级体验无契约**：degraded=True / errors 字段未定义前端展示规范（API 层无错误码映射）。
5. **重试与幂等**：图片 caption 重试需幂等（同一内容重复处理不重复计费/不重复写）；现状无 op_id 去重在管线内。

### 1.3 建议（待用户拍板）

- P0：实现 process_content 管线骨架（转写→分类→caption→事件聚合→回写 done），每步独立 try/except + 重试 + 失败标记（status=failed + error 字段），前端可展示"处理失败可重试"
- P0：dashscope.py 统一外部调用封装（超时 + 指数退避重试 3 次 + 连接池）
- P1：API 降级契约（degraded/errors 字段规范 + 前端空状态引导）
- P1：管线幂等（per-content 处理锁 + 幂等键）

## 二、C 盘 HF 缓存清理（bge-m3 三处 6GB 真相）

### 2.1 结论：可以删，删后释放约 3.8GB（保留 2.2GB 在用）

| 路径 | 大小 | 性质 | 处理 |
|---|---|---|---|
| `snapshots/5617a9f61b028005a4858fdac845db406aefb181/` | 2.2GB | **当前在用**（refs/main → 5617a9f6）pytorch_model.bin 格式 | **保留** |
| `snapshots/9a0624b896d81da7492a910ffa53731274b6cf3d/` | 2.2GB | **旧版本残留**（model.safetensors 格式，refs 未指向） | **可删**（删前确认无代码引用） |
| `blobs/1eebfb28493f...incomplete` | 1.65GB | **下载中断残留**（.incomplete 后缀） | **可删** |
| `blobs/5008ddfcf53c...incomplete` | 0MB | 中断残留空文件 | 可删 |

### 2.2 为什么有三处？（根因）

1. `blobs/` 是 HF hub 的**内容寻址存储**（所有版本共享），`snapshots/` 是**版本快照**。
   正常 Linux 下 snapshots 是指向 blobs 的符号链接；**Windows 上 HF hub 检测到无符号链接权限时回退为实体复制**——snapshot 是实体文件，blobs 里又有下载缓存，造成双份。
2. 两个 snapshot = 两次不同 commit 的下载（pytorch_model.bin 版 + model.safetensors 版）。
   原因：sentence-transformers 不同版本/加载路径会优先拉不同格式（旧版 pytorch_model.bin，新版 model.safetensors），
   两次下载各生成一个 snapshot；`.incomplete` 是某次中断留下的（可能就是之前 10053 网络错误）。
3. **重复下载已发生**：约 3.8GB 冗余（旧 snapshot 2.2GB + incomplete 1.6GB）。

### 2.3 模型下载记录现状（缺口）

- embedding.py 有注释（HF_HUB_OFFLINE=1 离线加载、模型路径），AGENTS.md 有"hf-mirror/modelscope 可达"条目
- **缺**：统一的"模型资产清单"（模型名/版本 hash/下载源/磁盘位置/加载方式/可删性）——新 Agent 无法快速判断哪个能用哪个能删
- **缺**：下载去重（未记录已下载的 commit/格式，导致 safetensors 版重复下载）
- 建议：写 `docs/模型资产清单.md`（或 backend/models/README.md），登记全部本地模型（bge-m3 / bge-reranker-base / bge-reranker-v2-m3 / setfit-classifier / bert-base-uncased / grounding-dino / Qwen2.5），含大小、用途、下载源、加载代码位置、清理建议；并在 embedding.py/rerank.py 顶部指向该清单

### 2.4 加载方式正确性

- embedding.py：`SentenceTransformer(MODEL_NAME, model_kwargs={"torch_dtype": torch.float16})` + `HF_HUB_OFFLINE=1` + `local_files_only=True`（sparse_linear）——**正确**（离线优先防 HEAD 超时，fp16 省内存）
- rerank.py：`CrossEncoder(str(model_path), max_length=512)` 读 backend/models/bge-reranker-base——**正确**
- 注意：CI 需 `HF_HUB_OFFLINE=0`（ci.yml 已处理）✅
