## 0. 这次到底改什么

### 0.1 目标形态



```
外部消费者（不在分层里）
  ├─ 客户端 uni-app x        JWT
  ├─ 微信/企微              验签
  └─ Agent 进程（L4 Harness） X-Agent-Token
        │
        ▼
L5 统一 API 网关（APISIX，复用成熟项目）
        │
        ▼
L3 适配器层（backend/app/api，一入口一文件）
        │ 只调端口
        ▼
L2 端口层（backend/app/ports，Protocol）
        │
        ▼
L1 域内核（backend/app/domain，纯策略）
        │
        ▼
L0 基础设施（backend/app/infra：PG/Qdrant/COS/Redis/LLM/ASR/微信）
```

Agent 是外部消费者，不是 backend 的一层。它只经 L3 端点读写，不持 Qdrant/COS 凭据，不直连业务表。它自己的 checkpointer、memory ledger 放自己的 schema，属于执行态 / Agent 资产，不属于 backend 业务表。

### 0.2 目录重构目标



```
GHapp/
  shared/
    contracts/              # 跨进程 DTO，无业务逻辑
    openapi/                # 生成的 OpenAPI JSON，给 Agent 做契约
  backend/
    app/
      api/                  # L3 适配器（原 api 文件原地重构）
      ports/                # L2 Protocol
      domain/               # L1 纯策略（由 services 拆出）
      infra/                # L0 适配器（PG/Qdrant/COS/LLM/ASR/微信）
      workers/              # RQ 任务
      main.py               # 装配
    migrations/
  agent/
    src/
      main.py               # 新 Agent 服务入口（8400 本地 / 8300 staging）
      harness/              # L4：orchestrator/plan/context/registry/effects
      agents/               # 五 Agent
      ports/                # Agent 外部端口
      adapters/             # backend HTTP / LiteLLM / checkpointer
      prompts/              # RoleCard / assembler
      memory/               # ledger / projection / policy
      api/                  # Agent HTTP
      jobs/                 # 夜间整理
      judge/                # 审判 Agent
      platform/             # 从旧 yishu 移入的 security/logging/degradation
    assets/
      cards/                # 12 张初始角色卡
    tests/
  client/                   # 保留；L6 三端搁置
  deploy/
    apisix/                 # L5 网关配置
    systemd/                # 新旧服务单元
    litellm-gateway/        # 已有模型网关
  archive/
    legacy-agent-v1/        # 旧 Agent 整包冻结
    legacy-backend-services/# 旧 services 逐步退役
  docs/
    adr/
    架构图/current/
    legacy-retirement.md
    background-index.md
```

### 0.3 硬规则



1. 一个模块只有一个家；`archive/` 不参与 import，不跑测试。

2. 新 Agent 不 import `backend` 代码；backend 不 import `agent`。跨进程只走 HTTP + `shared/contracts`。

3. L3 只调 L2；L2 只调 L1；L1 只依赖标准库与 L0 抽象。禁止 L3 直接调 SQLAlchemy。

4. Agent 不直连 backend 业务表；只调 L3 的 `/api/v1/.../agent` 端点。

5. 旧代码不再 “边改边长”；要么原地保留并标注 `IN-PLACE`，要么整包归档。

6. 任何模块改动必须在任务卡里写清 “背景文档 + 章节”，否则审判直接 FAIL。

## 3. L2 端口全量设计

### 3.1 双端端口



* **backend L2**：`backend/app/ports/`，给 L3/L1 用，协议 + DTO 在 `shared/contracts`。

* **agent 外部端口**：`agent/src/ports/`，只给 Agent 调 backend/LiteLLM/checkpointer 用。

Agent 不 import backend ports；backend 不 import agent ports。两边只共享 `shared/contracts` DTO。

### 3.3 agent 外部端口

`LLMPort`、`BackendPort`、`CheckpointPort`、`ClockPort`、`TracePort`。`BackendPort` 只映射 backend L3 端点：



```
POST /api/v1/search/agent
```

### 3.4 端口硬规则



1. 失败至少三态；`hits=[]` 不允许同时表示 “没匹配 / 没索引 / 系统挂”。

2. 写端口必须带 `idempotency_key`；重复键返回上次 receipt。

3. 端口实现只能在 `infra/` 或 `adapters/`；`domain/` 不得 import SQLAlchemy/Qdrant/httpx。

4. 每个端口一份 contract test + 3 个负向探针（跨用户、越权、伪造 id）。

5. `tests/test_import_boundary.py` 用 AST 检查依赖方向，不靠 grep。

## 10. 多 Agent + 审判 Agent 开发流程

### 10.1 角色



| 角色              | 职责                     | 权限                           |
| --------------- | ---------------------- | ---------------------------- |
| `architect`     | ADR、contracts、任务卡、接口裁决 | 改计划 / 契约；不写业务代码              |
| `implementer-*` | 一个垂直切片                 | 只改 `allowed_paths`；不改契约 / 测试 |
| `judge`         | 独立测试、变异、负向、拒绝合入        | 可写测试 / 报告；**不改生产代码**         |
| `integrator`    | 合并、全量回归、staging        | 可合并；不改业务逻辑                   |
| `auditor`       | Current 图核实            | 只读                           |

### 10.2 任务卡（必须带背景）



```
id: AGENT-CTX-01
goal: 实现单一 ContextAssembler（9 段帧）
background:
  summary: 现有 frame/bundle 两套 4200 预算，角色卡未进 Orchestrator
  docs:
    - docs/架构扩展_三合一陪伴智能体V2_45需求映射.md#4.4-上下文帧
    - docs/agent-v3/prompt-and-cards.md#10-段-bundle
    - docs/agent-v3/五Agent内环说明.md#0-外层
  decisions: [ADR-003]
allowed_paths:
  - agent/src/harness/context.py
  - agent/src/harness/contracts.py
  - agent/tests/harness/test_context.py
forbidden_paths: [backend/, agent/src/agents/]
acceptance:
  - 9 段顺序/预算/裁剪测试通过
  - 卡片 system_prompt/lore 注入测试通过
  - 保护段不被裁
evidence: [pytest.log, coverage.json, judge-report.json]
```

**背景门禁**：`background.docs` 缺失、路径不存在、章节不存在、与 `allowed_paths` 不匹配 → judge 直接 `FAIL: missing_background`。

### 10.3 流程



```
architect 写 ADR + 任务卡 + background
→ contract freeze（DTO/端口/错误码）
→ implementer 独立 worktree 实现
→ 自测（单测/契约/类型/格式）
→ judge 独立审判（读 diff，不读解释）
→ PASS → integrator 合并一个任务
→ 全量回归 + staging smoke + replay
→ FAIL → 回 implementer（最多 2 轮）→ architect 拆任务
```

### 10.4 审判硬规则



* 每任务至少 3 个变异体、5 个负向探针、1 个 property/replay。

* 实现者不得改测试变绿；测试 diff 由 judge 出。

* FAIL 必须给 `issue_code`、最小复现、期望 / 实际、文件行。

* PASS 必须给覆盖矩阵 + 未覆盖风险。

* 共享契约只由 architect 改；实现者只能提 ADR。

### 10.5 并行

contract freeze 后才并行；`allowed_paths` 不相交；每天最多 3 个 implementer；独立 worktree；集成用 fake ports。

### 16.1 B5 记忆域：先定“唯一真源”，再谈四层

* 四层是**读模型分区**，不是四张重复表：
  * ① 叙事记忆 → `memory_entries`（独立账本）；

  * ④ 偏好与修正 → `correction_log` + `user_ai_persona` + `profile_sensitive` + `echo_exclusion`。
