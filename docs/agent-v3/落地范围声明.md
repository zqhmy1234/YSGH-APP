## 部分落地（接口与域逻辑到位，生产依赖待接）

- **PG 生产存储**：领域账本是纯对象（`MemoryStore`），本地落盘由 `SqliteMemoryStore` 承担；
  PG 表迁移已随本轮落地（5 张新表），PG 适配器仍需实现同样的 `dump_state/load_state` 语义（尚未接 psycopg）。
- **真实检索/事件**：`BackendSearch`/`BackendEvents` 是 HTTP 客户端骨架，指向
  `SEARCH_BASE_URL`/`EVENT_BASE_URL`；未配置时抛 `PortUnavailable`（诚实降级），
  尚未联调后端 `/internal/rag/search` 的真实响应。
- **真实 LLM**：`BackendLLM` 走 OpenAI 兼容 `/chat/completions`；未配置时同样诚实失败。

## 明确未落地（不在本轮切口，避免假装完成）

- 夜间调度器的 *部署触发*（cron/systemd timer）：`jobs/nightly.py` 已可运行且幂等，但定时器本身属运维配置，未写入仓库。
- 后端既有表的视图兼容与 RLS 策略：本轮只加 5 张 agent-v3 新表，未动既有 32 张表的结构与权限。
- 客户端（uni-app x）与微信客服链路：与 Agent 域解耦，未触碰。
- 情绪三层、图片塔、语音通道：端口未定义，保持架构留白而不是空实现（45 矩阵中对应 #2/#9/#39）。
- 人脸/成长线/分享/导出/保险箱：属端侧或二期，45 矩阵中标 ❌，不由本包冒充。

## 与旧 `agent/src`（develop 上 7839 行）的关系

- 旧实现是「LangGraph 单 Agent + 13 个工具」；新实现把「说话/检索/校验/写入」拆成五个职责单一的角色。
- 旧代码未删除、未 shim，两条路径互不 import；切换点只在部署层选择挂 `/v1/chat` 还是 `/v1/v3/turn`。
- 复用而非重写：`output_validator` 的「非法回复降级」思想、`degradation` 计数、`redact` 脱敏，
  以更小的形态进入 `obs.py` 与 `muse.validate_reply`；不再复制 903 行单文件。
