## 1. 生产变量模板

**⚠️ 变更（v1.0 → v2.0）：模板不再内嵌于本文，改为落 `deploy/.env.production.template`（单一真源）。**
理由：同一份 120+ 行模板存在两处（文档 + 文件）必然漂移；且 compose 与 systemd 都要读它，落成真实文件才能被 `docker compose` 与 `EnvironmentFile` 直接消费。

相对 v1.0 的**新增/变更项**（逐条给出为什么）：

| 变量 | 变更 | 理由 |
|---|---|---|
| `POSTGRES_USER/PASSWORD/DB/PORT`、`REDIS_PORT`、`QDRANT_*_PORT`、`API_PORT` | 🆕 容器参数节 | compose 依赖这些插值；`deploy/.env` 同时服务容器与宿主进程（契约见 `deploy/README.md` §3） |
| `PORT=8010`（原 8000） | ⚠️变更 | 与客户端 `config.uts` 的 `getBaseUrl()`（写死 8010）对齐，避免端口漂移；8010 的由来见 `config.uts:8-11` |
| `MEDIA_URL_SECRET` | 🆕 必填 | 媒体票据（Valet Key）签名密钥，**独立于 JWT**；留空会回退 `jwt_secret`（削弱泄漏面隔离）。v1.0 漏项 |
| `MEDIA_THUMB_TTL` / `MEDIA_ORIGINAL_TTL` | 🆕 | 双 TTL（缩略图 24h / 原图 15m） |
| `ALLOW_DEVICE_LOGIN=true` | 🆕 | 内测期设备码登录通道（20 人零 UI 改动的前提）；**上架前必须置回 false**（决策台账 §1.13） |
| `RATE_LIMIT_ENABLED/TRUST_PROXY/WHITELIST` | 🆕 | v1.0 只写了 `TRUST_PROXY`；直连必须 `false`，否则 `X-Forwarded-For` 可伪造导致限流失效 |
| 三个依赖服务连接串 | ⚠️变更 | 单机形态下宿主侧一律 `127.0.0.1`；容器内后端（`profile=app`）才用服务名 |
| `SENSEVOICE_MODEL_DIR` | ⚠️变更（保持必填） | 必须指向 `deploy/scripts/pull_models.sh` 预置后的目录，否则首个请求联网下载（国内网络会卡死） |
| 必填项**保持注释状态** | 🆕 约定 | `config.py` 生产兜底拦「默认字符串」但**拦不住空串**——写 `KEY=` 会让服务带空密钥启动；保持注释才能 fail-closed |

**自证对齐**：模板末尾附一条比对命令（模板键集 vs `Settings.model_fields`），改 `config.py` 字段后跑一次，输出为空即对齐。

## 2. 部署检查清单（逐项勾选）

> 每项含「如何验证」；全部 ✅ 后方可对外发布。密钥项仅经 Infisical 校验，不写明文。
