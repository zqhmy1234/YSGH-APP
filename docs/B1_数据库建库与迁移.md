# B-1 数据库建库与迁移

## 当前入口

ORM 模型（`backend/app/db/models/`）是新库 schema 的唯一权威。空数据库运行：

```powershell
. .\infra\activate.ps1
python -m alembic -c backend/alembic.ini upgrade head
python -m alembic -c backend/alembic.ini check
```

`alembic upgrade head` 仅在 public schema **完全没有表**时，从 ORM metadata 建当前结构并登记 head。历史首迁移 `431bcaa8bd54` 没有改写；它假定旧核心表已存在，直接在空库执行会报 `contents` 不存在。此空库分支解决该矛盾，不应把它描述为“首迁移已自包含”。

已有带 `alembic_version` 的库仍按迁移链增量升级；B-1 新迁移 `e1b1c1d1e1f1` 幂等补建 `profile_l2_evidence`、`finetune_jobs` 并补数据库默认值，保留原有数据和旧表。**非空但没有版本记录**的库会停止，须先人工核对来源和版本，不能盲目 `stamp head`。不要对已有库执行 `--reset`、重建或清表。

`scripts/init_db.py` 现在只准备角色、数据库与 vector 扩展，再调用 Alembic；部署与 CI 仍可使用这一封装。它不再从 `schema.sql` 抽取裸 SQL 表。`backend/sql/schema.sql` 是历史参考，不能用于新库建库。

## 验证

- `alembic current` 应为 `e1b1c1d1e1f1`；`alembic check` 应报 `No new upgrade operations detected`。
- `scripts/check_schema_drift.py` 在两座随机命名的临时库分别执行 ORM `create_all` 和空库 Alembic 升级，比对表、列、默认值、主键、唯一约束、索引及外键；无 BLOCKING 才返回 0。需管理员连接串，命令行或 `DRIFT_ADMIN_URL` 注入，勿把凭证写入仓库。
- 现有库迁移前后须核对业务表行数；迁移失败时先保留现场，不做 `stamp head` 绕过。

## 保留与退休的表

现有业务读写 `profile_l2_evidence` 与 `finetune_jobs`，两表已补 ORM。其余 11 张旧表退出新库 schema；已有库中的旧表和数据不自动删除。逐表结论见 `docs/决策台账.md` §18。

## 2026-10-12 工作结果与未完成项

**已实现**：给两张仍在用的表补 ORM；为原 ORM 缺失的 34 个数据库默认值补 `server_default` 与增量迁移；空库 `alembic upgrade head` 改由 ORM 建当前结构并登记 head；`init_db.py` 停止抽取 `schema.sql` 和维护 `NON_ORM_TABLES`；定时漂移检查改为 ORM 与空库 Alembic 结果对比；CI、部署入口已接到上述建库方式。其余 11 张表已退出新库的 `schema.sql` 参考定义，旧库不自动删表。

**已验证**：空库升级至 `e1b1c1d1e1f1`，随后 `alembic check` 无新增操作；隔离漂移检查为 ORM 32 表 / Alembic 32 表、BLOCKING 0 / INFO 0；`schema.sql` 所有保留表的 DDL 默认值在 ORM 中均有 `server_default`（缺失 0）；隔离库从已有 `d9a0b1c2d3e4` 版本升级后，用户与旧 `audit_log` 哨兵行保留，目标两表存在；针对 `contents.sensitive_status` 默认值的回归用例 1 passed，测试收集 991 项，快速审核通过。

**尚未完成及原因**：

- 非空且没有 `alembic_version` 的旧库现在会安全停止，不能自动迁移；没有在真实存量库上执行升级。现有数据保留的实测只覆盖从 `d9a0b1c2d3e4` 升级的隔离库，不能外推为所有历史状态均已验证。
- 任务书建议从 ORM 生成一份自包含初始迁移；本实现选择在 `env.py` 对真正空库 `create_all` 后登记 head。它满足空库建库结果，但不是该建议的字面实现。历史首迁移未被改写。
- 任务书指定回写的两份旧新人文档位于当前仓库不存在的 `技术文档/` 路径；本机副本在 Git 忽略的 `infra/docs/`。因此新增本文件作为可跟踪的建库说明，旧副本未修改。
- 仓库全量审核未通过：标准 600 秒、用户要求的单次 1200 秒重试均在主 pytest 段超时；后者 API 冒烟中搜索、照片、时间轴 3 项失败（缺 BGE-M3 缓存与测试照片等环境资产，SetFit 依赖也缺失），研究验证通过。Ruff 0.17 在 61 个本次未改文件中报 151 条 UP017。详情见 `progress.md` 2026-10-12 条及 `.cowork-temp/test-report.json`。因此 `feature_list.json` 保持 `in-progress`，不得称全量验收通过。
- 本机没有 WSL 发行版，`bash ./init.sh` 无法启动；已做 PowerShell 等价 harness 文件检查。部署容器启动链和真实存量库升级尚未端到端实测。
