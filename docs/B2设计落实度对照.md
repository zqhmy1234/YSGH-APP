## 一、当前实际代码处理流程（rag.py search()）

```
查询 SearchQuery{q, content_types?, time_from/to?, place?, tag?}
 │
 ├─ 1. Query 改写 _rewrite_query()
 │    规则时间解析（去年/今年/上个月/昨天 → time_from/to 过滤条件）
 │    → LLM 改写 rewrite_query()（qwen-flash，百炼可用时真实调用；失败/未配置走规则结果）
 │    → 显式过滤条件合并（content_types/time/place/tag）
 │
 ├─ 2. 路由 _route_query()
 │    LLM route_query()（image/text/mixed，真实百炼可用时生效）
 │    规则词表兜底（照片/图片/拍的/截图/壁纸/合照… → image）
 │    → intent=image 时强制 content_types=["image"]（B2：路由决定检索范围）
 │
 ├─ 3. 编码+召回 vector_store.search()
 │    BGE-M3 encode_query（dense + sparse_linear 手动稀疏）
 │    Qdrant named vectors 双路并行召回 → RRF 融合（0.7/0.3, k=60, limit 50）
 │    payload filter：content_types/time_from/time_to/place/tag（过滤层，非召回路）
 │
 ├─ 4. 溯源组装（RET-016）
 │    content_id → contents 表回填真实文本/类型（按用户隔离）
 │    trace：dense_score/sparse_score/rrf + matched 来源标注
 │
 ├─ 4.5 双层 Rerank 第一层（WP-F）
 │    bge-reranker 粗排（本地 CrossEncoder，模型就绪自动启用，min_score 可配）
 │    候选无 text / 模型未就绪 → RRF 原序保底
 │
 └─ 返回 SearchResult{query, rewritten_query, intent, hits, latency_ms, degraded}
```
