# Phase A 逐功能域深度审计 · 共享简报（所有域 agent 必读）

> 波次：易扩展/易维护重构波 · **Phase A 只读筛查**。本文件是各域审计 agent 的统一纪律与输出契约。

## 铁律（违反即失败）

- **只读业务代码，禁止修改任何业务文件**。唯一允许写的文件是本域的报告文件。
- 本波性质是**严格行为等价**：发现的缺陷**只登记、不修**。
- 范围：`backend/app/` + `client/` + `scripts/` + `deploy/`。**`agent/` 目录明确排除**（不审计它）。
- 项目根：`d:\GuangH-App`。先读 `AGENTS.md`；用 `git status --short` 核实并记录当前在途文件。
- **排除浅层统计**：不得只报行数 / grep 计数就下结论。必须**实读代码**。

## 深度判据（每条都必须给结论）

1. **真实重复逻辑**：同语义多实现。给出两个具体位置（文件:行）并解释为何是同语义。
2. **死码 / 零调用导出**：必须用 Grep 证明（给出搜索式与结果）。
3. **边界与依赖方向**：跨层反向依赖（如 services 反向 import api、core import services）。逐条列实际 import 边。
4. **注册表 / 端口抽象覆盖度**：新增一类实体/渠道/类型需改哪几处？**把需要改的注册点全部列出**（文件:行）。
5. **可扩展性缺口**：if/elif 链、硬编码枚举、魔法字符串、复制粘贴式新增范式。
6. **异常 / 事务 / 软删口径一致性**：软删过滤、事务边界、错误码处理、幂等是否统一。

报告写入：`.trae/specs/refactor-extensibility-maintainability-wave/audit/domain-NN-<slug>.md`

| DNN-1 | `path:line` | 巨文件/重复/死码/边界/声明漂移/门禁缺口 | P0/P1/P2 | … | … | … | … | … | 确认/候审 |

## 口径定义

- **状态**：有直接代码证据 = `确认`；启发式推测、需人工确认 = `候审`。
- **严重度**：P0=阻碍改动/易致事故；P1=明确结构债；P2=顺手可清。
- **可回滚性**枚举：`纯移动+兼容再导出` / `行为等价替换` / `新增工具` / `删码(需证死)`。
- **证据纪律**：每条须可复现（给命令或 文件:行）。**禁止臆断、禁止编造行号**。

## 返回给主 agent 的内容

写完报告后，**只回 ≤200 字摘要**：条目总数、P0/P1/P2 分布、最严重的 3 条（一行一条）、以及未能覆盖的部分。**不要**把报告全文回传。
