# 令牌波（Design Token Convergence）· 方案（spec）· 2026-09-25

> **性质（用户 2026-09-25 拍板）**：**方案文档先行** —— 本文件是**讨论载体**，未拍板前**不动任何样式/令牌代码**。
> **判据纪律**：本文件每条结论都附**可复现证据**（命令或文件:行）；无证据的一律进「未验证项」。引"文档说已实现"不作为证据。
> **范围**：`client/`（uni-app x **App-Android 单端**）。**不含**：小程序/Web、dark mode（见 §7）。

## 0. 一句话

把 32 个内联 `<style>` + 6 个外置 css（合计 **7400 行**）里的 **~960 个颜色位点**与尺寸/字号/间距，收敛到 `client/design_tokens.json` **单一真源**，使令牌机制覆盖率从 **0%（实测）** 提升到**可门禁**，并保证**像素级视觉零差异**。

### 1.1 五个结构性差异（决定方案的关键，比"数字大小"重要）

1. **尺寸存在"两套基准并存"（原判"换算规则未知"已更正 · 2026-09-25）**：上一版本文件曾把 `design_tokens.json.dimensions`（390 画布 px）与代码 rpx 判为"人手写的、不同源"——**实测推翻**：
   - **换算规则已坐实**：`rpx = 画布px × 750/390(=1.9231)`，**保留 1 位小数**（与 `about.uvue` 注释里写明的 `SCALE=750/390=1.9231` 一致）。
   - **72.0% 的尺寸位点（1988 处 / 130 种）精确落在画布 px 整数格上**：`23.1rpx`=12px、`38.5`=20px、`26.9`=14px、`15.4`=8px、`30.8`=16px、`11.5`=6px、`7.7`=4px、`5.8`=3px、`1.9`=1px、`19.2`=10px、`21.2`=11px、`3.8`=2px、`28.8`=15px、`46.2`=24px、`115.4`=60px、`673.1`=350px、`750`=390px …（**全部为 px×1.9231 后 1 位舍入**）
   - **28.0%（774 处 / 98 种）是"rpx 原生整数"**，**不在**画布格上：`24rpx`(≈12.48px)×78、`20rpx`(≈10.40px)×54、`16rpx`(≈8.32px)×45、`32rpx`×40、`40rpx`×35、`12rpx`×34、`28rpx`×29 …
   ⇒ **这是"两套基准并存"，不是"没基准"**。由此产生本波**必须拍板的尺寸面取舍**（见 §7 第 7 项）：**保留两族**（零像素变动）还是**统一到画布格**（会改动 774 处、`24rpx→23.1rpx` 等，需目视验收）。
2. **令牌集覆盖不足**：52 个值 vs 颜色位点 962 个 —— 尤其 **`rgb()/rgba()` 190 处与 10 处渐变在令牌集里完全没有建模**（透明色阶、渐变、阴影全缺）。
3. **语义层级缺失**：现有 tokens 是"用途/色相混写"的**单层**（`bg_page`/`bg_card`/`accent_rust`/`accent_amber`…），没有 DTCG 那套 `原始色阶 → 语义别名` 两层 ⇒ **语义 token 无法表达**（例：`color.text.primary` → `{color.neutral.900}`）。
4. **19 处 `:style=` 动态绑定**：颜色/尺寸是运行时拼进 template 的（如进度条 `width: (p*100)+'%'`、`idle-color="#C4913C"`）⇒ 静态 CSS 替换覆盖不到，需**单独一簇**处理。
5. **`effects.card_shadow` 不是合法 CSS**：值形如 `"0 4 16 #00000008"`（空格分隔 + 8 位 hex alpha）⇒ 需转换器产出合法 ucss 阴影。

**写法不归一**：`0.10` 与 `0.1` 并存、`0.067`/`0.078` 等非常规档位。

**渐变 10 种（更正 · 2026-09-25）**：早先版本记的"9 处遮罩 + 1 处实色渐"是**半截字符串**造成的误述——原提取正则 `linear-gradient\([^)]*\)` 在 `rgba(...)` 的**内层括号**处截断。改用**括号配平提取**后，真实形态是 **10 个「两色对」**（各 ×1）：
`to bottom` 六条（ink 0.45→0.15 / paper 0→0.6 / paper 0.6→1 / paper 0→#f8f7f4 / ink 0.15→0 / inks 0.5→0、green 0.6→0.12）、`to bottom right` **两条跨色相对角**（olive 0.3→**amber** 0.2 / slate 0.28→**olive** 0.15）、实色暖渐 `#E3CCA8→#C7AD87` 一条。

**近重复漂移（收敛时会被归并 ⇒ 视觉等效、字节不等）**：`#3a2e25`/`#3b2e26`、`#b3a696`/`#b2a696`、`#b05a3a`/`#b0593b`/`#af5a39`/`#aa5334`、`rgba(59,46,38,α)`/`rgba(58,46,37,α)`、`rgba(176,89,59,α)`/`rgba(176,90,58,α)`、`0.10`/`0.1` …

> ⚠️ **由本节得出的最重要口径结论（须先认下再动 P3）**：令牌化**必然归并上述漂移** ⇒ 结果是 **「像素/视觉等效」而非「字节等值」**。因此 **静态门禁只能证"结构正确"，"是否视觉零差异"只能靠真机目视** —— 这也解释了为什么 §5 把目视列为**不可省略**的一条（而非"锦上添花"），以及为什么 P3 在无设备时**只能做到"编译 + 产物取证"**。

| `border-radius` | 55 / 214 | `38.5`×29、`23.1`×21、`30.8`×13、`2`×12、`24`×10、`9999`×7、`15.4`×7、`16`×7、`32`×7 … |

**效果**：`box-shadow` 去重 **41 种 / 77 处**（**无一种进了令牌集**：现存 token 只有 `card_shadow:"0 4 16 #00000008"` 一条且格式非法）；高频三条＝`0rpx 5.8rpx 23.1rpx rgba(59,46,38,0.05)`×11、`0rpx 7.7rpx 30.8rpx rgba(59,46,38,0.06), 0rpx 1.9rpx 5.8rpx rgba(59,46,38,0.04)`×9、`0 6rpx 16rpx rgba(58,46,37,0.05)`×4；`opacity` 去重 8/9；`z-index` 去重 9/36（`1`×12、`1000`×7、`10`×6、`20`×6、`999`、`1001`…）；`transform` 仅 `rotate(-45deg)`×1。

> **尺寸面的口径结论**：与颜色面不同，尺寸面的"漂移"是**跨基准**而非"同值近邻" ⇒ 归一会**真的移动像素**（`24rpx→23.1rpx` ≈ 0.9rpx ≈ 0.5 设备像素）。因此 **P1/P3 对尺寸面只建令牌、不擅自跨基归一**（保守默认，见 §7 第 7 项）；归一若要，须单独批次 + 目视。

### 2.1 未验证项（V1–V3，**本方案的成败全在这里**）

- **V1 · 变量作用域**：在"样式不继承"（#5）的前提下，变量随 class/inline style 挂到元素后，**后代元素的 `var()` 能否解析**？还是**只在同一样式块内可见**？
- **V2 · 跨文件可见性**：外置 `.css`（经 `@import`）内的 `var()` 能否解析到 `app.uvue` 全局 class 里声明的变量？
- **V3 · `@media (prefers-color-scheme)` + 变量覆盖**在本仓 HBuilderX 版本是否可用（决定"是否给暗色留门"）。

> 为什么必须实测：**编译不报错 ≠ 变量生效**（本波已有同类实锤——GAP-1/样式外置都出现过"编译绿但实际不生效"）。且这类失败的表现是**视觉塌陷/回退默认值**，静态门禁抓不到，只能靠探针 + 产物 bytes + **目视**。

### 2.2 探针实测结果（V1/V2 **已跑** · 2026-09-25）

**做法**：`App.uvue` 全局 `<style>` 加 `.probe-tok{--probe-color:#123456}`；`pages/about/about.uvue` 模板插「后代元素 + 同元素带 `.probe-tok`」两个节点、其 `<style>` 加 `.probe-child{color:var(--probe-color)}`/`.probe-same{color:var(--probe-color)}`；`styles/tab-index.css`（**外置 css**）追加 `.probe-ext{color:var(--probe-color)}` 并把 `probe-ext` 挂到 `TabIndex` 根节点 ⇒ **一次冷编译** ⇒ 扫**全部** `*.style.bytes` ⇒ **字节级还原**（4 个探针文件与备份全等、`git status` 干净）。

| 结论 | 证据 |
|---|---|
| ✅ **编译成功**（ucss 接受 `var()` 与自定义属性声明） | `项目 client 编译成功` |
| ✅ **声明被编进 App 级产物** | `GenAppSharedData.style.bytes`（基线 125 字节）在探针期间含 **`#123456`** |
| ✅ **使用侧原样透传（编译期不内联）** | `GenPagesAboutAboutSharedData.style.bytes` 含 `var(--probe-color)` + `probe-child`/`probe-same` |
| ✅ **跨文件（外置 css 经 `@import`）同样透传、不报错不丢弃** | `GenComponentsTabIndexTabIndexSharedData.style.bytes` 含 `var(--probe-color)` + `probe-ext` |
| ❓ **运行时能否取到值：无设备不可判** | 编译器只做透传，值解析在**原生样式引擎**；风险仍集中在「样式不继承」（本仓实锤）。缓解依据：官方《暗黑主题适配》示范形态**正是**「`app.uvue` 全局 class 声明 + 页面使用」＝本例 V1/V2 |

> **判定**：**V1/V2 的"链路与产物"侧已证**；"运行期像素级取值"侧**仍需真机** ⇒ **方案 A 具备可行性依据**，但其最终验收**是设备阻塞项**（P2/P3 目视挂账）。
> **V3（`@media`）未跑** —— dark 不在本波，留待需要时一次探针即可（探针方法同上）。

## 3. 方案候选与对比

| 方案 | 做法 | 改动面 | 换肤能力 | 回滚粒度 | 前置依赖 | 风险 |
|---|---|---|---|---|---|---|
| **A** 全局 class 变量 + `var()` | `app.uvue` 定义 `.theme-light{--…}`，各文件把字面量改 `var(--…)` | 小（逐值替换） | ✅ 有 | 逐文件 | V1/V2 必须成立 | 变量不解析=整页视觉塌陷，编译不报错 |
| **B** 构建期令牌编译 | 脚本（DTCG 源 → 生成字面量）替换 ucss 里的值 | 中（需生成链 + 纳入门禁） | ❌ 无（静态） | 全量（重跑生成） | 无（不依赖平台） | 与"人工抄写"的 diff 巨大；失去运行时换肤 |
| **C** 混合 | 颜色/尺寸走 A；19 处 `:style=` 走 `styles/tokens.uts` 常量；tabbar/nav 走 `theme.json` | 中 | 部分 | 分簇 | V1/V2 成立 | 三套机制并存，需清晰边界 |

**推荐路径（探针已跑，见 §2.2）**：V1/V2 的链路/产物侧已证 ⇒ **走 A**（19 处动态与 tabbar 按 C 拆簇）；仅当**真机目视**发现变量不取值时才退 **B**（此时 P1 的令牌集仍可复用，只是输出物换成"字面量替换"）。

**关于前沿标准（值得采纳的部分）**：W3C DTCG **Format Module 2025.10 已于 2025-10-28 成为首个稳定版**（`$value`/`$type` + `{color.blue-600}` 别名），Style Dictionary v4 / Terrazzo / Figma / Tokens Studio 均读写该形态。本项目 `design_tokens.json` **不是** DTCG 形态（扁平 `key:value`，无 `$type`）⇒ 建议**升级为 DTCG 形态**（拿到别名能力 + 类型化转换 + 与设计工具互通）；但**不建议引入 Style Dictionary/Terrazzo 本体**——它们的价值在"一份源产多端"，本项目为**单端**，自写 ~100 行转换器（DTCG → ucss 变量表 + 换算）成本更低、可控性更高。

## 5. 验收口径（**不含"看起来对"**）

1. **冷编译**：`HBuilderX cli launch app-android --compile true` → `项目 client 编译成功`（**必要非充分**，参见 GAP-1/GAP-2）。
2. **产物取证**：`unpackage/**/bytes/*.style.bytes` 含目标类名与**变量解析后的期望值**（B5d/B5.2e 先例）。
3. **目视真机**：像素级比对（颜色/圆角/阴影/渐变零差异）——**当前 `adb` 无设备 ⇒ 此条为阻塞项，必须显式标注，不得以冷编译冒充**。
4. **门禁**：P4 的棘轮（字面量只减不增）+ 反向探针（临时加一个字面量 → CRITICAL）。
5. **逐文件 diff**：仅允许"字面量 → `var(--x)`"改写，禁止结构变更（若必须改结构，另开单条说明）。

## 6. 风险与回滚

- **主风险**：V1/V2 不成立时，`var()` 静默不解析 → 视觉回退默认值/塌陷，而**编译与静态门禁全绿**。缓解：P2 探针先证；P3 逐批目视。
- **次风险**：单位基准选错（px↔rpx）造成全端尺寸漂移；缓解：P1 用"现有 rpx 值的分布"反推基准（整齐数 4/8/12/16/20/24 与 tokens.spacing 同构，佐证基准=750）。
- **回滚**：令牌源与样式**物理分离**，每批独立提交、可单批 `git revert`；P1（纯数据）零风险。
