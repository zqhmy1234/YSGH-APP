# 外部 API 申请 · 核心结论速查（2026-08-18）

> 本文档是 2026-08-18 一次实地操作腾讯云 / 阿里云 / 百度 / DCloud 时发现的几个**反直觉结论**，适用于 MVP 内测阶段。请把它当作"先把坑踩过的备忘"。

## 1. 腾讯云 COS 选「单 AZ」存储就对（别升多 AZ）

| 维度 | 单 AZ（标准存储） | 多 AZ（标准存储） |
|---|---|---|
| 单价 | 0.118 元/GB/月 | 0.15 元/GB/月 |
| 数据持久性 | 99.999999999%（11 个 9） | 99.9999999999%（12 个 9） |
| 服务可用性 | 99.99% | 99.995% |
| 是否支持容量包抵扣 | ✅ 是 | ❌ 否（只能按量付费） |
| 创建后可否切换 | 需新建桶 + COS Batch 迁移 | 需新建桶 + COS Batch 迁移 |

**结论**：MVP 选单 AZ。差 27% 成本，且不能买 6-7 折容量包。11 个 9 持久性对照片云端镜像已足够；最硬的兜底是「手机本地保留原件」（已写入产品设计）。

**坑**：多 AZ 是**创建存储桶时**决定的，开启后**无法关闭**。所以"想先单 AZ 后升多 AZ"→ 需要新建多 AZ 桶 + COS Batch 迁移，不阻塞当前架构。

**比单/多 AZ 更值得做的三件事**：开启版本控制、配生命周期（老照片转低频）、手机端原件兜底。

**参考**：[多 AZ 特性概述](https://cloud.tencent.com/document/product/436/40548) ｜ [存储容量费用](https://cloud.tencent.com/document/product/436/53482) ｜ [产品定价](https://buy.cloud.tencent.com/price/cos)

## 2. 子账号 API 密钥：腾讯云弹窗警告的正确操作

腾讯云控制台首次创建 API 密钥时会弹警示：「不建议使用主账号 API 访问密钥」并提供两个建议：

1. 使用 STS Token 临时凭证代替长期密钥（减少暴露面）
2. **使用子用户 API 密钥代替主账号密钥**（推荐，对应子账号 + 最小权限）

**必须选「切换使用子账号密钥」**，不要点「我已知晓风险继续使用」。理由：
- 主账号 AK = 账号下所有资源的完全控制权，泄露即服务器被入侵 / 数据被删 / 被勒索
- 子账号 AK 只授予你给的权限，泄露损失可控，**可在 CAM 控制台几秒禁用/删除该密钥止损**，不影响主账号和其他服务
- 与《忆述光华_外部API账号管理方案.md》3.2 节"腾讯云用 CAM 子账号"完全一致

**MVP 阶段建议绑的策略**（最小权限起步）：
- `QcloudCOSFullAccess`（对象存储读写）
- `QcloudCIFullAccess`（数据万象图片标签）
- `QcloudSTSFullAccess`（后端换 STS 临时凭证给客户端直传）

不要绑 `AdministratorAccess`。

## 3. 图像识别走 CI（数据万象）还是 TI-A？

| 维度 | TI-A 图像识别 | CI 数据万象-图片标签 |
|---|---|---|
| 接口 | 通用图像标签 0.0025 元/次 | 图片标签 0.0015 元/次 |
| 月 1.5 万次成本 | ~37.5 元 | ~22.5 元 |
| 是否要后端单独调一次 | 要 | 同 |
| 触发方式 | 后端显式调 API | **同上**（CI 没有"上传即打标"开关，见下条） |
| 适用场景 | 通用物体/场景识别 | 已存 COS 里的照片批量打标 |

**结论：MVP 用 CI 图片标签，便宜 40%**，且与 COS 同账号同权限管理更简单。

## 4. CI「上传自动打标」真相（重要！纠正之前的说法）

**CI 控制台里没有"上传即自动打标"开关**。上一版说"绑定桶 + 开启图片标签自动处理"是**不准确的**，CI 图像标签是同步 API，必须**后端显式调用**。

CI 倒是有「[数据工作流](https://cloud.tencent.com/document/product/460/46488)」能配置"对象上传 → 自动触发任务节点"，但**支持的文件格式明确列出的是音视频（3gp/asf/avi/mp4/mp3/wav）**，**没有列 jpg/png/webp 图片**——图片是否能走工作流存疑，生产不建议依赖。

**MVP 唯一稳妥的路径（照片自动打标）**：
```
照片上传 COS 成功
       ↓
后端通过 COS 回调（或 SCF/EventBridge）收到"新对象"事件
       ↓
后端异步任务调 CI 图像标签 API：
  POST ci.<region>.myqcloud.com/image/Tagging
  Body: { "Inputs":[{"Object":"photos/2026/08/18/abc.jpg"}] }
       ↓
拿到 Tags: ["聚会","室内","人像",...] → 写入数据库
```

**操作层面你这一步到此为止**：桶绑定完成 = CI 服务已开通 + 权限已给；"自动打标"是后端代码活（M2 接 API），不要在控制台再找开关了。

**手动测试**：控制台 → 数据万象 → 你的桶 → [智能工具箱](https://console.cloud.tencent.com/ci/bucket) → 选图片试一次标签识别，能跑通就 OK。

## 5. DCloud uni-push + 厂商通道实操要点

- DCloud 开发者账号注册**只需手机号**（不需要身份证实名）
- 首次开通 uni-push 2.0 会**向个推同步手机号**，不需要自己注册个推
- uni-push 2.0 **必须绑 uniCloud 服务空间**（即使业务服务器不用 uniCloud），推送走它
- **厂商通道是必填坑**（小米/华为/OPPO/vivo/荣耀/魅族），每家独立申请、各自 AppID/AppKey/AppSecret
- 没配厂商通道的手机：在线走个推 socket 正常收，**App 被杀后收不到离线推送**（属预期降级）
- MVP 阶段**先配小米 + 华为 + OPPO**（审核最快→最慢：小米 < OPPO < 华为），vivo/荣耀/魅族后补

## 6. 易踩坑清单

- ❌ 不要在阿里云/腾讯云/百度/DCloud 给**同名测试账号/正式账号**互相绑——实名信息要统一负责人
- ❌ 不要把 API Key/Secret 发到聊天/邮件/文档/截图（永久留痕）
- ❌ 不要给子用户 `AdministratorAccess` 全权策略
- ❌ 不要在创建 COS 桶时手贱开多 AZ（开关在创建时决定**不可关闭**）
- ❌ 不要以为 CI 桶绑定后会自动打标（必须后端调 API）
- ❌ 不要在 DCloud uni-push 没绑 uniCloud 服务空间就测推送
- ❌ 不要等所有厂商都审核完才开始内测（小米最快当天，**今天就去注册小米/华为/OPPO 开发者账号**，审核 3-7 天）
