> 版本：v1（调研版）｜日期：2026-08-16｜来源：行业最佳实践检索（OpenAI / Google Cloud / SecretDrop / Apidog / 腾讯云 CAM 文档 / 微信开放平台文档等）

> 待办：本方案为调研结论，需团队拍板后落地（建议在 M0 内确定）

---

## 一、结论先行

**不是"同一个人提供统一账号"，而是两层结构：**

1. **账号主体统一**（对）：所有外部服务用**公司/团队主体**注册，账号归组织不归个人——防止"人走了账号没了"。
2. **凭证绝不共享**（关键）：API Key / AppSecret / AK-SK 是"钥匙 + 钱袋"（计费挂在账号下），**一人一 Key、一环境一 Key、最小权限、可轮换、可审计**。

> 一句话：**统一的是"户头"，分散的是"钥匙"。**

---

## 二、为什么不能"同一个人统一提供账号"

| 问题 | 后果 |
|---|---|
| 单点故障 | 该人离职/生病/忙，全组拿不到凭证，开发停摆 |
| 无法审计 | 一个 Key 全组用，泄露了不知道是谁、从哪泄露的 |
| 计费混乱 | 开发/测试/生产混在一个 Key 里，没法按用途核算、限额 |
| 泄露无痕 | 群里/文档里传过的 Key 永久留痕（Slack/邮件/Notion 都可被检索），Git 历史里更删不掉 |
| 违反平台规则 | OpenAI/Google 等官方明确**不建议共享个人 Key**（共享=破坏安全+模糊用量追踪+违反最佳实践） |

行业共识（2026 检索来源）：
- OpenAI 官方：不推荐共享个人 API Key；协作应走 Project 级 Key（按项目/环境隔离，独立限额与用量看板）。
- Google Cloud：为每个成员/每个应用发独立 Key，便于控制访问、审计追溯、降低单 Key 泄露影响；定期轮换。
- SecretDrop / Apidog：密钥要"最小权限 + 定期轮换 + 集中管理 + 可审计"，任何永久留存渠道（聊天/邮件/文档）都不该传密钥。

## 三、按平台的具体落地（本项目 17 项服务逐一对应）

### 3.1 阿里云（百炼 qwen-flash / FunASR / Qwen3-VL-Embedding / 护栏）

- 一个**阿里云主账号**（公司主体，管理员 1 人持有，开 MFA）。
- 建 **RAM 子账号**：后端主程 1 个、CI 1 个（预留），每人独立 AccessKey。
- 主账号 AK 只在控制台管理用，**不下发到任何代码/环境**。
- 百炼平台内支持**多 API Key 按用途/环境分**（dev/prod 各一把），用量看板按 Key 分账。

### 3.2 腾讯云（图像识别 CI / COS / 服务器）

- 一个**腾讯云主账号**（公司主体，管理员持有，开 MFA）。
- 用 **CAM 子账号**给需要的人：COS 只授"指定 bucket 的读写"，图像识别只授对应服务权限（最小权限策略）。
- COS 走 **STS 临时密钥**（现有设计已是 STS 直传，30 秒有效）——客户端**永远不持有长期密钥**，这本身就是最佳实践。
- 服务器（Lighthouse）在子账号或主账号下均可，但**登录凭据走密钥对/堡垒机，不共享密码**。

### 3.3 微信开放平台 / 企微认证（AppID + AppSecret）

- 一个主体注册（公司），**成员管理**里按角色添加成员（开发者/运营/数据分析），不需要的人不给权限。
- **AppSecret 只有后端负责人 + 密钥管理器可见**；任何聊天/文档/代码库都不允许出现明文。
- AppSecret 支持**重置**：泄露即重置，重置后旧 Secret 立即失效（这是最后一道保险，日常仍按"不传明文"执行）。
- 企微认证属资质类（300 元/年），由运营/行政管主体即可，与开发 Key 无关。

### 3.4 百度（OCR 高精度版）

- 一个百度云账号（公司主体），**每人一个 API Key 或按环境分 Key**（百度支持多 Key）。
- 开发期个人调试用自己的 Key（免费额度各算各的），后端生产 Key 走密钥管理器下发。

### 3.5 高德开放平台（逆地理编码）

- 一个高德账号（主体），**Key 按应用维度创建**（iOS/Android/服务端各一个），别复用。
- 高德免费额度按账号算（个人 5000 次/日），团队内测共享一个账号额度即可——但**服务端 Key 只进后端环境变量，不打包进 App**（防反编译盗用）。

### 3.6 Sentry（云版）

- 一个组织（org），**按项目/环境建 DSN**；成员用邮箱邀请进组织（免费额度 5 万 event/月够用）。
- DSN 是半公开的（客户端可读），后端 DSN 仍走环境变量；脱敏规则（PII）由后端负责人配置。

### 3.7 AI 开发工具 Key（Claude Code / Cursor / Agent 的 LLM Key）—— 单独一条线

**与产品 AI 功能 Key 的区别**：产品 Key（百炼等）按 3.1 管；开发工具 Key 是团队自己烧的 token，**最易账单爆炸**（Agent 式编码 20 轮会话累计输入 token 可达 200 万+），必须单独设限。

- 原则不变：**统一组织计费，分散每人 Key**。
- Claude Console：组织 Admin API —— 按成员发 Key、按成员 spend limit、75%/90% 预算告警、用量分析（2026 年已支持）。
- OpenAI：Projects + 每项目独立 Key / 限额。
- seat 制产品（Cursor / Copilot 组织席位）：无裸 Key 可管，固定月费，适合不想管 Key 的团队。
- 国内模型（千问/DeepSeek）：同样每人独立 Key、组织统一开票。
- CI 用的 Key 只进 GitHub Actions Secrets / 密钥管理器。
- 成本控制：prompt caching（缓存输入省 90%）、会话卫生（任务完成 /clear 重置上下文）、模型路由（简单任务用便宜档）。
- ⚠️ AI 特有红线：**不要把 .env / 密钥文件内容喂给 AI 工具当上下文**；AI 生成提交的密钥泄露率是人工 2 倍（GitGuardian 2025），pre-commit 扫描对 AI 提交尤其重要。

**多模型团队（你 DeepSeek / 别人 Claude）怎么管**

- 定性：多模型混用是常态不是问题（避免供应商锁定 + 按任务选模型），管的是"人 + 预算 + 安全"，不是"模型"。
- 轻量档（2-4 人）：每人 BYOK（各用各的 Key），靠三样统一：①台账（管理员登记谁用哪个平台/限额）；②密钥管理器（Bitwarden 存各平台 Key，.env 模板统一变量名）；③月度对账（各平台后台拉账单）。
- 网关档（5 人+ 或要统一管控）：自托管 **LiteLLM Proxy**（或国内 one-api/new-api）——所有 Key 收口到网关，每人一个虚拟 Key，管理员看全量用量/按人设预算/限流/审计；代码只认网关一个 OpenAI 兼容端点，底层模型随便换。⚠️ 网关自己的 Key 是最高价值目标，需单独保护；小团队可不上。
- 代码层解耦：统一环境变量（LLM_API_KEY / LLM_BASE_URL / LLM_MODEL），换模型 = 改配置不动代码（DeepSeek/千问走 OpenAI 兼容；Anthropic 走网关或单独封装）。
- 质量一致性：不同模型生成风格不同 → 统一 code review + lint（ruff）+ 测试门禁（已有 review_agent/test_agent + pre-commit）兜底。

### 3.8 uni-push / DCloud（推送）

- DCloud 账号 + 各厂商推送后台（小米/华为/OPPO/vivo/荣耀）——**各厂商后台是必填坑**：每个都要独立申请、各自 appkey/appsecret。
- 建议：账号归公司主体，但**每个厂商后台由对应客户端负责人各自持有**，密钥进 uni-push 服务端配置，不写代码。

## 四、密钥存取层：用什么工具装这些 Key

调研到的 2026 年小团队主流（按"要不要自己运维"排序）：

| 工具 | 模式 | 适合度 | 备注 |
|---|---|---|---|
| **Infisical（免费档）** | 托管 secrets 平台（可自托管） | ⭐ 首选 | 免费：5 身份/无限项目/3 环境/密钥共享/2FA；CLI 注入 .env（`infisical run -- python app.py`）；操作详见《忆述光华_Infisical密钥管理操作手册.md》 |
| **1Password / Bitwarden（团队库）** | 密码 + secrets 一体 | 备选 | 既管账号密码又管凭证；Bitwarden 免费个人号可 1 对 1 共享；Families $40/年 6 人；1Password 国内访问需梯子 |
| **Vaultwarden（自托管）** | Bitwarden 兼容开源服务端 | 备选 | 免费无限用户/组织，Docker 单容器（<200MB 内存）；若 Infisical 国内访问不佳，服务器到位后切这个 |
| **Doppler** | 托管 secrets 平台 | 备选 | 免费 3 人，之后 $8/人/月；国内访问/支付不便，团队全在境外才考虑 |
| **HashiCorp Vault** | 基础设施型密钥库 | ✗ 过度 | 运维成本高，4 人技术团队 + 2核4G 服务器不划算（本项目已排除自托管 Sentry 同理） |
| **.env + .gitignore（现状）** | 手工 | 过渡态 | 只能防"入库"，不能防"传群"，作为起点但不是终点 |

**本项目建议路径（分阶段，成本敏感）：**

1. **现在（M0）**：建台账（共享表格记"谁有什么"）；维持 `.env` 不入库 + pre-commit 密钥扫描（已有）；主账号开 MFA；管理员建好各平台子账号。
2. **Sprint 2 前后**：上 **Infisical 免费档**（5 身份/无限项目/3 环境，4 人+1 CI 正好），全员 CLI 接入，废弃"群里发 Key"——操作步骤见《忆述光华_Infisical密钥管理操作手册.md》。
3. **上线前（M2+）**：接腾讯云 **SSM 凭据管理系统**（生产密钥托管 + 自动轮换）+ GitHub Actions Secrets（CI 注入）；若届时 Infisical 国内访问不佳，切 **Vaultwarden 自托管**（Docker 单容器，免费无限用户）。

## 五、落地步骤（建议 M0 内完成）

1. 指定 **1 名账号管理员**（建议后端主程/负责人）：持有各平台主账号 + MFA，负责建子账号、发 Key、轮换、吊销。
2. 管理员用公司主体注册/迁移：微信开放平台、阿里云、腾讯云、百度、高德、Sentry、DCloud（企微认证已在 M0 第一天流程里）。
3. 建子账号矩阵：阿里 RAM（后端、CI）、腾讯 CAM（后端、CI）、Sentry 成员邀请、微信成员角色——**按角色最小授权**。
4. 分环境建 Key：dev / prod 分开（云厂商与百炼都支持），限额按环境设。
5. 上密钥库（Bitwarden 团队版起步），`backend/.env.example` 只留变量名不留值。
6. 立纪律（见下节），写进 AGENTS.md / 团队 wiki。

## 六、纪律（红线）

- ❌ 禁止：Key/Secret 出现在聊天、邮件、文档、截图、代码、Git 历史（pre-commit 已挡一层，人为遵守另一层）。
- ❌ 禁止：客户端（App）内置长期 AK/SK（COS 必须 STS；高德/百度服务端 Key 不进包）。
- ✅ 必须：一人一 Key / 一环境一 Key；最小权限；MFA。
- ✅ 必须：**人员离职/离组 → 立即轮换其持有的全部 Key**（Key 不随人走）。
- ✅ 必须：**季度审计**一次各平台 Key 列表，停用无活跃的（云厂商控制台都有用量视图）。
- ✅ 必须：疑似泄露 → 立即重置/吊销，再查日志定位（先止血后追责）。

## 八、轻量档落地操作手册（远程团队版）

### 8.1 第一步：建台账（零工具）

用飞书多维表格/腾讯文档建共享表，**只记元数据不记密钥值**：

| 平台 | 用途(dev/prod/CI) | 持有人 | 创建日期 | 月度限额 | 下次轮换 | 备注 |
|---|---|---|---|---|---|---|
| 腾讯云 | prod-COS | 后端主程 | 08-20 | 50 元 | 11-20 | 走 STS |

规则：密钥值永不进表；谁改 Key 谁当天更新；新人加行、离职删行。

### 8.2 第二步：密钥存放（Infisical 免费档）

- **已选定 Infisical 免费档**（5 身份/无限项目/3 环境/密钥共享/2FA，4 人团队正好）。详细分场景操作（程序员视角）见《忆述光华_Infisical密钥管理操作手册.md》。
- 管理员 5 分钟起步：注册 app.infisical.com → 建组织 → 建项目（默认 dev/staging/prod 三环境）→ Access Control 邀请成员（邮箱）→ 角色：Admin/Member/Viewer。
- 日常三件事：
  1. 存：Secrets 页选环境 → Add Secret（或 `infisical secrets set K=V --env=dev`），命名规范"平台-用途"全大写下划线。
  2. 取：`infisical login` + `infisical init` 后 `infisical run -- uvicorn app.main:app` 自动注入；或 `infisical export --env=dev --format=dotenv > .env`。
  3. 传：Secret Sharing 临时链接（过期时间+访问密码），不发群。
- CI 用机器身份（Machine Identity）+ GitHub Actions 集成，人不用手填 Key。
- 免费档边界：无审计日志/版本回滚/自动轮换 → 台账 + 季度轮换纪律补（见手册第 9 节）。
- 中国访问备选：app.infisical.com 不畅则 CLI 走 API 仍可用；长期不行切 Vaultwarden 自托管（Docker 单容器）。

### 8.3 第三步：月度对账（每月 1 号，10 分钟）

1. 各平台后台拉上月账单 → 填台账实际花费列，超标标红。
2. 用量看板定位"谁在烧钱" → 降档或设限额。
3. 顺手吊销无活跃 Key，台账同步。

### 8.4 远程协作纪律

1. 发 Key 只走 Bitwarden/Send，不走微信/邮件/文档（聊天记录永久留存）。
2. 台账只记"谁有"不记"值"。
3. 人离职当天：删组织成员 + 轮换其全部 Key + 更新台账。

## 九、公司未成立阶段：公共账户怎么建（实操）

**核心思路**：没营业执照也能有"公共账户"——用"团队公共邮箱 + 手机号"当主体，负责人个人实名认证兜底；账号归属组织不归属个人。

**现在就能办（绝大多数平台）**：

1. 建团队公共邮箱（QQ/163/Outlook 免费），如 `yishu.team@163.com`——**所有平台账号统一用它注册**。
2. Infisical 组织：公共邮箱直接注册建 Organization，**不需要营业执照**。
3. 阿里云/腾讯云/百度/高德/Sentry/DCloud：支持个人实名（负责人身份证+人脸，免费当场过），API 与免费额度正常用；发票开普票。
4. 手机号：办一张团队副卡绑所有账号（或先用负责人手机，台账记录）。

**必须等公司成立才能办的（不阻塞内测）**：

1. 企微认证（300 元/年，需营业执照）——公司成立后第一时间办。
2. 微信小程序企业主体：个人主体可注册、code2session 正常跑内测；仅限支付/部分类目（不影响 MVP）。
3. ICP 备案：个人备案可先做；或服务器选香港地域暂缓。
4. 企业开发者额度（高德 10000 次/日等）与增值税专票：升级企业主体后。

**防纠纷三动作**：

1. 台账加"主体状态"列：标注"公共邮箱 + 谁实名"；实名者离职去平台换绑实名（阿里云/腾讯云支持变更）。
2. 团队内书面约定：公共邮箱注册的账号归团队，实名仅代表认证人。
3. 公司成立后统一升级企业主体 + 补办资质，两条路不冲突。
