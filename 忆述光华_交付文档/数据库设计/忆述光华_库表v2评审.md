# 忆述光华 · 库表 v2 评审（赵清欢修订版 vs 本地 schema.sql）

> 版本：v1｜日期：2026-08-18｜评审：官海峰（T1 后端）

## 一、总体结论

**赵清欢修掉了我们自审标注的 2 个问题（event_items 传递依赖、content_tags 悬空外键），并做了几处规范化重构，方向正确。** 但删除了 3 张表 + 若干字段，其中 **2 处是重要回归（echo_history 节流约束、sync_field_versions 同步版本表）**，建议拉回或明确决策。

> ⚠️ **2026-08-18 修正（重要）**：上述结论基于"赵清欢在我们 schema.sql 基础上改动"的假设，**经对照 28 表定稿核实后不成立**：
> 赵清欢 v2 实为**忠实复刻《数据库Schema设计.md》定稿**（其文档标题仍保留"整理：技术部（海峰）"），而我们的 schema.sql 是"定稿 + 开发期扩展/语义改动"，两边基线不同。
> ① echo_history 部分唯一索引：**定稿没有**，是我们的开发期修复 → 不是他删的，但代码依赖需拉回；
> ② sync_field_versions：**定稿没有**，是我们自己的扩展表 → 不是他删的；
> ③ sensitive_words.level：**定稿语义即"预置/画像驱动/违规回流"**，是我们 schema.sql 改成"敏感度" → 我们偏离，他忠实定稿；
> ④ event_items.event_level / content_tags 外键：定稿本无/本有，他照定稿，并非"修复我们的问题"。
> **根因 = 基线漂移**：schema.sql 未与定稿文档保持同步。建议三方对齐（定稿 + v2 + schema.sql）产出权威 v3，逐项决策扩展表的去留，并同步更新定稿文档。

## 四、ER 图自审（"看上去有点怪"的根因）

1. **布局**：单图 18 表 + TB 布局 → 4173px 超宽 / 590px 极扁，关系线横跨全图、交叉严重。
2. **缺关系线**：correction_log→contents、question_history→contents、echo_history→events、events 自引用（parent_event_id）未画。
3. **属性不完整**：只列核心字段，与表结构对不上。
4. **结构过期**：v2 新增 event_tags，旧图未含。

**改进方案**：拆两张图（核心业务域：用户/内容/事件/画像/交互；支撑域：同步/基础设施/纠错/消息）+ 补全关系线 + 按 v2 结构更新。
