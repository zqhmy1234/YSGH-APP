# B5-d · 双端后台任务与录音 — 设计文档

> 分支状态：grill 进行中（B5-d-1 后台任务清单讨论中）
> 依据：Q28/Q30 调研（三端后台机制）+ MVP v2.1 端策略（Android+Windows 为主，iOS 待定，鸿蒙移出）

## 1. 已有调研基础（Q28/Q30 结论）

**Android**：前台服务（foregroundServiceType=microphone + POST_NOTIFICATIONS）；WorkManager（约束/指数退避/幂等/持久化）；Android 15 mediaProcessing 限 6h/天；Android 16 强制 API 36 + 扩展归因 API（麦克风使用标注）
**iOS**：interruptionNotification 中断恢复 + UIBackgroundModes=audio；BGProcessingTask（reschedule/setTaskCompleted/expirationHandler 三坑）
**鸿蒙**：移出 MVP（二期评估）
**Windows**：无系统级限制，计划任务 + 文件监听（但 B4-4 已定 Windows 用"导入触发+手动刷新"，不做实时监听）

## 2. B5-d-1 后台任务清单（已收敛 ✅）

**输入分布**：5 个后台任务——#1 录音中断恢复（🔴 用户实时等待）、#2 照片增量同步（🟡）、#3 上传队列（🟡）、#4 事件聚合重跑（🟡）、#5 云侧结果拉取（🟢）；只有 #1 是前台感知

**统一调度（峰宝确认 ✅）**：一个前台服务（承载录音+相册监听，Q28 同款）+ 一个 WorkManager 队列（承载全部静默任务：上传/聚合/拉取，按 B4-3 优先级排序）
- 理由：输入分布只有 1 个实时任务 → 不需要 5 套机制；单前台服务省电省通知位；WorkManager 共享配额统一管理（Android 16 运行时配额下更简单）

**iOS（峰宝确认 ✅）**：**团队无 iOS 能力，不纳入 MVP 实现**——B5-d 只做 Android + Windows；iOS 的 BGProcessingTask 三坑已记录在 Q30 调研，等未来启动 iOS 时直接引用，不现在设计

## 3. B5-d-2 Android 实现边界（已收敛 ✅）

**任务→机制映射**：录音中→前台服务（microphone）；相册监听→前台服务内（dataSync，短命）；照片上传/队列→WorkManager（WiFi 约束）；事件聚合→WorkManager；云侧拉取→WorkManager（定期）

**前台服务短命化（峰宝确认 ✅）**：录音结束 → stopForeground 立即降级 → 后续转 WorkManager；不常驻 24h（Android 15 mediaProcessing 6h/天上限 + Google Play 审查）
**两个前台服务类型不同时开**：录音时（microphone）监听停，录完恢复监听（dataSync）
**扩展归因 API（峰宝确认 ✅）**：Android 16 强制，架构期设计——每个后台任务定 attribution tag（sync_photo / voice_transcribe / event_aggregate / profile_fetch），隐私面板可查

## 4. B5-d-3 录音中断恢复落地（已收敛 ✅）

**状态机（峰宝确认 ✅）**：
```
RECORDING → 中断通知 → INTERRUPTED（已录片段落盘临时文件）
  ├─ 短中断（来电/闹钟）结束 + shouldResume → 恢复录音
  ├─ 用户切走 → 停留暂停态（可能不想录了），等用户回来
  └─ 中断 >30 分钟 → 自动结束，标记"分段"，通知"录音已自动保存"
```
**边界**：来电/闹钟自动恢复（主流）；用户切走不自动恢复；系统杀进程靠已落盘片段，下次打开提示"检测到未完成的录音"

**分段拼接（峰宝确认 ✅）**：Android 9+ 用 MediaRecorder.resume() 原生追加；不兼容机型降级"分段保存+云端拼接"（中断是低频场景，云端拼接简单、成本可忽略，MVP 不做复杂端侧拼接）

**用户可见性**：中断恢复无感（通知栏小状态），不弹窗；>30 分钟未恢复给通知

## 5. B5-d-4 Windows 端后台（已收敛 ✅）

**输入分布**：Windows 端是桌面工具（用户主动打开用），后台只需低频同步，不需要常驻服务

**轻量方案（峰宝确认 ✅）**：
- App 运行时：应用内定时器（每 30 分钟）同步
- App 未运行时：计划任务（每天 1 次，仅用户开启"开机自动同步"才启用，默认关）
- **不做**：开机自启常驻服务（侵入感强、违背桌面工具轻量定位）

## 6. B5-d-5 任务优先级与资源竞争（已收敛 ✅）

**输入分布**：录音转写/新照片是用户有感知任务（等结果），其余后台静默

**优先级表（峰宝确认 ✅）**：
| 优先级 | 任务 | 理由 |
|---|---|---|
| P0 | 语音转写/上传（录音结束） | 用户在等"录音变文字"（B5-a 关怀链路依赖） |
| P1 | 新照片上传（拍照后） | 刚拍的，跨端可见预期高 |
| P2 | 事件聚合重跑（L0/L1） | 打开时间轴才看，可延迟 |
| P3 | 云侧拉取（L2/L3、画像） | 纯后台增强 |
| P4 | 历史批量导入/补传 | 一次性大任务让路给日常 |

**实现**：WorkManager chain——P0/P1 独立高优先级队列，P2-P4 共享低优先级队列；批量导入拆小块，每块让路给高优先级（existingWorkPolicy + 分段 enqueue）

## 7. B5-d 分支总结（全部收敛 ✅）

**任务清单**：5 个后台任务，只有录音中断恢复是前台感知 → 统一调度（单前台服务 + 单 WorkManager 队列）
**iOS**：团队无能力，不纳入 MVP（Q30 调研记录留给未来）
**Android**：前台服务短命化（录完即降级，不常驻）；microphone/dataSync 两类型不同时开；attribution tag 架构期设计（sync_photo/voice_transcribe/event_aggregate/profile_fetch）
**录音中断**：状态机（RECORDING→INTERRUPTED→恢复/停留/30min 自动结束）；MediaRecorder.resume() 原生追加，不兼容降级云端拼接
**Windows**：App 内定时（30 分钟）+ 可选计划任务（默认关），不做常驻服务
**优先级**：语音 > 新照片 > 聚合 > 拉取 > 批量（按用户感知排序）
