# B5-e · Windows 桌面端 — 设计文档

> 分支状态：grill 进行中（B5-e-3 体积瘦身定稿，B5-e-4 批量导入讨论中）
> 依据：MVP v2.1（Windows P1：本地轻量 OCR + 批量导入 + 同步 + AI 引擎适配器）+ Q10/Q24 调研 + Eagle 5.0 设计借鉴

## 1. MVP v2.1 对 Windows 端的定位

**端策略**：Android（主移动端）+ Windows（P1 桌面端）为主，iOS 待定（团队无能力），鸿蒙移出
**Windows 职责**：导入电脑里的老照片/文件 → 本地轻量 OCR（PP-OCRv5 mobile）→ 批量整理 → 与云端同步（B4-1 已定：照片镜像上云、跨端可见）
**已定约束**：
- B4-1：照片原件上云 COS（Windows 可看手机照片）；本地原件保留
- B4-4：Windows 用"导入触发 + 手动刷新"，不做实时监听
- B4-3：上传队列（Windows 也参与）
- B5-d-4：Windows 后台 = App 内定时 30 分钟 + 可选计划任务，不做常驻服务
- **体积瘦身（2026-08-14 拍板）**：Windows 端基础体积 ≈250-300MB——本地 OCR 用 PP-OCRv5 mobile（20MB）而非 PaddleOCR-VL（2GB）；复杂版面走云端兜底；Ollama 不打包用户自装

## 2. B5-e-1 技术栈（已收敛 ✅）

**Electron + Python sidecar（峰宝确认 ✅）**：
- PaddleOCR 是 Python 生态 → 任何方案都要带 Python 运行时；Electron sidecar 是社区最成熟做法（Umi-OCR 等）
- 团队软件工程背景（Web 技能），Electron 前端效率最高
- 包体积大不是问题（模型文件本身就 1.5-2GB，优化空间在模型不在框架）
- 架构：Electron 主进程（UI/交互/上传队列）↔ Python sidecar（PP-OCRv5 mobile 推理服务，本地 HTTP）↔ Ollama（可选，用户自装）↔ 云端 API

**AI 引擎适配器 + 统一配置中心（峰宝确认 ✅，调研 Eagle 5.0 后修正原"Ollama 可选安装"方案）**：
- 调研依据：Eagle 5.0"Freedom of choice"（GPT-5/Ollama/全本地三选）+ 统一 AI 配置中心（设定一次全插件共享）+ Local-first 分级；行业共识 = 模型是可切换适配器不是安装时二选一（ThunderAI Adapter 模式 / Chatbox / PolyUI / Raised Letters 印证）
  - 来源①：Eagle 5.0 <https://cn.eagle.cool/blog/post/eagle5-teaser>
  - 来源②：ThunderAI 适配器架构 <https://blog.csdn.net/weixin_28702613/article/details/160998351>
- **设计**：设置页「AI 引擎」——☑ 云端引擎（默认 qwen-flash，零安装）｜☐ 本地引擎（Ollama，检测到本机安装才显示，免费+隐私+离线）｜☐ 全离线模式（需装 Ollama+本地模型）
- **MVP 范围**：适配器接口 + 云端实现（MVP 必须）；Ollama 适配器 P1（接口预留，用户装了再补）
- 与全项目"可插拔适配器"设计语言一致（检测器/ASR/AI 引擎都是 adapter）

## 3. B5-e-2 本地 OCR 边界（已收敛 ✅）

**输入分布**：清晰截图/PPT/文档照（高，本地够）｜老照片/低质扫描（中，本地够）｜手写笔记（低，云端兜底）｜复杂版面/票据（低，云端兜底）

**本地优先 + 置信度门控 + 云端兜底（峰宝确认 ✅）**：
```
导入照片 → 本地 PP-OCRv5 mobile（20MB）
  ├─ 置信度高（>0.85）→ 直接用（免费、隐私、零上传）
  ├─ 置信度中（0.6-0.85）→ 本地结果先用，标记"低置信度"
  └─ 置信度低（<0.6）/ 手写 / 复杂版面 → 云端百度高精度版重识别
```
- 理由：清晰截图占多数本地免费吃下；隐私（敏感文档不上传，Eagle 卖点）；成本（本地免费、云端按次）；离线可用
- **版面/手写检测（峰宝确认 ✅）**：复用 PaddleOCR 自带版面分析（PP-Structure）+ 手写检测，不额外开发；检测到复杂/手写 → 上云
- **体积瘦身（峰宝确认 ✅）**：本地 OCR 用 PP-OCRv5 mobile（14-20MB，数字源图 95-98%+）——**不用 PaddleOCR-VL-1.5（2GB）**，因为复杂版面已走云端兜底，VL 版优势用不上；这是"功能拆到正确位置"（轻的留本地、重的走云端）

## 4. B5-e-3 本地模型降级（已收敛 ✅，体积瘦身修正）

**输入分布**：Windows 端"降级"的 AI 能力按离线重要性分档——OCR（本来就本地，离线不降级）｜图片向量（离线不补，联网后补）｜分类（离线用 mini 模型/规则）｜摘要（离线才需 Ollama，可选）

**体积瘦身（峰宝确认 ✅，2026-08-14 核心修正）**：
- **本地 OCR：PP-OCRv5 mobile（20MB）**，不是 PaddleOCR-VL（2GB）——复杂场景走云端（B5-e-2），VL 优势用不上
- **本地分类：SetFit mini 蒸馏版（~50MB）**，不是全量（~400MB）——分类是轻任务，mini 够
- **Ollama 不打包（4-6GB）**：AI 引擎适配器保持，用户需要离线摘要时**自己去 ollama.com 装**（Eagle"Want free? Use Ollama"模式——不捆绑，用户自装）
- **修正后基础体积 ≈250-300MB**（修正前 ≈3GB，-90%）

**三档降级（峰宝确认 ✅）**：
```
档位 A（默认，在线）：全能力，云端兜底
档位 B（离线 + 装了 Ollama）：OCR 本地 ✅ + 分类 mini/规则 ✅ + 摘要本地 7-8B ⚠️（慢但可用）
档位 C（离线 + 没装 Ollama）：OCR 本地 ✅ + 分类规则 ✅ + 摘要 ❌（提示"联网后补"）
```
- 分类降级用 SetFit mini（Q20 四层方案的端侧层），不跑 7-8B（便宜快）
- 摘要降级才需要 Ollama 7-8B（可选，AI 引擎适配器已预留）

**离线数据补齐（峰宝确认 ✅）**：离线产生的向量/画像/事件 → 入队，联网后补（B4-3 离线队列）——离线时分类结果/OCR 文本先存本地，联网后补向量/画像/事件 L2/L3，用户无感

## 5. B5-e-4 批量导入流程（已收敛 ✅）

**输入分布**：超大文件夹（首次导入千张级）｜重复导入（拖两次同一文件夹）｜导入中关闭（进度丢失）——三个必然场景，必须防护

**流程（峰宝确认 ✅）**：
```
拖入/选择文件夹 → ① 预扫描（只读目录，算总量不复制）
  → ② 去重预筛（感知哈希 Q16：对比本地已有 + 批次内，重复跳过）
  → ③ 分批处理（每批 200 张，进度条"第 3/25 批"，不阻塞 UI）
  → ④ 每张：本地 OCR（PP-OCRv5 mobile）+ mini SetFit 分类（异步）
  → ⑤ 批次完成 → 入库（本地索引 + 上传队列 B4-3）
  → ⑥ 进度落盘：App 被杀/关闭后续传（从断点批次继续，不白干）
```
- 超大文件夹分批 200 张不卡死；重复导入去重预筛只入一次
- **导入预览（峰宝确认 ✅）**：每批完成顶部一条提示"已整理 200 张，点此查看"（可勾选剔除误入照片）——**默认确认不强制**，不弹窗打断批量流程（兼顾掌控感和流畅度）

## 6. B5-e-5 与云端同步关系（已收敛 ✅）

**数据上云范围**：照片原件 ✅ 上云（COS 镜像，B4-1）；OCR/分类元数据 ✅ 上云（云端主库）；本地整理进度 ⚠️ 部分上云（同步状态）；本地模型缓存 ❌ 绝不上云

**同步触发**：导入时（每批完成）→ App 运行时每 30 分钟 → 手动同步按钮（"正在同步 ✓"）；不做实时文件监听（B4-4）

**Windows 删除策略（峰宝确认 ✅ + 补充）**：
- 默认：**删除 = 只删云端镜像 + 云端索引，本地原件保留**（Windows 是归档库，原件是用户原始资产；防误删，B4-2 软删除 30 天兜底）；用户明确"彻底删除"才删本地
- **⚠️ 必须告知用户（峰宝补充 ✅）**：删除时要明确提示——"**此操作只删除云端副本，本地文件仍保留，如需删除本地文件请手动处理**"——**用户必须知道"云端删了，本地还得自己删"**，不能默默让用户以为全删了

**手动全量重传（峰宝确认 ✅）**：设置页提供"重新上传全部照片"（本地原件可能比云端多：之前没同步完/换机器），低频兜底操作

## 7. B5-e 分支总结（全部收敛 ✅）

**技术栈**：Electron + Python sidecar（PP-OCRv5 mobile 推理服务）；AI 引擎适配器 + 统一配置中心（默认云端 qwen，Ollama 检测到才可选，MVP 只实现云端适配器——Eagle 5.0 模式）
**体积瘦身（核心修正）**：基础体积 ≈250-300MB（-90% vs 原方案）——本地 OCR 用 PP-OCRv5 mobile 20MB 而非 PaddleOCR-VL 2GB（复杂版面已走云端）；本地分类 SetFit mini ~50MB；Ollama 不打包用户自装
**本地 OCR**：本地优先 + 置信度门控 + 云端兜底（>0.85 直接用 / 0.6-0.85 标低置信度 / <0.6 或手写复杂 → 百度云端）；复用 PP-Structure 版面检测
**本地模型降级**：三档（在线全能力 / 离线+Ollama 分类 mini 摘要 7-8B / 离线无 Ollama 规则+无摘要）；离线数据入队联网后补（B4-3）
**批量导入**：预扫描 → 去重预筛 → 分批 200 张 → 本地 OCR+分类 → 默认确认入库；进度落盘续传
**同步**：导入时/30 分钟定时/手动；删除 = 云端删本地留（**明确告知用户本地需自行删除**）；手动全量重传兜底

**待办**：
- Electron + Python sidecar 骨架（M4）
- PP-OCRv5 mobile 集成 + 置信度门控
- AI 引擎适配器接口（云端实现 MVP，Ollama P1）
- 删除告知文案（"只删云端副本，本地请自行删除"）列入产品验收
