# B5-c · 分类纠错学习机制 — 设计文档

> 分支状态：grill 进行中（B5-c-1 纠错链路讨论中）
> 依据：云端"AI分类纠错机制"产品设计（第一版必须有）+ Q20 SetFit 方案

## 1. 云端产品设计（黄伽妮，已定）

**核心原则**：纠错藏在自然使用流程里（回响联动 + 长按改标签），不让用户专门来纠错
**触发时机**：① 主动纠错（长按/编辑）② 被动确认（回响联动：置信度 40-60% 时顺带问"这条我放在XX分类合适吗"）③ 资料收纳联动（整理时确认/修改）
**处理流程**：记录纠错行为（用户ID/内容ID/原标签/新标签/内容特征向量/纠错时间）→ 个性化规则库（本地优先云端同步）→ 同类内容（特征相似度>80%）优先应用纠正后分类 → 每周批量反馈云端微调
**连续纠错 3 次** → 提示"需要我创建自定义分类吗？"
**验收标准**：纠错后 7 天同类准确率提升 ≥10%；操作路径 ≤3 步；被动确认响应 <2s

**待技术评估**（grill 重点）：
1. 纠错数据存储结构（本地 SQLite 表设计）
2. **用户个性化规则与全局模型的权重平衡**
3. 相似度算法选型（余弦/向量距离）
4. 模型微调的周期与计算成本

## 2. B5-c-1 纠错链路与记录结构（已收敛 ✅）

**纠错记录表（本地 SQLite，云端同步）**：
```
correction_log：id, user_id, content_id, content_embedding(向量),
                old_label, new_label, source(主动/回响/整理), created_at
```
- 带**内容向量**：同类内容靠向量相似度泛化（>80% 应用纠错），不靠关键词
- 生命周期：同内容多次纠错以最后一次为准；保留最近 500 条/用户，旧的归档（防膨胀）

**两条路径置信度（峰宝确认 ✅）**：主动纠错（长按）可信度高 → **立刻生效**；回响被动确认可信度中 → **同一类型 ≥3 次一致才生效**（偏好信号积累，防随手误伤）

## 3. B5-c-2 个性化规则 vs 全局模型权重平衡（已收敛 ✅）

**背景澄清（峰宝遗忘点）**：SetFit = 全用户共用的公共分类器（内容类型分类：待办/灵感/情绪/引用/混合），用产品方标注的公共样本训练，一个模型服务所有用户；个人规则 = 每用户自己的纠错记录（correction_log）

**三层裁决（峰宝确认 ✅）**：
```
新内容 → ① 个人规则层命中（correction_log 向量相似 >80%）→ 应用个人纠错结果
       → ② 未命中 → 全局 SetFit 正常分类（公共语义）
       → ③ 共性纠错每周回流微调全局模型
```
- 个人规则层优先 → 用户纠错立即生效（验收"7 天准确率提升 ≥10%"靠它）
- 全局微调只收**共性纠错**（多用户对同类内容一致纠错，如 5 人把"美食→植物"改回）→ 防个体偏好污染全局
- 判定：纠错记录打"全局候选"标记，每周批量比对（多用户一致 → 全局微调；不一致 → 留个人）
- 产品设计"每周批量反馈云端微调"落实为"每周比对共性纠错 → 微调"——**不是所有纠错都微调**

## 4. B5-c-3 相似度匹配算法（已收敛 ✅）

**复用 B2 向量管线，零新增**：
- 文本 → BGE-M3 dense 向量；图片 → Qwen3-VL 图片向量（入库时已算）
- correction_log 存向量（B5-c-1 已定）；新内容入库时向量与纠错记录向量做**余弦相似度**比对
- 余弦 >0.8 → 判"同类"，应用纠错（产品"待评估"列了余弦/向量距离，选余弦）

**类型约束（峰宝确认 ✅，输入分布陷阱补强）**：
- 纠错记录带 content_type（照片/文字/语音）
- 匹配先同类型再比向量（照片纠错只匹配照片）——防"猫的新闻套用猫照片纠错"误伤
- 80% 阈值按类型微调（照片语义宽可放宽、文字精确更严格）

## 5. B5-c-4 微调周期与成本（已收敛 ✅）

**输入分布**：100 用户每周纠错 300-500 条，但多用户一致的共性纠错每周仅 5-20 条（极稀疏）

**按量触发，不按周（峰宝确认 ✅）**：**共性纠错累计 ≥50 条才触发 SetFit 微调**；不足则攒着（个人规则层已生效）
- 理由：SetFit few-shot 微调需足够样本才有效；每周 5-20 条微调 = 过拟合抖动风险（这周往左下周往右）
- 50 条阈值 ≈ 2-4 周一次，样本足、稳定、成本低
- 微调成本：0.5B 级小模型 + 50 条样本，CPU/小 GPU 几分钟，可忽略
- 微调只是"固化共性纠错进全局模型"，微调前共性纠错已通过个人规则层生效

## 6. B5-c-5 纠错噪音处理（已收敛 ✅）

**输入分布**：误操作（手滑）/ 用户自身不一致（来回改）/ 一次性情绪（批量删）/ 钓鱼乱点（被动确认）

**三道防噪音闸门（峰宝确认 ✅）**：
1. **一致性校验**：A→B 但 3 天内刚同类 B→A（来回改）→ 判定"用户没想好"不写入规则层，标记待定；来回改 2 次以上 → 轻提示"以哪次为准？"
2. **批量操作保护**：一次改 >10 条 → 弹确认防情绪化；24 小时内可撤销（产品设计已写）
3. **权重衰减**：纠错记录带时间权重（近期高远期低）；同类型新旧冲突按最近胜；连续同方向 ≥3 次 → 强规则，偶尔一次 → 弱规则

## 7. B5-c 分支总结（全部收敛 ✅）

**纠错链路**：三入口（主动长按/回响被动确认/整理联动）→ correction_log（带内容向量，本地 SQLite 云端同步，500 条上限，最近权重）；主动纠错立即生效，回响被动确认 ≥3 次一致才生效
**全局 vs 个人**：三层裁决（个人规则优先 → SetFit 全局兜底 → 共性纠错回流微调）；SetFit = 全用户共用公共分类器（内容类型 5 类）；全局微调只收多用户一致的共性纠错（防个体偏好污染）
**相似度匹配**：复用 B2 向量管线（BGE-M3/Qwen3-VL），余弦 >0.8 + 类型约束（先同类型再比向量，防跨类型误伤）
**微调触发**：按量不按周——共性纠错累计 ≥50 条才微调（≈2-4 周一次），每周 5-20 条微调是过拟合抖动
**噪音防护**：三道闸门（一致性校验/批量保护/权重衰减）
