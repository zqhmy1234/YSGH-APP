# B5-b · 安全护栏 — 设计文档

> 分支状态：grill 进行中（B5-b-1 护栏范围讨论中）
> 依据：Q39 完整方案（已写入 Q31-44 文档 + Q1-30 表格版）+ Qwen3Guard 调研

## 1. Q39 已定方案（回顾）

**四层安全护栏**：
1. 生成前：敏感话题标签 → 不触发追问（画像 L1 常驻敏感标记 + 事件级敏感）
2. 生成时（MVP）：人工审核模板 + 变量填充（白名单零误伤）
3. 生成后：Qwen3Guard-Gen-8B 三级检测（安全/有争议/不安全，96.2%/F1 96/320ms GPU）+ 规则兜底
4. 框架：NeMo Guardrails 串层（对话流 rail，+500ms/次）
5. 审核 API：MVP 不接（模板白名单兜底）；合规需要时接阿里云文本审核

## 2. B5-b-1 护栏覆盖范围（已收敛 ✅，输入分布驱动）

**输入分布**：追问（低频主动侵入 🔴）｜回响（低频主动触达 🔴）｜复盘文案（中频整理 🟡）｜摘要/搜索（高频转述 🟢）

**分级覆盖（峰宝确认 ✅）——护栏成本与风险成正比**：
- 🔴 追问/回响 → **四层全过**（敏感检测 → 模板 → Qwen3Guard → 规则）
- 🟡 复盘文案 → 敏感检测 + 规则兜底（模板部分天然安全）
- 🟢 摘要/搜索 → **规则级**（敏感词表兜底，不过模型）——转述用户自己的内容，过 Qwen3Guard 是浪费

**回响双查（峰宝确认 ✅）**：回响重提旧内容 → **画像 L1 敏感校验**（该内容是敏感话题 → 跳过不重提）+ Qwen3Guard（查"这句话是否安全"）——敏感校验更前置（查"该不该提"，Qwen3Guard 只查"安不安全"）

## 3. B5-b-2 Qwen3Guard 部署形态（已收敛 ✅，调研更新）

**调研结论（2026-08-14）**：阿里云百炼已托管 Qwen3Guard——
- `qwen_response_check`（输出护栏）/ `qwen_query_check`（输入护栏），均基于 Qwen3Guard；Pro 版用审核大模型增强（适用 Qwen-Max）
- 用法：调用百炼 qwen 时 header 传 `X-DashScope-DataInspection: {"input":"cip","output":"cip"}` 自动匹配
- 计费：按 token 按量付费、不用不收费、无需 GPU
- 来源①：<https://help.aliyun.com/document_detail/2923687.html>
- 独立 API 备选：`https://qwen3guard.cn-hangzhou.aliyuncs.com/api/v1/content/check`（来源②：<https://blog.csdn.net/SapphireFox37/article/details/157007690>）
- 阿里云 AI 网关安全护栏底座同为 Qwen3Guard（Gen 离线 + Stream 流式）（来源③：<http://developer.aliyun.com/article/1742142>）

**部署决策（峰宝确认 ✅）**：
- **MVP 采用阿里云百炼托管护栏**（`qwen_response_check`，按 token 计费，几元/月量级）——替换"规则+flash 自检"方案，零部署零 GPU
- CPU 自部署 8B Q4 淘汰（5-10s/次灾难且有托管可用）；flash 自检降为托管不可用时的兜底
- **隐私权衡**：内容发阿里云检测（与 OCR/ASR 同性质），敏感内容已走排除不进 AI 管线
- **可插拔检测器接口（峰宝确认 ✅）**：规则检测器 / 百炼托管检测器 / Qwen3Guard 自部署检测器都是实现，MVP 挂百炼托管，未来私有化换实现不换调用方

## 4. B5-b-3 检测时机与成本优化（已收敛 ✅）

**两级过滤（先便宜后贵）**：
```
生成内容 → ① 规则预检（免费毫秒级：敏感词表+画像校验+模板白名单）
         → ② 百炼托管检测（按 token，仅高危：追问/回响、复盘 LLM 段）
```
- 模板生成的追问/回响：变量填充后先跑规则，命中即拦不调模型；规则通过才送百炼（变量可能敏感）
- 复盘文案：只检测 LLM 自由发挥段落，模板段跳过
- 摘要/搜索：不过模型（B5-b-1 已定规则级）
- 成本量级：100 用户 × ~300 次/天 × 60 token ≈ 54 万 token/月，个位数元/月

**三层敏感词表（峰宝确认 ✅）**：① 预置基础词表（涉政/涉黄/暴力标准词）② 画像敏感标记驱动（B1：用户"别再提前任"→ 个人词表）③ 违规词回流（百炼检测违规 → 自动加入本地规则表，越用越省）

**模板机制说明（峰宝质询确认）**：
- 追问/回响模板 = 人工审核骨架 + 变量填充（骨架安全，变量可能敏感 → 需要两级过滤）
- 重复感控制：30-50 个骨架池（按内容类型路由）+ 30 天不重复（Q40）+ 变量个性化；回响内容全为用户记忆，句式重复被内容掩盖
- **模板不是终态**：追问是 P2（云端标"备选玩法"），MVP 仅回响；进阶 LLM 生成 + 百炼检测护栏（Q39"进阶才用 LLM 生成"）；模板扩展 = 产品运营定期补充骨架

## 5. B5-b-4 敏感记忆检测实现（已收敛 ✅）

**两级敏感判定**：
- 第一级：画像 L1 敏感清单（B1 对话式管理，用户显式添加）→ 追问/回响前查画像，命中即回避
- 第二级：**事件级敏感标记（新增）**——内容入库时（照片 OCR/标签、文字分类、语音转写后）打"敏感话题"标签（分手/离世/健康/金钱/家庭矛盾等 5-8 类）；敏感事件不触发追问、回响跳过
- 关键设计：敏感标签是"事件属性"（只在"该不该提"时读），不展示、不参与搜索排序

**检测方式（峰宝确认 ✅）**：**规则先行 + LLM 补漏**（qwen-flash）——规则关键词命中即敏感（快免费可解释）；规则未命中但 LLM 判敏感 → LLM 补（抓"他说以后别联系了"这种无关键词表达）；输入分布：绝大多数不敏感（规则直接放行），敏感是少数（LLM 只处理规则未命中的，成本低）

**敏感有效期（峰宝确认 ✅）**：**动态降级 + 画像永久**——
- 事件级敏感：带时间戳 + 最近提及次数（用户主动提及 +1）；主动提及 ≥3 次 → 降级为普通话题（用户已释怀）
- 画像级敏感（用户显式标记）：**永不过期**（用户没说"可以提"就一直回避）

## 6. B5-b-5 审核 API 取舍（已收敛 ✅）

**关键认知**：Q39 问的"内容安全审核 API"指向两件事（之前混在一起）：
1. **AI 输出审核** → 已由百炼托管护栏解决（B5-b-2，无需额外 API）
2. **用户内容合规审核**（上传的照片/文字过审，防违规入库）→ 另一件事

**决策（峰宝确认 ✅）**：
- AI 输出审核：✅ 百炼托管护栏（B5-b-2）
- 用户内容合规审核：**MVP 不接专用审核 API，用敏感识别顶替**（内测熟人用户风险低；B5-b-4 事件级敏感标记已覆盖"该规避的"）；**上架前必接**（应用市场硬门槛，接阿里云内容安全，文本 ~0.0015 元/千字符，成本忽略）
- 架构预留审核 API 接口（可插拔，同检测器接口模式）

## 7. B5-b 分支总结（全部收敛 ✅）

**分级护栏**（成本与风险成正比）：🔴 追问/回响四层全过（敏感检测→模板→百炼检测→规则）｜🟡 复盘敏感检测+规则｜🟢 摘要/搜索规则级
**回响双查**：画像 L1 敏感校验（该不该提）+ 百炼检测（安不安全）
**部署**：阿里云百炼托管 Qwen3Guard（qwen_response_check，按 token 计费，零部署零 GPU）；可插拔检测器接口（规则/百炼/自部署都是实现）
**两级过滤**：规则预检（免费毫秒级）→ 百炼检测（按量，仅高危）；三层敏感词表（预置/画像标记/违规回流）
**模板机制**：人工审核骨架+变量填充；30-50 骨架池+30 天不重复+变量个性化；模板是 MVP 护栏非终态（P2 进阶 LLM 生成）
**敏感记忆**：两级（画像 L1 永久 + 事件级动态降级：主动提及 ≥3 次降级）；规则先行+LLM 补漏
**审核 API**：AI 输出已接百炼；用户内容 MVP 敏感识别顶替、上架前接正式审核
