# B3 · 照片事件聚合算法 — 设计文档

> 分支状态：grill 进行中（四层模型已收敛，参数层讨论中）
> 依据：云端 Q14 原文 + 2026 调研（ST-DBSCAN/级联聚类/LibrePhotos/Qwen3-VL 语义聚合/Google-Apple 关系图）

## 1. 云端原题（Q14）

> 事件聚合算法：按"时间+地点+场景"三维聚合成事件组的技术实现？同一地点 30 分钟内拍摄归为同一事件的时空边界算法？GPS 漂移如何处理？

**云端已有回答**（方向对，无算法）：不要用"同一地点+30分钟"做死规则，做时间连续性+空间接近性+场景相似性的三维聚合；GPS 漂移在进入聚合算法前先处理。

**产品部验收标准**：授权后 30 秒内展示首批已整理事件（≥50 张）；同一地点 30 分钟内归为同一事件。

## 2. 核心判断：单层聚类必死，必须四层事件模型

**单层 30 分钟窗口的三大死穴**（峰宝质询确立）：
- 长跨度事件（5 天旅行）→ 被切成几十个 30 分钟碎片，时间轴废
- 并行事件（备考 3 个月 + 日常）→ 混在一个窗口无法分离
- 每天都有大跨度事件 → 一张照片同时属于多个事件，单层聚类只能二选一

**根因**：用户照片里的"事件"天然是**多粒度嵌套结构**（瞬间 ⊂ 一天 ⊂ 一段旅程 ⊂ 人生阶段），单层聚类只有一个粒度，是架构问题不是调参问题。

## 3. 四层事件模型（已认可 ✅）

```
照片入库
  ↓ 预处理：去重(Q16) → 连拍折叠(<5s) → GPS漂移修正 → 标签(腾讯云) + OCR + 人脸
  ↓
L0 瞬间层：级联 ST-DBSCAN 最低档（500m / 30-60min）── 产品部 30 分钟标准升级版
  ↓
L1 日聚合：当日连续性 → "8月14日 · 杭州"（时间轴骨架，纯日层）
  ↓
L2 主题事件：LLM 语义归并（跨天/跨地点）→ "7月云南之旅" ← 长跨度事件在这层解决
  ↓
L3 长期主题流：标签+时间线持续归并，与日常并行 → "2026考研备考" ← 并行事件在这层解决
```

**三个关键设计**：
1. **长跨度事件 → L2 靠 LLM 认**：地点域连续+时间连续+主题一致 → LLM 判断"一个事件"。不靠调窗口
2. **并行事件 → 标签维度分离**：备考照片（书本/笔记/电脑标签）与生活照片（美食/朋友）两流并行、互不干扰（Google Photos"橙背包"主题回忆同机制）
3. **照片↔事件多对多**：一张备考学习照 = L0"今晚学习片段" + L3"考研备考"——关系表，不是一次聚类定终身（Google 关系图思想）

**调研依据**：
- 级联 ST-DBSCAN 三级参数（瞬间 500m/1hr → 日 5km/12hr → 行程 50km/72hr）：event-detection-temporal-intelligence-expert（ST-DBSCAN Birant & Kut 2007 演进）<https://lobehub.com/skills/erichowens-some_claude_skills-event-detection-temporal-intelligence-expert/skill.md>
- LLM 语义聚合实测（"把一组照片扔给模型问是不是同一事件"→ 识别"都是云南大理之旅"）：Qwen3-VL-30B 智能相册 <https://adg.csdn.net/69709434437a6b40336acbcb.html>
- LibrePhotos 开源实现（三级时间粒度+增量聚类+参数自适应 1h/2h/3h）<https://blog.csdn.net/gitblog_00503/article/details/151290230>
- Google Photos 关系图（跨年跨地点主题回忆"橙背包"）<https://techcybo.com/software/google-photos-memories-and-why-they-keep-reappearing>

## 4. 照片分布全谱覆盖矩阵（10 类）

| # | 分布形态 | 覆盖层 | 覆盖度 |
|---|---|---|---|
| 1 | 短时单事件（一顿饭） | L0 | ✅ |
| 2 | 短时多事件（咖啡馆→公园） | L0 间隙拆 | ✅ |
| 3 | 单日连续移动（杭州一日游） | L1 | ✅ |
| 4 | 跨天事件（5 天云南） | L2 LLM | ✅ |
| 5 | 并行长事件（备考+日常） | L3 主题流 | ✅ |
| 6 | 无 GPS（截图/微信图） | L0 时间 + **L2 内容维**（OCR/标签，LLM 反成主信号） | ✅ |
| 7 | 高密度连拍 | 预处理折叠 | ✅ |
| 8 | 稀疏记录（一天 1-2 张） | L0 noise → **并入 L1 日卡片**（峰宝拍板 ✅） | ✅ |
| 9 | 低质/重复 | 预处理去重先行 | ✅ |
| 10 | 时间错乱 | ❌ 不覆盖 | 接受限制 + 时间戳可信度校验 |

## 5. 已收敛决策清单

- ✅ 四层事件模型（L0 瞬间 / L1 日 / L2 主题事件 / L3 长期主题流）
- ✅ 照片↔事件多对多关系表
- ✅ #8 稀疏记录并入 L1 日卡片（"8月14日 · 2张"，日常是"日子"不是"事"）
- ✅ #6 无 GPS 走内容维（LLM 依赖 OCR/标签，不依赖地点）
- ✅ #10 时间错乱：接受限制 + 时间戳可信度校验（EXIF 时间 vs 文件修改时间 vs 导入时间，差异>阈值标记"时间存疑"降级按导入时间）
- ✅ 产品部 30 分钟标准降级为 L0 层验收，非"事件"验收（L1/L2 需新增验收项）

## 6. B3-2 各层参数（已收敛 ✅）

**L0 瞬间层**（级联 ST-DBSCAN 最低档）：
- 时间窗口 ε_t：**默认 60 分钟；30 分钟保留为"保守模式"开关**（产品部验收标准作为可调参数，不硬编码）
- 空间 ε_s：500m（室外混合场景）
- min_pts：3 张（<3 张散片进 L1 日卡片，呼应 #8）
- 连拍折叠：<5s 间隔折叠为 1 个时间点（#7）

**L1 日聚合**：
- 聚合单位：自然日（0-24 时）；深夜 23:30-1:00 连续拍摄归属前一天
- 依据：ST-DBSCAN 短事件 1hr 官方建议

**L2 主题事件**（LLM 语义归并）：
- 触发：跨天 + 地点域连续（5km/12hr）或主题标签一致
- LLM 只看代表照片元数据（时间/地点/标签/OCR 摘要），不全图
- 最小规模：≥2 天 且 ≥10 张

**L3 长期主题流**：
- 形成阈值：同一标签 7 天内 ≥3 次（跨天，呼应 B1 L2 维度创建阈值）
- 生命周期：活跃（30 天）→ 静默降级 → 归档

**MVP 加手动合并/拆分事件入口**（峰宝拍板 ✅）：自动识别 + 手动合并/拆分两条腿走路，为 B3-5 纠错闭环前置

## 6.4 B3-3 GPS 漂移处理（已收敛 ✅）

**核心原则**：漂移在进入聚类之前处理（预处理阶段），不进任何一层聚类——否则漂移会把同一个事件拆成多个。

**① 漂移识别**（速度校验主判据）：
- 相邻照片时间差 Δt 内，位移超过物理速度上限 → 漂移（如 2 分钟位移 5km = 时速 150km，人不可能）
- 阈值：步行 6km/h、驾车 120km/h 为上限；超过上限标记"坐标存疑"

**② 纠正策略**（分两种，峰宝确认 ✅）：
- 单点漂移（少数照片跳出事件簇）→ 取事件内众数位置（中值滤波）拉回
- 系统性偏移（整批偏，如室内 GPS 差）→ **不纠正**，逆编码降级为"附近/某区"粒度，**不猜精确 POI**（"降级不猜"——猜错 POI 比不猜更伤信任）

**③ 逆编码缓存**：geohash 精度 6（≈1.2km）作为缓存键，同格复用一次逆编码结果（一次聚餐 30 张 = 1 次调用，高德免费额度富余）

**④ 漂移点与 L2 的关系**（峰宝确认 ✅）：漂移点**不进 L2"地点域连续"判断，但时间维照常参与**（时间戳可信、坐标不可信；不因坐标存疑就把照片踢出事件）

## 6.5 B3-4 事件输出形态（已收敛 ✅）

**标题生成**：
- L0/L1（日卡片）：模板（日期+地点/标签）→ "8月14日 · 杭州"
- L2 主题事件：**LLM 生成（qwen-flash 文本版，只看元数据：时间/地点/标签/OCR 摘要，不调 VL 看图）** → "7月云南之旅"
- L3 主题流：模板（标签+周期）→ "2026 考研备考"
- 标题可编辑（用户改后存自定义标题，不再自动覆盖）；LLM 失败/离线 → 模板兜底

**封面图**：
- L2：有人脸优先 + 画面质量分 + 时间居中（非第一张）
- **L3：独立封面（峰宝拍板 ✅）**——复用"人脸优先 + 质量分"，**不做时间居中**（长期流时间跨度大，时间居中无意义）
- 用户可手动换封面

**元数据**：时间范围 / 地点（降级粒度）/ 标签聚合 top3 / 人脸聚合 / 照片数 / 置信度

**照片归属（峰宝确认机制 ✅）**：
- `photo_event` 多对多关系表（photo_id + event_id），一张照片可属多个事件（L0 瞬间 + L3 主题流并存）
- 三处用户可见入口：
  - 照片详情页：显示"属于：事件列表"可点击跳转
  - 事件详情页：事件内照片列表
  - 搜索/时间轴：结果带事件上下文
- 归属机制实现"正向（事件→照片）+ 反向（照片→事件）"互查

## 6.6 B3-5 置信度与纠错闭环（已收敛 ✅）

**置信度来源（三层）**：
- L0 瞬间：聚类密度（簇内照片数/时间连续性）；2 张"伪事件"降级进 L1
- L2 主题：LLM 归并判断的置信度输出
- L3 主题流：标签强度（累计次数/跨天数）；弱流不展示

**阈值**：L2 LLM 归并置信度 **<0.7 → 进"待确认"区**（与 B1 枚举标注 0.7 阈值一致）；≥0.7 直接转正；用户确认后置 1.0（用户背书）
（对应产品部"整理房间 · 今日 · 3张待确认"设计）

**纠错闭环（用户操作回流，峰宝确认 ✅）**：
- 确认 → 存"用户背书"标记，事件不再被自动算法改动
- 合并 → 存"合并规则"，同标签/同地点未来照片倾向合并
- 拆分 → 存"拆分规则"，离群照片永久留在事件外
- 改名 → 标题覆盖（B3-4）+ 存"事件类型参考"
- **核心原则：用户操作优先，自动算法永不覆盖用户决定**

**回灌训练**：**MVP 不回灌**（峰宝确认 ✅）——用户操作只存规则（可解释、可回滚、零风险）；等合并规则同模式 ≥50 条再考虑离线训练

## 6.7 B3-6 处理位置与性能（已收敛 ✅）

**三层管线分置**：
- 预处理（去重/连拍折叠/漂移修正）→ **端侧**（纯计算无模型，不上传）
- L0/L1 聚类（ST-DBSCAN + 日聚合）→ **端侧**（10K 张 <2s，授权后立即出首批，不依赖网络）
- L2 LLM 归并 + L3 主题流 → **云侧**（需 qwen-flash + 全局标签统计，异步后台跑）

**30 秒验收达成路径**（峰宝确认 ✅）：
```
授权相册(0s) → 端侧预处理+L0/L1 聚类(1-3s) → 立即展示首批日卡片(30s 内 ✅)
→ 云侧 L2/L3 异步跑 → 完成后增量刷新（"今天·杭州"先出现，"7月云南之旅"几分钟后补上）
```
30 秒验收靠端侧 L0/L1 达成；L2/L3 是增强层异步补上（与"整理房间"渐进式体验一致）

**增量处理**（对应 Q17）：新照片只重跑受影响时间窗；先匹配现有事件、超限才分裂（LibrePhotos 增量思路）；L2 只在"新标签形成候选主题"时触发

**L2 全量补跑**：**MVP 不做**（峰宝确认 ✅）——新用户照片量小增量够用；历史照片按标签聚合粗分组，不逐张 LLM；P2"去年今日/回忆"时再决定

## 8. B3 分支总结（全部收敛 ✅）

**四层事件模型**（L0 瞬间 / L1 日 / L2 主题事件 / L3 长期主题流）+ 照片↔事件多对多关系表，覆盖 10 类照片分布中的 8 类完整、1 类部分（#8 并入日卡片）、1 类不覆盖（#10 时间错乱，接受限制+时间戳校验）。

**关键决策清单**：
1. 四层模型：L0 级联 ST-DBSCAN（60min 默认/30min 保守开关、500m、min_pts 3）→ L1 自然日（深夜归前一天）→ L2 LLM 语义归并（跨天+地点域连续或标签一致，≥2 天≥10 张，qwen-flash 文本版看元数据）→ L3 标签主题流（7 天≥3 次，生命周期活跃→降级→归档）
2. 并行事件靠标签维度分离；长跨度事件靠 L2 LLM 认；多对多关系表承载"一张照片多事件"
3. GPS 漂移：预处理阶段速度校验（步行 6km/h/驾车 120km/h 上限）→ 单点取众数纠正/系统性降级不猜 → geohash 缓存 → 漂移点不进 L2 地点判断但时间维照常
4. 事件输出：L2 标题 LLM 生成（可编辑、模板兜底）、L3 独立封面（人脸+质量分，无时间居中）、photo_event 三入口归属展示
5. 纠错闭环：确认/合并/拆分/改名四动作存规则，用户操作优先算法永不覆盖；MVP 不回灌训练；L2 置信度 <0.7 进"待确认"
6. 处理位置：预处理+L0/L1 端侧（30 秒验收靠它）、L2/L3 云侧异步；增量处理不做全量补跑

**待办**：
- 产品部验收标准需更新：30 分钟标准降级为 L0 层；新增 L1 日聚合正确率、L2 主题流分离正确率验收
- 端侧 ST-DBSCAN 实现列入开发规划（新增开发量）
