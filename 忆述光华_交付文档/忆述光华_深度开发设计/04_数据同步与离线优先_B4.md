# B4 · 数据同步与离线优先 — 设计文档

> 分支状态：grill 进行中（B4-1 同步范围讨论中）
> 依据：云端 Q17 原文 + V4 6.1 本地优先原则 + Q28/Q30 后台任务调研

## 1. 云端原题（Q17）

> 增量同步：当日照片的增量同步触发机制——是打开 APP 时触发、后台定时任务、还是系统相册变更监听？iOS/Android 的后台任务限制（BGTaskScheduler/WorkManager）差异？

**云端已有回答**：空（未填）。

**相关约束（V4 6.1 本地优先原则）**：原始数据优先本地存储，云端仅存元数据；用户可随时删除/导出；数据不用于模型训练。

**产品场景**：Android + Windows 双端 + 微信入口三通道；照片/文字/语音/文章多类型内容。

## 2. B4-1 同步范围与数据模型（已收敛 ✅）

**峰宝拍板：MVP 就要"手机照片在 Windows 能看到" + 微信图云端存原件**

**同步范围（更新后）**：

| 数据 | 存放位置 | 是否跨端同步 |
|---|---|---|
| 照片原始文件 | 手机本地 + **云端镜像（COS）** | ✅ 同步（为跨端可见） |
| 照片元数据（时间/GPS/标签/OCR/事件归属） | 云端（唯一主库） | ✅ 同步 |
| 事件/时间轴/画像 | 云端 | ✅ 同步 |
| 微信收的图片 | 云端原生（来源：wechat 标记） | ✅ 云端原件 |

**对象存储成本重算（腾讯云 COS，100 用户）**：
- 单价：标准存储 0.118 元/GB/月、外网下行 0.5 元/GB、请求 0.01 元/万次（来源①：<https://21obsidian.com/blog/obsidian-remotely-save-sync> 来源②：<https://cloud.kd.cn/ask/91336.html>）
- 新增量：100 用户 × 5 张/天 × 30 天 × 3MB ≈ 45GB/月新增
- 存储：初期 45GB × 0.118 ≈ 5.3 元/月 → 一年后存量 270-540GB ≈ 32-64 元/月（**随存量线性涨，这是成本项不是一次性**）
- 流量：Windows 跨端查看默认拉缩略图（COS 图片处理生成）+ 原图按需下载；100 用户每月约 10GB × 0.5 ≈ 5 元/月（新用户 50GB 存储 + 10GB/月流量免费额度可抵扣初期）
- **结论：MVP 初期 +10~20 元/月可控；长期是线性增长项，需"缩略图为主 + 原图按需 + 低频归档"成本策略**

**架构调整（本地优先的再解读）**：
- 手机本地保留原件（不删），云端是"镜像"（为跨端可见）
- Windows 端默认拉缩略图，点开按需下载原图
- 隐私：敏感照片不进云端镜像（敏感识别排除）；用户可关"跨端可见"开关（关闭后新照片不上传，已有镜像可清理）
- ⚠️ 需产品部知情：这已不是"纯本地优先"，是"本地为主 + 云端镜像（可选）"

## 3. B4-2 冲突策略（已收敛 ✅）

**LWW 字段级（峰宝确认机制 ✅）**：
- 云端为主库，客户端只做"提交"，云端返回权威版本
- **字段级 LWW**：冲突按字段粒度比较修改时间，每字段独立取最新（改标签只覆盖标签字段，不覆盖标题）
- 同步游标：每端记录"已同步到哪个版本号"，增量拉取天然幂等
- 不用版本向量：个人场景冲突极低频，LWW 简单可靠（版本向量是多人协作才需要）

**冲突兜底（峰宝确认 ✅）**：同字段同时间冲突 → **MVP 云端胜 + 提示用户"另一台设备修改了此标签"**（不弹窗，弹窗留第二版）

**删除策略（峰宝确认 ✅）**：**软删除**——删除 = 标记 deleted + 时间戳，保留 30 天后物理清理（防误删可恢复 + 同步时序安全）

## 4. B4-3 离线队列（已收敛 ✅）

**本地队列结构**（每端 SQLite，操作型日志）：
- `[op_id, type, payload, status, created_at, retry_count]`
- 操作是"日志"不是"状态"：离线只追加操作记录，不直接改主库 → 重放安全
- 持久化：复用 Q30 已定的 WorkManager/BGTaskScheduler 机制，App 被杀不丢

**重试策略**：瞬时错误（断网/5xx/限流）→ 指数退避（2s→4s→8s→上限 5 次）；永久错误（4xx）→ 停该条不阻塞其他

**幂等**：客户端每条操作带全局唯一 op_id，云端按 op_id 去重（网络重试同一操作只执行一次）

**同步状态分级处理（峰宝拍板 ✅，从"预警数字"改为"状态可见"）**：
- 完全离线 → 操作进本地队列，联网自动补传；照片角落"待上传"小图标（不打扰）
- 网络抖动（用户以为有网）→ **自动重试 3 次**（2s/4s/8s），无感知；3 次都失败才标"失败"
- 真失败 → 该条标红"上传失败" + 可点击重试（逐条显示，保留透明性）
- 批量失败（连续 10+ 条）→ **暂停剩余**（不取消不丢弃，留在队列），顶部横幅"网络异常，已暂停同步"，恢复后一键"继续上传"
- 跨端乱序：不做全局有序，依赖 B4-2 字段级 LWW 兜底（峰宝确认 ✅）

## 5. B4-4 增量同步触发（已收敛 ✅）

**三路并用，优先级分层**（峰宝确认 ✅）：
- ① 应用内主动：打开 APP / 切前台 / 拍照后 → 主入口最可靠（Android + Windows）
- ② 系统相册监听：相册新增立即触发（Android ContentObserver，前台服务+常驻通知——Q28 同款方案）
- ③ 后台定时：每 2 小时兜底（Android WorkManager + Windows 计划任务）
- 三路互不冲突，靠"已同步游标"去重（B4-2），同张照片只传一次

**流量约束（峰宝确认 ✅）**：**默认 WiFi 才传原图，蜂窝只传缩略图+元数据**（原图 3MB/张蜂窝吃不消）；用户可手动"立即上传原图"；原图 WiFi 自动补传（接 B4-3 队列）

**Windows 端（峰宝确认 ✅）**：不做系统监听实时同步——"导入触发 + 手动刷新"即可（导入型场景，实时监听文件夹有误触发风险）

## 6. B4-5 微信通道一致性（已收敛 ✅）

**微信内容进主库路径**：
```
用户微信转发 → 企业微信客服 → 服务器接收 → 直接入库（云端原生，来源=wechat）
  → 打标签/OCR/分类（云端管线，B2/B3 同款）
  → 事件归属：并入 L0 时间线（微信图无 GPS → 内容维，B3 #6）
  → Android/Windows 拉取时可见（云端镜像，B4-1）
```

**一致性保障**：微信内容源头唯一（无"另一端同时改"）→ 直接走云端主库，不需要 LWW；删除走软删除（B4-2），两端同步消失；用户想存本地 → 手动下载为本地照片（来源改 local）

**微信端特有规则**：
- 只做"收 + 找"，不做编辑（打标签/合并事件只在 APP/Windows 端）——避免微信端维护编辑状态
- 敏感内容识别（B5-b）在微信入库时同步执行，命中不进云端镜像
- **微信端支持"软删除本条"（峰宝确认 ✅）**：语音"删掉"或快捷操作；不做批量删除/清空（防误操作，清空留 APP 端）

## 7. B4 分支总结（全部收敛 ✅）

**同步范围**：结果同步 + 照片云端镜像（跨端可见，峰宝拍板）；微信图云端原生；元数据/事件/画像云端主库；对象存储 COS 初期 +10~20 元/月、随存量线性涨（需缩略图为主+低频归档策略）

**冲突**：字段级 LWW（云端主库、客户端提交、同步游标幂等）；同字段同时冲突 → 云端胜+提示；软删除 30 天

**离线队列**：操作型日志本地 SQLite + op_id 幂等；抖动重试 3 次 → 真失败逐条标红 → 批量失败暂停剩余（不取消不丢弃）；不做跨端全局有序（LWW 兜底）

**增量触发**：三路并用（前台主动/相册监听/2 小时定时）靠游标去重；WiFi 才传原图、蜂窝传缩略图+元数据；Windows 导入触发+手动刷新

**微信通道**：云端原生入库、只收找不编辑、软删本条、敏感排除
