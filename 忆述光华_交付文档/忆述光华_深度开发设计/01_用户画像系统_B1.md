## 1. 为什么这个功能需要深度设计

用户画像是个性化（搜索重排/复盘文案/追问/回响）的地基——**错了全错**。技术评估清单 Q37 已拍板：画像不走 RAG、直接注入、不压缩。本设计在"不压缩"基础上进一步收敛为**枚举化维度 + 三层治理 + 渐进式披露**方案。

## 2. 已拍板的设计决策

### 2.1 画像形态：枚举化维度（借鉴 MatrAIx，但动态化）

- **不是**五大地带自由文本画像（自由文本会膨胀、需蒸馏折叠）
- **是** MatrAIx 式枚举维度：每个维度 = 枚举值（闭集）+ phrase 模板 + 时间戳 + 历史列表
- **全量注入量级**：~300 个有值维度 × ~8 token ≈ **3-4K token**（MatrAIx 1290 维全量也才 ~10K）
- **关键结论**：枚举化天然免蒸馏——每个维度只存一个短枚举值，没有"可折叠的长文本"，"不折叠不合并"自动成立

### 2.2 三层维度治理模型（人 × LLM 分工）

| 层 | 谁设计 | 更新频率 | 内容 | 生命周期 |
|---|---|---|---|---|
| **L0 核心维度**（~50-80 维） | **人**（一次性设计） | 几乎不变 | 人口/性格(Big5)/价值观/关系/敏感标记 | 永久 |

> **⚠️ 2026-08-25 修订（L0 内容与结构）**：
> - L0 实际内容按《画像维度枚举集清单_v1》§一落地：**身份背景 / 关系核心 / 人生大事时间线 / 中国节假日锚点 / 价值观与动机 / 敏感标记 / 主语归属+隐私分级**——比原表多出"中国节假日锚点"（回响推送核心）与"主语归属+隐私分级"（防数据污染机制）。
> - **性格(Big5) 调整出 L0 常驻**：改按**方案 D** 全量建在 L1（Big5 50+Character 34 超细维度，见 §8-修订2），L1 常驻只放**有值索引**（名+值），详情按需拉取——原"L0=性格(Big5)"表述被取代。
> - **敏感标记两层分治**：画像只管**用户个人敏感**（话题×处置 5 级：allow/mention/caution/review/forbid，见 §8-修订3）；**红线级**（涉政/违法/未成年/医疗诊断）**不进画像枚举**，走 B5-b 护栏硬规则 + fail-safe 默认拒发。
| **L1 领域维度**（~150-200 维） | 人设计主干 + **LLM 提候选 + 人审核** | 周/月级 | 兴趣话题/媒体/学习/消费 | 长期（可退役） |
| **L2 用户特有维度** | **LLM 运行时创建** | 实时/事件驱动 | 用户独有模式（"考研冲刺期"/独特分类脑回路） | 随事件活跃度浮动 |

**分工本质**：
- 人 = 定义"人类的共性"（L0/L1 骨架，稳定不漂移）
- LLM = 定义"这个用户独特在哪"（L2 血肉，聪明不呆板）
- 审计 = 把个体共性沉淀回群体（L2 → L1 晋升）

### 2.3 枚举标注机制（事件 → 画像更新）

**核心：标注是"映射"不是"生成"**——LLM 把自然语言归一到闭集，不能发明新值。

```json
{
  "event_id": "ev_8f21",
  "trigger": "text_fragment",
  "dimension_updates": [
    {
      "dimension": "emotion_state",
      "enum_value": "压力_高",
      "confidence": 0.85,
      "note": "项目延期导致的疲惫感",
      "timestamp": "2026-08-14T01:05:00+08"
    }
  ],
  "low_confidence_hits": []
}
```

**标注规则**：
- 置信度 ≥0.7 → 更新画像（同值则强度累加；异值则当前值替换 + 旧值进历史列表）
- 置信度 <0.7 → 不更新，进"低置信度事件池"（周级批量复核，可作标注样本）
- 枚举集无合适值 → 不自动加，进"维度扩展队列"（累计 N 次同类 → 人工确认后加值）

> **⚠️ 2026-08-25 修订（开放枚举，取代上一条"进队列等人工确认"）**：
> - **枚举值 = 种子值（人设计起点），非封闭集合**。LLM 标注时种子值匹配不上 → 走**同义归一**（查维度别名表，`母亲`→`妈妈`、`备考`→`考研`）→ 确无等价值才**直接新增 value**（带证据锚点 + 时间戳，即时入集，不等人）。
> - **防碎片**：新增前强制查重（同义归一 + 别名映射表）；同一概念不同表述归一到已存在值。
> - **生命周期**：活跃 value 保留；低频 value 提示合并；与正式值合并后退役（证据保留）。
> - **晋升**：跨用户高频新增（≥3 用户）→ 人工确认一次 → 升为 L1 正式值（与 L2→L1 晋升同构，§4-5）。
> - **审计**：新增 value 全量记变更日志（value + 证据 + 时间戳 + 来源用户哈希）。
> - 设计依据：闭集枚举覆盖不全真实长尾表达（中国语境尤甚）；开放枚举不破坏"枚举化免蒸馏"（每维仍只存当前值 1 个短枚举）。
- 一句命中多维 → 全部更新，但**同日同维度只写一次**（高频用户节流）

> **⚠️ 2026-08-25 修订（置信度双门槛 + 证据机制）**：
> - 置信度门槛分两档：**普通维度 ≥0.7**（原规则不变）；**超细性格维度（Big5/Character）≥0.8**——需多证据累积才入，宁缺勿错（画像错了全错）。
> - **证据锚点 + 新鲜度戳**（方案 D 核心）：每条维度更新带**证据原话 + 时间戳**；消费时"标签进思考、证据进话术"——LLM 判断用标签，表达引用证据原话（不引用标签名，防"分析感"话术）；证据按新旧打折（半年前=曾经如此，近期=现在如此）。

**更新=适时更新，无全量重构**：事件驱动命中维度即更新当前值；历史值进有界列表（保留最近 10 条）；重大事件（人生大事）入"事件时间线"维度，永不衰减。

**⚠️ 2026 前沿修正（DEEPER 论文）**：增量追加/全量重生成两种更新方式**都会失败**——画像必须走**"行为预测→纠错"反馈闭环**：
- 每次更新后，用**下一个事件**做验证预测（"这个用户接下来会记录什么维度？"）
- 预测正确 → 该更新方向确认（强化）；预测错误 → 回滚/纠正该维度更新
- 低置信度（<0.7）更新进"待确认池"，周级用预测验证批量裁决

**⚠️ 2026 前沿修正（Sleeping Agent 论文）**：gist 压缩会系统性丢失时间信息（时间问答 -0.314）——**画像的时间字段显式剥离保留**（兴趣开始时间/最近活跃时间作为独立字段，不塞进叙述），任何压缩/摘要环节时间戳不得丢失。

### 2.4 渐进式披露（永不压缩的实现方式）

**永不压缩的定义**：任何维度的**值**永不丢失/折叠/合并；L1/L2/L3 只是**披露范围**不同，不是把维度变薄。

**⚠️ 2026 前沿修正（ICLR'26 受控实验 + claude-mem 模式）**：披露分层过深反而掉点（0.9126→0.6398）；无关规则增 20%+ 推理成本且无收益。**L1 常驻层只放"索引"（维度名+值，20-30 token/条），agent 按需拉取详情**——不是把整维度描述塞常驻层。

| 披露层 | 注入什么 | 什么时候 |
|---|---|---|
| **L1 常驻核心**（**~300 token，索引级**） | 身份核心 + ⚠️敏感标记 + 当前活跃维度**索引**（名+值，详情按需拉） | 每次调用必带 |
| **L2 场景扩展** | 按功能追加维度组（搜索→兴趣类；复盘→心理+事件类） | 按消费场景（深度控制在 1-2 层） |
| **L3 全量** | 全部有值维度（~3-4K token） | 深度复盘/用户主动查看 |

**补充（ProGraph 验证）**：画像注入时**逐条附"来源事件残差"**（精确日期/数量/人名/地点，每次更新零额外成本抽取）——既支撑溯源（用户问"你怎么知道我养猫"→ 指向证据事件），又补检索盲区（残差里的精确数字/人名可被关键词匹配命中）。

| # | 输入 | 命中维度 → 枚举值（置信度） |
|---|---|---|
| 1 | 文字："明天记得买咖啡豆，试试耶加雪菲" | shopping_pref_category→咖啡/茶饮(0.95)；behavior_todo_rate→高频(0.9) |
| 2 | 语音："项目又延期了，感觉被掏空" | emotion_state→压力_高(0.82)；emotion_baseline→(0.6 不更新) |
| 3 | 照片：橘猫 | interest_pets→猫(0.88)；life_scene→居家(0.9) |
| 4 | 访谈："最重要的人是妈妈、女友、小张" | relation_core→家人/伴侣/挚友(0.97)；冷启动批量激活维度 |
| 5 | 转发《AI Agent 落地十个坑》 | topic_interest→AI_Agent(0.9) 强度+1；达阈值进 L2 场景层 |

## 4. L2 用户特有维度机制（防爆炸）

1. **创建阈值**：同一模式 ≥3 次/周 且现有维度无法容纳 → 才新建
2. **生命周期**：活跃 → 进 L2 披露；静默 30 天 → 降级不披露但保留；静默 90 天 → 归档
3. **可追溯**：每个 L2 维度带证据事件（3 条来源）
4. **命名规范**：LLM 建维度走模板（`维度ID + 枚举值 + 描述 + 证据`），防碎片化
5. **晋升机制**：某 L2 维度在多个用户出现（≥3 人）→ 晋升为 L1 全局维度

## 5. 参考数据（MatrAIx 1290 维 schema 分析）

- 1290 维全部枚举（2-16 取值，中位 5）+ 全部有 phrase 模板
- 分类分布：Expertise 144 / Interests-Media 81 / Interests-Topics 78 / Worldview 67 / Skills 69 / Personality-Big5 50 ...
- 全量注入估算：1290 × 8 ≈ 10,320 token；30% 有值 ≈ 3,096 token
- **缺失（忆述光华需自建）**：情绪曲线（时间序列）、人生大事时间线、敏感话题标记、主题强度+时间戳
  - **✅ 2026-08-25 已落地**：四组自建维度已全部进入《画像维度枚举集清单_v1》（情绪曲线→`emotion_curve`；人生大事→`life_event_major/impact`+中国式事件；敏感话题→`sensitive_topic` 两层分治；主题强度+时间戳→`topic_active_top5`+证据新鲜度戳）
- 来源：MatrAIx 论文 https://arxiv.org/abs/2608.04205 ；本地 schema 文件 `matraix_schema/dimensions.json`

## 6. 待续子决策（下一轮 grill）

- **B1-5 画像消费侧**：✅ **已完成**（2026-08-14）：
  - L1 常驻核心 = 背景身份 + ⚠️敏感话题标记 + 当前情绪 + 当前活跃主题 Top5（~800 token）——**峰宝确认：敏感标记常驻 L1，每次必带**（护栏不能有漏带窗口）
  - L2 场景扩展组：复盘文案（心理+能力+习惯+近事件，~1500）/ 追问生成（主题+情绪曲线，~800）/ 回响选择（在乎+人生大事时间线，~600）/ 今日摘要（习惯+当日事件，~400）
  - **峰宝确认：MVP 搜索重排暂不接画像**（纯查询相关性排序，画像个性化重排留第二版）——搜索验收=找得对（Top3≥70%），不是排得巧
  - 预算：日常 L1+L2 ≤2500 token；复盘 ≤3500；仅"用户主动查看"走 L3 全量
- **B1-6 隐私**：✅ **已完成**（2026-08-14）——**峰宝拍板：画像增删改查完全对话式，不提供显式接口**：
  - 修改/删除：对话式（"把'养猫'删了，那是我室友的猫"→ LLM 定位维度→删除+用户锁定，LLM 不再自动写回）
  - 查看：对话式（"你对我了解多少？"→ AI 大白话总结画像→同时是修改入口）——这是对话式修改的成立前提
  - **导出：保留显式按钮，但放设置页（不放对话聊天页面）**——数据主权承诺（V4"完整数据控制权"）
  - 定期主动披露：每月/聪明镜子，AI 主动总结"新增了这些了解…对吗？"给被动纠正机会
  - 合规：对话式满足《个保法》查阅/更正/删除权；需记录操作日志（审计）
- **B1-7 冷启动**：✅ **已完成**（2026-08-14）——**云端产品部已设计冷启动本身**（V3 玩法「B. AI访谈式冷启动」：温和三问"最重要的人/人生转折/最骄傲的事"→ 生成"生命底色档案"；V4 MVP 范围明确为"第一版配置的 2 个优先玩法"之一）：
  - 技术侧只需设计**维度激活顺序**：产品部三问 → L0 关系核心/人生大事时间线/价值观（"最骄傲的事"反推 values_priority）+ L1 兴趣稀疏（5-10 维）+ **L2 留白**（等事件积累，防画像幻觉）
  - 冷启动不强求敏感话题（产品部三问本就不含）→ 敏感标记靠运行时事件 + 用户主动说（B1-6 对话式添加）
  - 档案确认闭环：问卷完 → AI 对话式复述"这是我对你的初步了解，对吗？"→ 接 B1-6 对话式修改
  - 冷启动回答与常态标注同链路（LLM 枚举映射，用户主动回答置信度更高）
