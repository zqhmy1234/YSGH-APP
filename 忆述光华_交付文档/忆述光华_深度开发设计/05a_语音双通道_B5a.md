# B5-a · 语音双通道 — 设计文档

> 分支状态：grill 进行中（B5-a-1 分工边界讨论中）
> 依据：云端 Q29 已回填答案 + SenseVoiceSmall 调研

## 1. 云端 Q29 已回填答案（峰宝已贴回）

> ✅ 方案（推荐，双通道）：
> 音频侧：SenseVoiceSmall（FunASR 开源）一次推理直接输出情绪标签（7 类）+ 音频事件（12 类）+ 转写文本，天然区分"情感碎碎念"vs"事件记录"
> 内容侧：ASR 转写后 → LLM 一次 few-shot 分类（待办/灵感，~85-90%）+ 关键词规则兜底（可复用 Q20 SetFit）
> 结论：✅ 双通道（音频情绪标签 + 转写后 LLM 分类），比纯 LLM 判断更准更省

## 2. B5-a-1 双通道分工边界（已收敛 ✅）

**职责分工**：
- 情绪 → 信 SenseVoice（声学情绪：语气/笑声/环境音，音频有语气文本没有）
- 内容类型 → 信 LLM（语义判断：待办/灵感/情绪/引用/混合）

**冲突合并规则（峰宝确认 ✅）**：`综合情绪 = 取两者中更强烈的那个`（声学中性+语义难过 → 难过；声学低落+语义中性 → 低落）；每个情绪标签带来源（audio/text/both），供 B1 画像情绪层加权（声学来源权重更高——语气更难伪装）
- 不互斥二选一：声学在"哭着说没事"失效（语义对）、语义在"反讽开心"失效（声学对）——双源合并补盲正是双通道价值

**音频事件（峰宝确认 ✅）**：MVP 只用 3 个——`笑声`（情绪加分）、`静音`（提示"录了空段可删除"）、`键盘/环境音`（标记"非口述，可能非主动记录"）；其余 9 类 MVP 不消费（不为暂时不用的能力付开发成本）

**输入分布兜底（峰宝方法论铁律：推荐前先想输入分布，2026-08-14 补）**：
- **非人声音频分布**：语音输入可能是播放的音乐/电视声/误触录音（不是人声说话）→ 声学情绪会乱判（音乐可能标 HAPPY）→ **预处理加"人声检测"**（VAD 判是否有人声），无人声 → 不产生情绪标签，标"疑似非口述内容"
- **噪音环境分布**：地铁/街头录音 → 声学情绪不可靠 → 噪音大时**降低声学来源权重**（合并规则里 audio 权重从"更高"降为"持平"），语义来源主导
- **方言分布**：SenseVoice 支持多语言但方言情绪识别未验证 → MVP 接受"方言语音情绪标签可能不准"，靠语义侧兜底（文本情绪不受方言影响）

## 3. B5-a-2 长录音分段策略（已收敛 ✅）

**按录制时长分三档**（峰宝确认 ✅）：
- ≤60 秒：整段处理（Hy ASR 覆盖）
- 60 秒-5 分钟：**整段 FunASR**（异步），不分段（5 分钟内延迟可接受）
- >5 分钟：**VAD 静音检测分段**（每段 2-5 分钟，停顿处切分保持语义完整）→ 逐段转写 → 合并；部分失败只重试该段

**段级情绪合并（峰宝确认 ✅）**：主导情绪 = **时长最长的段**；但**情绪峰值保留为标记**（如 4 分钟平静 + 30 秒哽咽 → 主导"平静"+ 峰值"哽咽"标记）——峰值进 B1 画像情绪曲线，比均值更有价值

**延迟实测数据（峰宝要求写入文档，2026-08-14 调研）**：
- FunASR/Paraformer（GPU：A10G/4090 级，阿里云录音识别 API 即此级别）：1 分钟 ≈3.6s、3 分钟 ≈10.6s、5 分钟 ≈12-18s、30 分钟 ≈1 分钟、1 小时 ≈3-5 分钟（RTF 0.03-0.06）
  - 来源①：A10G 实测 <https://agent.csdn.net/6a4e668a662f9a54cb8bf6a7.html>
  - 来源②：4090D 实测 <https://wenku.csdn.net/answer/5ti1nwgoa25>
- SenseVoice-Small（RTF 0.032）：3 分钟 ≈5.7s、5 分钟 ≈9.5s（同上来源①）
- **⚠️ CPU 自部署慢 5-8 倍**（1 小时 15-20 分钟，来源 <https://blog.csdn.net/weixin_30423977/article/details/99948789>）→ **FunASR 必须走阿里云 API 不自部署**；SenseVoice 需评估云 API 或接受 CPU 慢速（3 分钟约 20-40s，异步可接受）

**ASR 引擎可插拔适配器（峰宝确认 ✅）**：
- 输入音频 → VAD 分段 → ASR 适配器（Hy ASR / FunASR / 讯飞都是实现），各家的时长限制只是"约束配置"不是架构假设
- Hy ASR 限制取消 → 改适配器配置（max_duration 60s→600s），管线零改动
- 分段逻辑独立于 ASR（失败隔离+段级情绪是独立价值，不为绕限制而设计）
- 主路径永远用稳定项（FunASR），内测项（Hy ASR）只做增强不做依赖

**输入分布兜底（2026-08-14 补）**：
- **无停顿口语分布**：有人说话不停顿（VAD 找不到切分点）→ **兜底按最大段长硬切**（5 分钟），不无限等待静音
- **时长分布认知**：用户语音大概率是"大量短条（<1 分钟）+ 少量长录音"两头分布 → 分段是例外不是常态，三档设计符合真实分布

## 4. B5-a-3 情绪标签消费链路（已收敛 ✅，输入分布驱动）

**消费方**：① 事件层（语音卡片带情绪标记）② 画像层（B1 情绪曲线）③ 安全层（Q39 护栏联动）④ 复盘层（聪明镜子）

**落库（峰宝确认 ✅）**：情绪标签**落库持久化**（时间序列是画像/复盘刚需；不落库=每次消费重跑 SenseVoice 浪费）；**必须带置信度**（emotion + confidence + 来源），低置信度（<0.7）只存档案、不参与任何触发

**负面情绪触发追问——输入分布驱动的分层触发（峰宝确认 ✅，2026-08-14 修正）**：

输入分布：情绪类型（NEUTRAL 是绝对主流，负面是少数）｜程度（轻度随口/中度/剧烈崩溃）｜类型（SAD vs ANGRY）｜是否已说明原因｜时段｜频次

| 输入组合 | 触发策略 |
|---|---|
| SAD + 未说明原因 + 高置信度 | ✅ 关怀追问（"今天怎么啦"） |
| SAD + 已说明原因（"今天工作好累"） | ❌ 不追问原因，**回应内容**（"工作辛苦了"）——再问是废话 |
| ANGRY | ❌ 不主动追问，提供陪伴出口（"想聊随时找我"）——愤怒时关怀是火上浇油 |
| 轻度随口（"好累"）+ 低置信度 | ❌ 不触发（防过度关心） |
| 深夜时段 | ✅ 轻量表达（"如果还醒着，我随时在"），不催回复 |
| 连续多日负面 | 频次递减：第 1 天问 → 第 2 天"好些了吗" → 第 3 天只陪伴不重复问 |
| NEUTRAL / 无人声 / 噪音大 | ❌ 不触发（输入分布兜底） |

**时机**：语音处理完成（异步回调）→ 情绪判定 → APP 消息中心推送关怀消息（不打断、非弹窗）

**情绪局限（诚实声明）**：SenseVoice 只有 7 类基础情绪，**无"疲惫"类**——"有点疲惫"可能归 NEUTRAL；靠语义侧（文本"好累"）补，双通道合并兜底

## 5. B5-a-4 双通道成本与部署（已收敛 ✅）

**成本测算（100 用户/月，输入分布假设：人均 1 条/天 × 3 分钟 ≈ 150 小时/月）**：
- FunASR（阿里云录音识别 API）：150h × 0.79 元 ≈ **118 元/月**（已含 MVP 成本）
- LLM 内容分类（qwen-flash）：9000 条 × ~400 token ≈ **7 元/月**
- SenseVoice 情绪：见下

**SenseVoice 部署（峰宝拍板 ✅）**：**优先走阿里云 API 一体输出**（FunASR 服务若直接返回情绪标签 → 零额外成本零部署）；API 不带情绪输出则退化为 CPU 自部署（接受 20-40s 慢速，异步可接受）；**GPU 自部署排除**（+400-800 元/月为省 30 秒不值）；走 API 则服务器不升（4C8G 维持）

## 6. B5-a 分支总结（全部收敛 ✅）

**双通道**：SenseVoice 声学情绪（7 类）+ 音频事件（12 类取 3）+ LLM 内容分类；综合情绪取强信号、带来源加权（声学权重大）；输入分布兜底（人声检测/噪音降权/方言靠语义）

**长录音**：三档（≤60s 整段 / 60s-5min FunASR 整段 / >5min VAD 分段 2-5min）；主导情绪=时长最长段+峰值保留；无停顿硬切 5min 兜底；延迟实测已写入（5min ≈12-18s、30min ≈1min）

**ASR 适配器**：可插拔（Hy ASR 限制是配置非架构），主路径 FunASR 稳定项

**情绪消费**：落库带置信度（<0.7 不触发）；负面触发追问=输入分布分层（SAD未说明原因→关怀/SAD已说明→回应内容/ANGRY→陪伴出口/深夜轻量/连续多日递减）；SenseVoice 无"疲惫"类靠语义补

**成本**：FunASR 118 元 + LLM 7 元 + SenseVoice API 0（或 CPU 自部署 0 新增）；GPU 排除

**待办**：验证阿里云 FunASR API 是否带情绪标签输出（决定 SenseVoice 走 API 还是 CPU 自部署）
