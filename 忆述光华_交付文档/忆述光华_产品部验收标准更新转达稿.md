## 一、必须更新的验收标准（4 条，硬性）

### 1️⃣ 照片事件聚合：30 分钟标准降级为"L0 瞬间层"，新增 L1/L2 验收

**原标准**："同一地点 30 分钟内归同一事件"
**更新**：30 分钟窗口降级为 **L0 瞬间层**的验收（检测"拍照瞬间"），不再是"事件"的验收。事件分四层：

- **L0 瞬间层**（端侧，30-60 分钟窗口 + 500m GPS）→ "一顿饭"级别的底事件
- **L1 日卡片**（端侧，自然日聚合）→ "8月14日 · 杭州"
- **L2 主题事件**（云侧 LLM 语义归并）→ "7月云南之旅"（跨天跨地点的长事件）
- **L3 主题流**（云侧标签聚合）→ "2026 考研备考"（长期并行事件）

**新增验收**：
- 单日长事件不被切碎（5 天旅行不被切成 100 个 30 分钟碎片）
- 并行主题流正确分离（备考流与日常流不混）
- 照片/文字/语音混合内容聚合到同一时间线

### 2️⃣ 稀疏记录：一天 1-2 张并入日卡片

一天只拍 1-2 张的用户，照片并入 L1 日卡片展示（"8月14日 · 2张"），不强行升级为"事件"——日常是"日子"不是"事"。**这个产品决策请产品部确认**（我建议如此，避免碎片化的"伪事件"）。
!!#ff8000 H：可以的!!
### 3️⃣ Windows 端删除告知（新增产品文案）

Windows 端删除照片 = **只删云端副本，本地原件保留**。删除时必须明确告知用户：

> "已从云端删除，本地文件请自行删除（如需彻底删除）"

**需要产品部提供最终文案措辞**（技术侧已按此逻辑实现）。

### 4️⃣ 时间错乱限制（接受项）

相机时间设置错误（跨时区没调/换电池时间重置）的照片无法处理——技术侧只做时间戳可信度校验（EXIF vs 文件修改时间 vs 导入时间，差异大则标记"时间存疑"），**不做主动修正**。请产品部确认接受此限制（已在风险清单）。

## 二、建议更新的验收标准（6 条）

### 5️⃣ 语音情绪关怀：SAD / ANGRY 分策略 + 文案库

情绪识别后 AI 的回应**分类型分场景**（不是一刀切"负面就关怀"）：

| 输入 | AI 策略 | 文案示例 |
|---|---|---|
| SAD + 未说明原因 | 关怀追问 | "听起来你今天有点累，发生什么了吗？" |
| SAD + 已说明原因 | 回应内容（不追问） | "听起来工作很辛苦，注意休息" |
| ANGRY | 陪伴出口（不追问） | "想聊的话随时找我" |
| 深夜时段 | 轻量表达，不催回复 | "如果还醒着，我随时在" |
| 连续多日负面 | 频次递减（第 1 天问→第 2 天"好些了吗"→第 3 天不重复） | — |

**需要产品部提供关怀文案库**（技术侧已搭好触发逻辑，文案待产品部补）。

### 6️⃣ 追问/回响模板骨架池（产品运营建）

追问 = 人工审核的**模板骨架 + 变量填充**（如"当时为什么停下来拍{物品}？"）。为防用户察觉重复：
- 骨架池 30-50 个，按内容类型分池（照片/语音/文字各 10+）
- 同一用户 30 天不重复同一骨架
- 需要产品部/运营**持续维护骨架池**（新内容类型出现 → 加骨架）

**注意**：追问是 P2 备选玩法（MVP 只有回响），骨架池可在正式内测前建好。

### 7️⃣ 纠错验收测量方案

原标准"纠错后 7 天准确率提升 ≥10%"——需要**明确的测量方法**：
- 基线：纠错前同类内容分类准确率（离线评估集）
- 测量点：纠错累计 N 条后重测
- 技术侧建议：纠错记录带向量 + 三层裁决（个人规则优先），测量脚本 M1 交付
- **请产品部确认测量口径**（全量重测 vs 抽样）

### 8️⃣ 搜索延迟修正（重要！）

原文档某些地方写"长文本处理 30-60 秒"——**已核实为错误**。2026 实测：qwen-flash 摘要场景总延迟 **8-15 秒**（可同步等待），只有 3000+ token 长文生成才到 30-60 秒（才需异步）。**验收标准请按实测更新**。

### 9️⃣ 隐私文案知情更新（合规关键）

B4 已拍板**照片原件上云 COS**（跨端可见）——V4 原话"云端仅存元数据"已过时，**隐私政策必须如实更新**：
- 照片原件默认上云（用于跨端访问），可关闭
- OCR/图片向量化/内容检测需上传到云厂商（百度/阿里/腾讯）
- 崩溃上报（Sentry）不含用户记忆内容
- 端侧数据 SQLCipher 加密存储

**请产品部更新隐私政策措辞**（技术侧已按"可关闭"实现）。

## 三、新增产品确认项（3 条，来自技术收口）

### 1️⃣ 推送类型策略确认

产品文档对"回响/复盘推送方式"有不同表述——技术侧确认产品部原文是**按消息类型分策略**（非矛盾）：

| 消息 | 触达方式 |
|---|---|
| 回响（去年今日） | **in-app**（打开 APP 自然出现，非 push，怕打扰） |
| 每日复盘（22:00） | **push**（用户开启通知权限后系统推送） |
| 语音处理完成 | **push**（任务完成通知） |
| 关怀追问 | **in-app** 消息中心（不打断） |

**请产品部确认此理解一致**。
